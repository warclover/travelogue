## 0. 执行原则

1. **按决策风险排序，不按代码依赖排序。** 先验证多画布与计划契约，再批量改模板。
2. **功能冻结。** 收敛期不新增平台、导出形态、ECC 卡片规格和运行时 AI 能力。
3. **不推倒重建。** 保留模板、系列、星级、策展、Studio 和导出基础设施。
4. **不建立第三套页序世界。** 优先把现有 `chapters[].screens[]` 升格为 `LayoutPlan v1`。
5. **生成器退役与旧项目兼容分开处理。** 可删除 `mosaic` 新建路径，但旧 trip 所需的渲染资产须冻结保留。
6. **视觉变化必须可判定。** 模板扩充前先建立确定性编译和分层视觉门禁。
7. **每个阶段均有退出门。** 未满足退出条件，不扩大下一阶段的实施范围。
8. **完成优先于完美。** **`R0-04` 所定义的全部发布门槛验证通过后，即允许并应当发布 v1.0**；未通过的门槛必须修复，门槛之外的一切缺陷进 post-1.0 台账。**不得以「还可以更精致」阻止发布，也不得以「门槛已定义」代替「门槛已通过」。**
   > **rev2 修订理由**：原文写「达到 `R0-04` 门槛即发布」，可被误读为「只要 `R0-04` 这项任务完成（= 门槛清单写出来了）就可以发布」。**定义门槛与通过门槛是两件事**，此处必须写死：`R0-04` 交付的是判据清单，发布条件是该清单逐条验证通过。
   > 依据 [备忘录 §16.6 / §16.7](./项目发展路线图备忘录0831.md)：本项目无时限、无盈利指标、质量要求高，最大的风险不是做不完，而是 **永不结束**。清单本身的完备性会强化这个风险，故本条须优先于其余七条被记住。
9. **先取零成本证据，再做有成本的决策。** 凡是「今天就能跑出来、且会改变后续判断」的检查，一律前置。
10. **试验代码不得绑架架构决策。**（rev2 新增）G2 拍板之前写的画布相关实现，一律视为 **可丢弃的最小试验**：不进公开 API、不承诺兼容、不写迁移文档。避免「已经建好的基础设施」在 `CV-08` 投票时替你投票。

  - **rev2 修订理由（重要）**：rev1 把 v0.9 称为「画布无关核心层」，**这个命名是错的**。`patternId` 是模板 ID、`crop` 依赖槽位宽高比，两者都与具体画布几何强绑定——同一张照片进 16:9 槽位与进 9:16 槽位需要不同裁切。若继续宣称 v0.9「画布无关」，则当第二种画布需要不同裁切时，**渲染器只能偷偷重算 crop，这将直接违反 `LP-06` 的消费者边界**，而命名上的谎言会让人以为这是合规的。
  - **rev2 的处理选择**：不引入新抽象层（不现在拆「叙事层 + 表面层」两层模型），只做两件事——**把 v0.9 改称其实际身份「今天这一条画布的完整解析计划 + 已识别的公共字段」，并用上表把 `LP-07` 的范围精确界定**。两层模型很可能是 `LP-07` 的结论，但 `CV-08` 拍板前无法知道每画布究竟要绑多少东西，故现在不拍，也符合执行原则 10。
  - **原 rev1 循环依赖分析仍然成立**：`canvasVariant` 的语义由 `CV-08` 决定——
    - 若选「同模板多 variant」→ 计划里是一个 `patternId` + 一个 `canvasVariant`
    - 若选「独立竖版模板」→ 计划里应是 **每画布各自的 `patternId`**，根本不该有 `canvasVariant`
    - 若选「升格改造 `screen-*`」→ 两个画布用的是两族模板，绑定关系又不同

    **即 LP-03 无法在 CV-08 之前定稿，而原 G1 又要求 LP 全部完成才进阶段 2——这是一个循环依赖。** 分两次冻结后死锁解除：公共核心现在冻结，画布绑定留作 **预留扩展点**，由 `LP-07` 在 G2 之后按上表补齐并升为 v1.0。

## 3. 推荐开工顺序（rev2 重排）

**关键排法：`EA-00` / `EA-01` 与 `R0-*` 并行，不串行。** `R0-*` 需要你做产品决策并签字，工期取决于你；`EA-00` / `EA-01` 是只读、零产品依赖、当天可出。串行等于让证据轨白等一段时间，而 `EA-01` 的量化结果反过来能给 `R0-04` 的门槛提供依据（例如「破损态模板数 = 0」是否够格进发布门槛）。

| 步 | 任务 | 说明 |
|----|------|------|
| **并行轨 1** | `R0-01`～`R0-05` → **G0** | 产品收口，不写代码 |
| **并行轨 2 · ①** | `EA-00` 定义共同指标口径 | `EA-02a` 的前置，必须先做 |
| 并行轨 2 · ② | `EA-01` 源码模板全量几何体检 | 只读报告，产出反哺 `R0-04` |
| 并行轨 2 · ③ | `EA-02a` 用 `trips/` 下 20 趟真实旅行做横版影子对照 | 口径来自 `EA-00` |
| 4 | `LP-01`、`LP-02` | 需 G0 已过 |
| 5 | `LP-03`（含字段三分表）、`LP-04`～`LP-06` → **G1** | |
| 6 | `CV-01` 按「2 健康常用 + 1 难迁移 + 1 `screen-*` 对照」选样、`CV-02` | 选样依据 `EA-01` |
| 7 | `CV-03`～`CV-07` **以可丢弃的最小实现完成** | 执行原则 10 |
| 8 | `EA-03` 一趟真实旅行竖版自测（六条可否决判据） | |
| 9 | `CV-08` 正式拍板（四选一；选 D 须接受 ID 冻结条件） → **G2** | |
| 10 | `LP-07` 冻结 `LayoutPlan v1.0` 契约 | 波次 C 起点 |

第一批（步 1～3，即两条并行轨）完成后应得到：

1. 已签字的 v1.0 完成定义与已重签的产品主叙事；
2. **两条管线的共同指标口径定义**（`EA-00`）；
3. **123 个源码模板的健康清单**（`EA-01`）；
4. **20 趟真实旅行上 series vs mosaic 的横版鲁棒性对照摘要**（`EA-02a`）；
5. 是否进入 variant 试验的明确开工条件。

> **证据轨为什么排在最前**：三条都是只读或离线、当天可出，且 **会改变后续判断**——`EA-00` 决定后面所有数字是否可比，`EA-01` 决定 `CV-01` 选哪几个模板，`EA-02a` 决定阶段 5 是先做鲁棒性还是先做三种性格（**2026-09-01 结论：有阻断性发现，非质量通过**；先 `SE-00a` `placementGap`、再 `SE-00b` 超量容量策略、再性格）。先花两天拿证据，比先花一周做设计划算（执行原则 9）。

在这些产出完成之前，不建议直接修改 `css_gen.py` 或批量处理全部 `page-*`。
