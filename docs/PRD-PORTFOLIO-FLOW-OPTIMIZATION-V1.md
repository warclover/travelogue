> **定位**
>
> PFM 已经把作品集装进运行时：身份、匹配器、`page-*`、八档成册、导出门面「这一本 + 页图」。缺的是 **C 端主路径**：页数被藏在精修、生成后必须重排、导出前常被游记「更新版面」闸误拦，自动推荐又不按用户以为自己交进去的文件夹张数说话。
>
> 本主题只改 **作品集怎么走进来、怎么定厚度、怎么出门**。筛选 / 聚类 / 成册装配 / 双管线隔离仍归 PFM + DPI，本文不重开。
>
> **一句话目标**：选文件夹 → 系统用一句人话给出厚度规格（可展开改）→ 按该规格一次生成预览 → 打开这一本与导出并列可达；多数人直接出门，少数人不满意再进精修；导出点法跟现网六种同一套外壳，默认产物仍是这一本。
>
> **产品铁律**
>
> 1. **作品集是独立管线的主路径，不是游记精修里的进阶项。**  
> 2. **页数是规格，在生成前定完。** 精修不再是定厚度的唯一入口。第一眼是人话确认，不是九个数字考试（BLK-PFO-02）。  
> 3. **80% 不进精修。** 自动推荐须能交出约 70 分的一本；精修服务其余 20%。  
> 4. **导出习惯对齐的是点法，不是把六种重新平铺成同等选项。** 同一钮、同一等待、同一类成功面。默认产物仍是作品集。六种是分组降级的熟面孔，不得与「这一本」并排成两本一样大的书（BLK-PFO-04 · 与 PFM SHD-06 和解）。  
> 5. **游记零改。** 向导、Dock「导出长图」、六平台平铺、OR 意图卡，游记路径逐字不变（守 D-PFM-11）。  
> 6. **张数必须说人话。** 向导/成功面默认一句；N / M / P / C 只进详情或二次展开。禁止再用一个「你有 N 张」混谈，也禁止四个工程名词同时铺开（BLK-PFO-02 · SHD-PFO-04）。  
> 7. **逐页精修另立项。** 现网精修还不能换脸/换槽图；成功面与帮助不得假装已经有（BLK-PFO-07）。

### 0.1 术语

| 术语 | 定义 |
|------|------|
| **文件夹张数 N** | 向导扫到的图片文件数（用户以为「我交了多少」）。C 端说「文件夹 N 张」 |
| **可上版 M** | 剔除糊/近重复/低质后、进入装填组的库存。现网 `studio.portfolio.photosKept`。C 端不说「可上版」，只在详情里用人话说「这本大约用上」 |
| **本册已排 P** | 真正写进 `screens[]` 的张数。现网 `photosPlaced` |
| **档位容量 C** | 正式系列 `capacity`（槽预算）。内部用；C 端不说「容量」 |
| **页数规格** | 生成前钉死的档：`auto` 或 8/12/16/20/24/28/32/36。写入 `pageCountSource` + 可选 `pageCount` |
| **人话规格句** | 向导第一眼唯一必现句。例：「文件夹 160 张，做成大约一本 32 页。」数字是系统的，用户可以不猜 |
| **满意即导** | 生成成功后 **打开这一本** 与 **导出作品集** 并列可达，不必先开精修、不必先「更新版面」 |
| **六种模式** | 游记发行出口：微信群 / 朋友圈 / 小红书 / 公众号 / 海报 / 印刷跨页。作品集里它们是 **同一面板上的熟面孔、分组降级**，不是默认主产物，也不是与「这一本」同等的第二本书 |
| **70 分自动本** | 自动规格 + 一次生成即可翻阅、可导出；允许堂亲换脸与少量溢出；不允许厚度选错还要进精修才能出门 |
| **点法对齐** | 点导出 → 弹出面板 → 确定 → Task Dock 等待 → 成功面打开产物/文件夹。对齐的是这五步肌肉，不是六张卡默认摊开 |

## 1. 问题

### 1.1 现网主路径（as-is）

```
选文件夹（作品集）
  → 生成（pageCountSource=auto，导入不问页数）
  → FirstSuccess「打开画册」（不能导；游记路径还有倒计时自动导长图）
  → 打开预览 → 精修 → 画册 → 成册类型 ↓ 页数
  → 重跑 curate + render → 整页刷新
  → Dock 常变成「预览需更新 / 更新版面」
  → 再 rerender → 再刷新
  → 才能点「导出作品集」
```

合同依据：PFM **D-PFM-28 / D-PFM-13 / N-PFM-14 / OQ-PFM-02**（导入不问、页数仅精修）；FirstSuccess 导出不在这次生成里。

### 1.2 摩擦拆开

| # | 现象 | 根因 |
|---|------|------|
| 1 | 页数找不到 | 有意藏进精修（D-PFM-28） |
| 2 | 定页必须再等一轮编排 | 首次生成未钉规格 |
| 3 | 排完还要点「更新版面」才能导 | 游记 `layoutPending` 套到作品集；`layoutCssStale` 用 `journal-screens.css` 查 `page-*` 格子，且屏上常无固化 cols/rows，易误报；edition 收尾未 stamp |
| 4 | 推荐「换 36 页会更饱满」 | 分子是可上版 M 或当前兑现空页，不是文件夹 N；把「空页」和「没收进文件夹」合成一句 |
| 5 | 预览张数大约是文件夹的 2/3 | 正常漏斗（去重/剔除），界面不解释；东澳样本 kept/N≈0.83、placed/N≈0.63，不能用一个 0.67 同时解释两层 |

东澳样本（`demo-81d3442e92`，用户钉 32 页后）：文件夹/入库约 129，可上版 107，已排 81，容量 88，提示却按兑现劝换 36 页。

### 1.3 产品口述的目标态（2026-08-25）

1. 独立管线操作：**文件夹 → 推荐页数（可指定）→ 按该页数生成预览 → 满意直接导出；不满意进精修，最终再导出。**  
2. **约 80% 不使用精修**；自动推荐做出约 **70 分** 即可。  
3. **导出模式尽力与现网六种保持同一操作习惯**（v0.2.0 澄清：习惯 = 点法，不是六张卡重新平铺）。

## 2. 目标与非目标

### 2.1 目标

| ID | 目标 |
|----|------|
| **G-PFO-01** | 作品集向导在扫完文件夹后给出 **人话规格**（默认可不改数字）；用户可展开改档或保持自动；**生成按该规格一次出预览** |
| **G-PFO-02** | 成功面 **打开这一本** 与 **导出作品集** 并列可达；预览 Dock 在「已按规格生成且 HTML 与 trip 对齐」时直接是导出，不插「更新版面」。作品集 **禁止** 倒计时自动导 |
| **G-PFO-03** | 80% 路径：导入确认规格 → 等一次生成 → 打开或导出。精修零步 |
| **G-PFO-04** | 页数与推荐文案使用 §5 人话口径；默认规格服务「尽量收得下真可上版」（生成后真 M）。估计比不进选档 |
| **G-PFO-05** | 导出 **点法** ≡ 六种模式：同一 Dock 钮、同一弹出、同一等待、同一类成功面。默认高亮作品集主产物；六种分组降级，不与主产物同等平铺 |
| **G-PFO-06** | 游记导入 / 游记 Dock / 游记六平台 **零 diff** |
| **G-PFO-07** | 精修仍可改页数、改成册类型（20% 支线），但不再是发现页数的唯一入口；文案不承诺逐页换图 |

### 2.2 非目标

| **N-PFO-05** | 改匹配器换脸规则、系列 YAML、工坊升格 | 归 PFM / MSP |
| **N-PFO-06** | 把作品集设成 Studio 默认身份 | 守 D-PFM-02 |

| **N-PFO-09** | 作品集 FirstSuccess 复用游记倒计时自动导（`wechat_chat`） | BLK-PFO-03 |
| **N-PFO-10** | 无 F9–F11 签核拆 W2 向导/成功面/导出面板 | BLK-PFO-06 |

### 2.3 成功标准（产品可验）

| 场景 | 通过 |
|------|------|
| 新作品集、采纳推荐、不进精修 | 从选夹到可点导出 ≤ **2 次等待**（生成 1 + 导出 1），中间无「更新版面」；成功面能先打开这一本 |
| 新作品集、导入展开改档再生成 | 预览页数 = 钉死档；无需为定页再重排 |
| 打开已按规格生成的预览 | Dock 主文案是导出，不是「更新版面」 |

## 4. 统一主路径

本文 §4 是作品集 **C 端流程的唯一目标态**。[作品集模式流程.md](./作品集模式流程.md) 的「用户侧」在实施落地前保持 as-is，并在文首指向本节。

### 4.1 主路径（约 80%）

```
选「作品集」→ 指定文件夹
  → 扫描：文件夹 N 张 + 缩略图
  → 规格区第一眼（无九芯片）：
       「文件夹 N 张，做成大约一本 X 页。」
       默认已选「自动」（X 为展示估计，见 §5.3）
       次级：「换一本更厚 / 更薄」→ 展开才出芯片
  → 一次生成（ingest → cull → cluster → 按规格装配 → 渲染）
  → 成功面：【打开这一本】∥【导出作品集】并列 · 【去精修】弱链（不承诺逐页）
       禁止倒计时自动导
  → 点导出：同一套面板（默认高亮这一本 / 页图 · 六种分组降级）
  → 等待 → 成功面（打开这一本 / 文件夹 / 压缩包）
```

### 4.2 支线（约 20%）

```
打开预览（或成功面「去精修」）
  → 精修：封面、成册类型、页数副本、精选/拼图（现网已有）
  → 改页数：走现网 edition job（curate + render），成功后 Dock 仍是导出，不升假 pending
  → 导出（同 §8）
```

**本波精修不包含逐页换脸/换槽图。** 产品口述「逐页调整」记为 OQ-PFO-01，实施与文案不得冒充已交付。

### 4.3 状态

| 状态 | 含义 | 可导出？ |
|------|------|----------|
| `spec_draft` | 向导已选夹、未生成 | 否 |
| `generating` | import job 进行中 | 否 |
| `preview_ready` | HTML 与 `renderedRevision` 对齐，规格已兑现 | **是** |
| `spec_replacing` | 精修改页数 job 进行中 | 否（忙） |
| `preview_lagging` | trip 内容新于 HTML（真落后） | 否，须 rerender；文案「预览需更新」 |
| `exporting` | 导出 job | — |

`preview_ready` 是 80% 用户生成结束后的默认态。禁止把 `preview_ready` 误标成 `preview_lagging`。

### 4.4 等待次数预算

| 路径 | 允许的等待 |
|------|------------|
| 80% 满意即导 | 生成 1 次 + 导出 1 次 |
| 20% 改页数 | 生成 1 + 改页 1 + 导出 1。**禁止**改页后再强制「更新版面」第 4 次 |
| 真改拼图/封面且 HTML 未写 | 额外 1 次 rerender（游记同款，仅真落后） |

## 5. 张数模型与推荐

### 5.1 三层必须能读到，但不得同时铺开

| 层 | 符号 | 权威来源 | C 端默认 | C 端详情 |
|----|------|----------|----------|----------|
| 文件夹 | N | 向导 `photoCount` / 扫描 | 「文件夹 N 张」 | 同左 |
| 可上版 | M | 生成后 `photosKept`；生成前估计只进「大约」 | 不单独出名词 | 「这本大约用上 M 张」 |
| 本册已排 | P | `photosPlaced` | 生成后可进详情 | 「放进这本的有 P 张」 |
| 档位容量 | C | 系列 `capacity` | 不说「容量」 | 「这一档大约收得下 C 张」 |

**向导 / 成功面默认一句（加席第 3 条）：**  
「文件夹 N 张，做成大约一本 X 页。」  
生成后若 P 明显小于 N：「有几十张没放进这本，要的话用游记能全收。」（溢出 CTA 守 D-PFM-21，改口成人话）

角标默认同样一句人话；N / M / P 进「详情」或二次展开（SHD-PFO-04）。禁止默认同时甩出四行工程数字。

### 5.2 默认推荐意图（D-PFO-05）

**生成后 / 自动档权威：尽量收得下真可上版 M。**

1. 库存 S = **真 M**（cull 之后）。  
2. 在正式档 8…36 中，选 **C ≥ S 的最薄档**；若所有档 C < S，选最厚档并明示溢出。  
3. 填充率窗口 0.85–1.05（现网 `FILL_RATE_*`）仍可用于并列打分，但 **不得**用「当前预览空页数」作为生成前推荐的主因。

**生成前：估计不得锁档。** 见 §5.3。

**预览弱提示（单独成句，可选）：**  
「有 K 页没排满。」禁止接「换 Y 页会更饱满」而不写人话张数。若要建议换档，必须写成：「换 Y 页大约能多收一些（文件夹 N 张）。空页是另一回事。」

### 5.3 生成前估计（BLK-PFO-05）

导入时 cull 未跑完，不能用真 M，也 **不准**用未校准的 `0.67×N` 去调 `select_series` 或预点某个数字档。

| 层 | P0 做法 | 禁止 |
|----|---------|------|
| **控件默认** | 选中 **「自动」**（`pageCountSource=auto`） | 用 M̂ 预点 8–36 某一档当默认 |
| **人话里的 X** | 展示用保守启发式 `display_hint_pages(N)`：正式档中选 **C ≥ N 的最薄档**（按「文件夹全都能上版」估，偏厚），必须标「大约 / 估计」。或只写「系统会按能上版的张数自动选厚度」而不给 X | 把 `kept_estimate_ratio` 或 M̂ 送进选档 |
| **文案「大约能用上」** | 可选：M̂ = round(N × `kept_estimate_ratio`)，默认 0.67 **仅调试/遥测/详情「大约」**，须标「大约」 | 用 0.67 当 AC-PFO-04 的对齐基准 |
| **校正** | 生成结束后用真 M 回写详情；**不自动改已钉页数**（D-PFO-07）；自动档的权威页数 = `select_series(auto, 真 M)` | 生成完偷偷变厚 |

薄档确认（现网 `thinTierConfirm`）改口：  
「这一档大约收得下 C 张。文件夹 N 张。继续则可能有照片放不进这本。」  
「你有 M 张」禁止再出现。

**W3：** 用 ≥3 本真实夹测量 kept/N 与 placed/N，再决定估计比能否进入选档。P0–P2 **不准**提前把 0.67 写进匹配器。

### 5.4 自动档 `pageCountSource=auto`

用户保持「自动」（向导默认）：生成时走现网 `select_series(kept_n=真 M)`（cull 之后）。  
**AC-PFO-04** 只锁这件事：生成后 `pageCount` 等于该函数对真 M 会选的档。  
**不**要求向导展示的估计 X 与最终档一致；文案已写「估计 / 生成时按实际上版张数定」。

用户展开并点了具体页数：`pageCountSource=user`，钉页不升档（D-PFO-07）。

## 6. 导入：页数规格

### 6.1 落点

仅当向导身份 = 作品集。放在相册预览（N、缩略图）**之后**、点生成 **之前**。不与「快速 / 精细」抢成第三张模式卡（守 N-PFM-07）。

游记身份：整区 `hidden`，请求体不带 `pageCount`。向导是共享壳，须走身份 seam，禁止抄一套 portfolio wizard（纪要 F-10）。

精细制作与快速制作同一规格区形态（OQ-PFO-04）：也是一句人话 + 可展开改厚度，不是九芯片考试。

### 6.2 控件（BLK-PFO-02 · OQ-PFO-06）

**第一眼（未展开）必现且只这些：**

1. 人话规格句：`文件夹 N 张，做成大约一本 X 页。`（X 按 §5.3 展示启发式，或改成不给数字的自动预告）  
2. 默认已选：**自动**（不是某个 8–36 芯片）  
3. 主按钮：**开始**（沿用现网生成钮，不另起第三击）  
4. 次级文字链：**换一本更厚 / 更薄**（默认收起）

**展开后才出现：**

- 芯片：自动 + 8 / 12 / 16 / 20 / 24 / 28 / 32 / 36（与现网 `pageCountChipDetails` 同源；副文可用「大约收得下 C 张」，不说「容量」）  
- 用户点过具体档则记住本次向导会话，提交为 `pageCountSource=user`  
- 过少：沿用 D-PFM-29 置灰 + 知情继续；与规格区同时出现，不互相替换

**禁止第一眼：** 九个芯片横排、四行 N/M/P/C、倒计时、要用户先猜数字才能点开始。

### 6.3 请求

`POST /__travelogue/import` 作品集增加：

```json
{
  "edition": "portfolio",
  "pageCount": 32,
  "pageCountSource": "user"
}
```

默认开始（未展开改档）：`pageCountSource: "auto"`，可不带 `pageCount` ≡ 旧行为，选档权威按 §5.4。  
非法页数靠档（现网 `snap_user_page_count`）。向导展开改档时，靠档句与后端 **同一函数或共享 JSON**（SHD-PFO-03），禁止前端自写一份。须在提交前预览靠档句，避免生成完才说「按 36 靠档」。

`apply_import_edition`：**允许写入用户钉页**，不再写死只有 `auto`（改 D-PFM-28 的实现）。走已有 seam，禁止在 `import-run.js` 里写 `is_portfolio` 旁路。

## 9. 过期闸门（D-PFO-06 · BLK-PFO-01）

### 9.1 原则

「更新版面」只服务 **HTML 真的落后于 trip**。规格变更的 edition job 已包含 `render_trip_surfaces` 时，成功并刷新后必须是 `preview_ready`。

### 9.2 必须修的误报（对照现网）

| 误报 | 处理 | 代码锚 |
|------|------|--------|
| 作品集用 `journal-screens.css` 查 `page-*` grid class | 作品集只查 `portfolio-pages.css`（或已固化 geometry 则不过期） | `css_stale.py` `trip_layout_css_stale` |
| `render_trip_surfaces(update_pipeline=False)` 之后又写 trip，revision > renderedRevision | 规格 job / 成功 persist 必须走 import 同一套 `mark_render_bundle_current` | `edition_handlers.py` + `studio_pipeline.py` |
| 打开作品集预览即 `layoutPending` | 禁止；`preview_ready` 时 Dock = 导出 | `refreshStaleHint` / `setLayoutPending` |
| 改页数成功后 `reloadPreviewAfterLayout` 再被 `refreshStaleHint` 拉回 pending | 禁止 | 预览工具条 |

真落后（封面、拼图、模板且未渲染）：保留游记同款拦截 + 「更新并导出 / 仅更新版面」。

### 9.3 热更新（P2，不挡 P0）

改页成功后优先热替换预览 DOM；P0 仍允许整页刷新，但刷新后不得假 pending。

| `keptEstimate` | 可选，生成前 M̂，**仅调试/遥测/详情「大约」**，不进匹配器 |
| `pageCountHint` | 拆成结构化更佳：`{ density?: string, capacity?: string }`；P0 可仍是一句，但必须是人话，且不得以空页为唯一原因劝换档 |

`pageCountSource` / `pageCount` / `photosKept` / `photosPlaced` / `overflow` 语义不变。

### 11.2 API

| 面 | 变化 |
|----|------|
| `POST /import` | 作品集可带 `pageCount` + `pageCountSource`；默认 auto |
| `GET /trips` / studio entry | 投影 `folderCount`、人话句、拆开的 hint |
| `POST /trips/{id}/edition` | 行为保留；收尾必须 stamp 渲染水印（与 import 同一函数） |
| `GET /config` 作品集投影 | `keptEstimateRatio`（只影响详情「大约」）、芯片 details（已有） |

studio:
