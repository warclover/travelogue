## 0. 测量契约：先冻结输入与采集时点

### 0.1 两条管线必须从同一份 compose 前快照独立运行

现有主流程已经把同一份 `preflight.layout_assets` 分别传给 `compose_trip` 与 `compose_portfolio_trip`，但影子对照不能只检查资产数量。compose 会修改 `chapters`，作品集还会向 `trip.studio.portfolio` 写入匹配结果；若两条管线顺序复用同一对象，后一条会读到前一条的副作用。

每趟旅行应在 cull 与 compose 准备阶段完成后生成一次**公共输入快照**，内容至少包括：

`trip, chapters, buckets, aspects, assets, appConfig`

执行纪律：

1. mosaic 与 series 必须分别从该快照深拷贝，禁止复用可变对象。
2. 除 `pipeline/edition` 及其必要开关外，不允许存在其他输入差异。
3. 两侧 `eligible` 的资产 ID、顺序和内容必须一致；只比较 `folderN` 与 `eligible` 数量不够。
4. 每次正式计时也必须重新深拷贝，禁止复用上一轮已被 compose 修改的对象。
5. 记录以下可复核标识：
   - `inputSnapshotHash`：切换 pipeline 之前，公共输入规范化 JSON 的哈希；
   - `eligibleSequenceHash`：按输入顺序排列的 eligible asset ID 哈希；
   - `armConfigHash`：切换到该管线后的完整有效配置哈希；
   - `codeRevision`：代码 revision 与 dirty 标记；
   - `seriesCatalogHash`、`templateRegistryHash`：系列目录和模板 Registry 的版本哈希。

同一 `comparisonRunId + tripId` 的两行必须具有相同的 `inputSnapshotHash` 与 `eligibleSequenceHash`，否则整对样本作废、修复后重跑。

### 0.2 唯一采集时点

`EA-02a` 的资产、页面和规划指标统一取自：

> `compose_trip` / `compose_portfolio_trip` 刚返回的 chapters，以及同次返回的 meta；尚未执行 featured grid、breath screen、封面/收尾投影和人工修改。

因此本页所称 page/screen 均指 **compose 输出的内容屏**。不得把后处理插入的 `screen-breath-pause`、封面、目录、收尾等结构屏计入 `renderedPageCount`、空页或槽位统计。

`MG-02` 若需要统计最终投影结果，必须在行内写明 `measurementStage = projected`，并使用对应 surface profile；不得与 `measurementStage = compose` 的数字直接合并。

### 0.3 样本与管线状态

| 状态 | 定义 | 失败率处理 |
|------|------|--------------------|
| `ok` | 输入、采集和管线结果均有效 | 进入分母，作为成功样本 |
| `inputInvalid` | `eligible = 0`、eligible ID 重复/缺失、两侧快照或顺序哈希不一致 | 否；修复或剔除并说明 |
| `metricInvalid` | 因采集器缺陷、版本不匹配或所需原始数据缺失而无法可信计算指标 | 否；修复采集器后重跑 |
| `outputInvalid` | 管线已返回，但结果存在重复填图、foreign 引用、未知模板、槽位越界或资产守恒破坏 | 进入分母与失败分子 |
| `pipelineFail` | 输入有效，但目标管线抛错或未产生任何有效内容屏 | 进入分母与失败分子 |

`inputInvalid` 和 `metricInvalid` 不得冒充某条管线的失败；`outputInvalid` 不能借“指标无效”之名从失败率中剔除。

## 1. 资产集合、覆盖率与引用完整性

所有资产级计数以**唯一 asset ID**为单位。若输入存在缺失或重复 ID，样本直接记为 `inputInvalid`，不得一边按列表长度、一边按集合长度计算。

| 符号 | 定义 |
|------|------|
| `folderN` | `trip.assets` 中 `type != video` 的记录数；沿用现有 `photosFolder` 命名，但它是**资产表图片数，不保证等于磁盘原始文件数** |
| `eligibleIds` | `layoutEligible is not False` 且 `type != video` 的资产 ID 集合，即 `layout_eligible_assets(trip)` 的 ID 集合 |
| `eligible` | `|eligibleIds|` |
| `intakeIds` | 目标管线在进入选系列/排版分组时实际识别到的 eligible ID 集合 |
| `intakeN` | `|intakeIds|` |
| `slotAssetIds` | compose 输出的全部内容屏槽位中，非空 `assetId` 的序列；保留重复项 |
| `placementOccurrences` | `len(slotAssetIds)`，即槽位引用总次数 |
| `placedIds` | `set(slotAssetIds)` |
| `placedUnique` | `|placedIds|` |
| `placedEligibleIds` | `placedIds ∩ eligibleIds` |
| `placedEligible` | `|placedEligibleIds|`，覆盖率唯一合法的分子 |
| `foreignPlaced` | `|placedIds − eligibleIds|`；引用非 eligible 或不存在资产的唯一 ID 数 |
| `duplicatePlacements` | `placementOccurrences − placedUnique`；同一资产被重复填入多个槽位的次数 |
| `coverage` | `placedEligible / eligible` |

必须满足：

```text
0 <= coverage <= 1
placedEligible <= intakeN <= eligible
unplacedEligible = eligible - placedEligible
eligible = placedEligible + unplacedEligible
duplicatePlacements >= 0
foreignPlaced >= 0
```

`foreignPlaced > 0`、`duplicatePlacements > 0`、`placedEligible > intakeN`，或输出数据本身破坏任一恒等式时，记录详细 asset ID，并把该行标记为 `outputInvalid`。只有无法判断问题来自输出还是采集器时才暂记 `metricInvalid`，修复采集器后必须重跑，不能直接进入对比结论。

现有 mosaic coverage 会在提供 `planned_asset_ids` 时排除未进入 chapter bucket 的 eligible 资产。本对照**不得直接复用该分母**；两条管线都必须从公共快照重新计算本页定义的 `eligibleIds`。某条管线主动不把 eligible 资产放进正文，应作为其 intake loss 或 placement gap 被观察，而不是悄悄修改分母。

## 2. 页面、槽位与计划履约

### 2.1 页面计数

| 符号 | 定义 |
|------|------|
| `plannedPageCount` | series 选中 YAML 的 `sequence` 长度；mosaic 没有同构的预定页序列，记 `null` |
| `renderedPageCount` | compose 输出中实际出现的内容 screen 数；旧字段 `pageCount` 在本报告中只作为该值的兼容别名 |
| `omittedPlannedPages` | series 的 `max(0, plannedPageCount − renderedPageCount)`；mosaic 记 `null` |
| `slotCount(p)` | 最终 `patternId` 对应模板在 Registry 中声明的 `len(template.slots)` |
| `filled(p)` | 页面槽位中具有非空 `assetId` 的槽位次数；重复或 foreign 引用仍算视觉占位，但由独立指标揭示 |
| `emptyRenderedPages` | `filled(p) = 0` 的实际内容页数 |
| `partialPages` | `0 < filled(p) < slotCount(p)` 的实际内容页数 |
| `fullPages` | `filled(p) = slotCount(p)` 的实际内容页数 |
| `emptySlots` | `Σ max(0, slotCount(p) − filled(p))` |
| `declaredSlots` | `Σ slotCount(p)` |
| `emptySlotRate` | `emptySlots / declaredSlots`；`declaredSlots = 0` 时记 `metricInvalid` |

必须使用**最终实际落下的 `patternId`**查询同次运行绑定的 Registry，不能使用系列 YAML 原始 `slotBand`，也不能根据已经填入的槽位数反推模板容量。管线输出了未知模板、空槽位声明或 `filled(p) > slotCount(p)` 时记 `outputInvalid`；如果只是采集器加载了错误版本的 Registry，则记 `metricInvalid` 并重跑。

必须满足：

```text
emptyRenderedPages + partialPages + fullPages = renderedPageCount
0 <= emptySlots <= declaredSlots
0 <= emptySlotRate <= 1
```

作品集现有文案“有 N 页没排满”来自计划履约或满槽判断，不能称为空页。三种情况必须区分：

- 计划了但没有生成：`omittedPlannedPages`；
- 生成了但一张未放：`emptyRenderedPages`；
- 生成了但未填满：`partialPages`。

### 2.2 页面降级不是页面失败

| 符号 | 定义 |
|------|------|
| `pageDegraded` | 计划模板无法使用，实际换成 fallback/demotion 模板并成功产出页面 |
| `pageRenderFail` | 已有页面计划，但模板解析或渲染执行失败；未执行 render 时记 `null` |

fallback 是鲁棒性策略，不得计入 `pageRenderFail`；但必须单独记录，供解释 series 或 mosaic 的适配能力。

## 3. 容量截断、装填缺口与 intake loss

不得只依赖作品集当前的 `overflow.resolution` 拆分原因。一次运行可能同时存在容量之外的照片和容量范围内未装入的照片，而单个 resolution 无法表达混合原因。

### 3.1 定义

| 符号 | 定义 |
|------|------|
| `capacityN` | series 选中系列的实际容量；mosaic 无固定系列容量，记 `null` |
| `seriesId` | series 实际选中的系列 ID；mosaic 记 `null` |
| `intakeLoss` | `eligible − intakeN`；公共 compose 入参中存在、但未进入该管线排版分组的资产数 |
| `overflowCapped` | 因固定系列容量不足而必然无法入册的资产数 |
| `placementGap` | 已进入管线且仍在可用容量范围内，却未出现在内容屏中的资产数 |
| `selectionResolution` | `capped` / `tier_upgraded` / `tier_upgraded_then_capped` 等系列选择过程说明；只作元数据，不直接决定上面两个计数 |

### 3.2 唯一计算公式

series：

```text
overflowCapped = max(0, intakeN - capacityN)
placementGap = max(0, min(intakeN, capacityN) - placedEligible)
```

mosaic：

```text
capacityN = null
overflowCapped = 0
placementGap = max(0, intakeN - placedEligible)
```

两条管线都必须满足：

```text
unplacedEligible = intakeLoss + overflowCapped + placementGap
eligible = placedEligible + intakeLoss + overflowCapped + placementGap
```

不得把“装不满”并进溢出，也不得把 `tier_upgraded` 本身解释为资产丢失。

## 4. compose 前排除项

`folderN − eligible` 是 compose 前已经排除的资产记录数，但它不一定都能证明是 cull 主动舍弃，且 `folderN` 也不保证等于磁盘原始文件数。

| 符号 | 定义 |
|------|------|
| `preComposeExcluded` | `folderN − eligible` |
| `cullDiscard` | 有明确 cull / 用户剔除 / 重复 / 低质量 reason 的排除数；reason 不完整时记 `null`，不得直接用 `preComposeExcluded` 冒充 |

若采集器能可靠拿到 reason，应进一步按原因分组；本页不强制冻结 reason 枚举。

## 5. 失败粒度：输入、管线、章节、页面分开

| 符号 | 定义 |
|------|------|
| `eligibleChapterCount` | 在公共输入中实际分配到至少一个 eligible asset 的内容章数 |
| `chapterFail` | 上述内容章在 compose 输出中没有任何有效内容 screen；无资产的结构章不计失败 |
| `pageRenderFail` | 见 §2.2；没有执行 render 时为 `null` |
| `attemptedRenderPages` | 实际提交给 renderer 的内容页数；没有执行 render 时为 `null` |
| `integrityFail` | 管线返回了结果，但出现重复填图、foreign 引用、未知模板、槽位越界或资产守恒破坏；对应 `status = outputInvalid` |
| `tripFail` | 输入有效，但 compose 抛出 `PortfolioUnavailableError` / `CurateError` 等错误，或未产生任何有效内容 screen |
| `errorCode` | 失败代码；无稳定代码时写异常类名 |
| `errorStage` | `snapshot` / `intake` / `select` / `plan` / `render` / `export` |
| `invalidReason` | `inputInvalid` / `metricInvalid` / `outputInvalid` 的可复核原因；`ok` 时为 `null` |

需要比率时必须写清分母：

```text
chapterFailRate = chapterFail / eligibleChapterCount
pageRenderFailRate = pageRenderFail / attemptedRenderPages
tripFailRate = pipelineFailTrips / validInputTrips
pipelineFailureRate = (pipelineFailTrips + outputInvalidTrips) / validInputTrips
```

`pageDegraded`、`omittedPlannedPages`、`emptyRenderedPages`、`chapterFail`、`integrityFail` 与 `tripFail` 可能有关联但不是可相加的互斥分类，报告中必须分列。可以按上式报告明确命名的 `pipelineFailureRate`，但不得把各层计数简单相加生成“总失败数”。发生 `tripFail` 时仍保留该管线行，无法计算的页面和覆盖指标写 `null`，不得写 0。

## 6. 耗时：分阶段、预热、重复测量

| 符号 | 起点 → 终点 |
|------|-------------|
| `planMs` | 进入 `compose_trip` / `compose_portfolio_trip` → 返回 chapters 与 meta |
| `renderMs` | assemble HTML；不含 compose |
| `exportMs` | 长图或页图导出；不含 compose 与 assemble |

采集纪律：

1. 使用单调高精度计时器，例如 `perf_counter_ns`。
2. 每趟、每条管线先预热 1 次，预热结果不进统计。
3. 默认正式运行 3 次；每次从公共快照重新深拷贝。
4. 两条管线交替执行，避免固定让后一条独享热缓存。
5. 保存原始 `planMsSamples`，行内主值使用 `planMsMedian`。
6. `EA-02a` 只强制采 `planMs`；`renderMs`、`exportMs` 与 `pageRenderFail` 缺测时写 `null`。
7. 不得用墙钟总数冒充规划耗时，也不得把三个阶段相加后直接宣称“谁更快”。

## 7. 密度与页数只记录、不评分

```text
density = placedEligible / renderedPageCount
```

`renderedPageCount = 0` 时 density 为 `null`，并按有效输入下未产出内容屏判定 `tripFail`。

游记意图偏向合格张尽量全收，作品集允许固定容量与留白。density 更低、页数更多或更少都不自动代表质量更差。禁止把 density、`renderedPageCount` 或 `emptySlotRate` 单独写入优劣排名；它们只能与覆盖、容量、降级和失败原因一起解释。

## 8. surface 适用边界

以下是跨 surface 的核心口径，`EA-02a`、`EA-02b`、`MG-02` 均不得另立定义：

- `eligible / intakeN / placedEligible / coverage`；
- 重复与 foreign 引用；
- `intakeLoss / overflowCapped / placementGap`；
- 输入、管线、章节和阶段耗时。

以下属于 surface profile：

- `plannedPageCount / renderedPageCount`；
- `slotCount / emptySlots / partialPages`；
- `density`；
- render 与 export 的页面失败定义。

`EA-02a`、`EA-02b` 使用 `surface = landscape-16x9`。`MG-02` 引入手机或长图前，必须增加 `mobile-9x16` / `longshot` profile，明确“页”和“槽位”在该投影中的单位。不能把 16:9 的页面数直接与手机流式块数比较。

## 9. 二十趟旅行的汇总口径

影子对照是同一 trip 的**配对实验**。每个汇总必须保留 pipeline、trip 和量级分组，不能先把所有行混成两个总平均数。

### 9.1 覆盖与装填

同时报告：

```text
microCoverage = Σ placedEligible / Σ eligible
macroCoverage = 所有有效旅行 coverage 的中位数
pairedCoverageDelta(trip) = coverage(series) - coverage(mosaic)
```

摘要至少包含：

- 全量 microCoverage；
- 全量 macroCoverage；
- 配对差值的中位数与 Q1/Q3；
- 稀疏 60–140、常规 196–326、超量 424–1000 三组分别汇总；
- win / tie / loss 数。`tieTolerance` 必须在运行清单中预先声明，执行后不得根据结果修改；本页不把它升级为质量门槛。

只报 micro 会让 1000 张旅行主导结果；只报 macro 又会弱化超量旅行的实际资产损失，因此两者缺一不可。

### 9.2 失败与耗时

- trip 失败率和完整性失败率都只以有效输入旅行数为分母，并分别报告；
- 失败旅行不得从报告中静默删除；
- `planMs` 报各管线的中位数、P90，并报告同一 trip 的配对差值；
- `inputInvalid`、`metricInvalid` 单列数量和原因，不并入任一管线胜负。

### 9.3 判定边界

EA-00 只冻结计算与汇总，不冻结“series 必须赢 mosaic”之类产品结论。实际 go/no-go 门槛由 `R0-04` 或对应阶段退出门引用本页指标后另行签字，禁止在看到结果后临时更换指标或分母。

## 10. 对照时禁止做的事

- 只比较 `folderN` / `eligible` 数量，不校验资产 ID、顺序和快照哈希。
- 两条管线复用同一个可变 `trip`、`chapters` 或上一轮运行结果。
- 用 `folderN` 当 coverage 分母。
- 用 mosaic 周报 `keptCount` 当 eligible。
- 用所有 `placedIds` 直接除以 eligible，而不与 `eligibleIds` 求交集。
- 去重计算 coverage 后，不记录重复槽位引用和 foreign 引用。
- 把 `overflow.count` 或单个 resolution 未拆原因就用于跨管线比较。
- 把作品集“没排满”叫空页，或忽略计划页被跳过。
- 把 fallback/demotion 直接计为页面失败。
- 把后处理插入的呼吸屏、封面、目录和收尾算作内容空页。
- 用 density、页数或 emptySlotRate 单独给管线打分。
- 把规划耗时和导出耗时相加后宣称“谁更快”。
- 只报告总体平均数，不保留同 trip 配对结果和量级分组。

## 11. 采集最小字段（给 `EA-02a`）

每趟旅行、每条管线一行。字段分组如下。

**运行身份**

`comparisonRunId, tripId, pipeline, edition, surface, measurementStage, status, inputSnapshotHash, eligibleSequenceHash, armConfigHash, codeRevision, seriesCatalogHash, templateRegistryHash`

**资产守恒**

`folderN, eligible, intakeN, placedEligible, placedUnique, placementOccurrences, coverage, duplicatePlacements, foreignPlaced, preComposeExcluded, cullDiscard, intakeLoss, capacityN, overflowCapped, placementGap`

**页面与章节**

`plannedPageCount, renderedPageCount, omittedPlannedPages, declaredSlots, emptyRenderedPages, partialPages, fullPages, emptySlots, emptySlotRate, pageDegraded, eligibleChapterCount, chapterFail`

**失败、计时与解释元数据**

`tripFail, integrityFail, pageRenderFail, attemptedRenderPages, errorCode, errorStage, invalidReason, planMsSamples, planMsMedian, renderMs, exportMs, density, seriesId, selectionResolution`

同一配对的公共快照或 eligible 顺序不一致时，两行都记 `inputInvalid`；不能只废掉其中一行。发生 `pipelineFail` 时保留身份、哈希、失败与耗时字段，其余无法计算项写 `null`。

## 12. 手算样例与验收恒等式

### 样例 A · series 同时发生容量截断和装填缺口

```text
folderN = 100
eligible = 80
intakeN = 80
capacityN = 72
placedEligible = 70

preComposeExcluded = 20
intakeLoss = 0
overflowCapped = 8
placementGap = 2
unplacedEligible = 10
coverage = 70 / 80 = 0.875
```

不能根据单个 `overflow.resolution` 把 10 张全部归为 capped 或 placement gap。

### 样例 B · mosaic 出现重复填图

```text
eligible = 40
intakeN = 40
placementOccurrences = 40
placedUnique = 38
placedEligible = 38
foreignPlaced = 0
```
