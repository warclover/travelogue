## 0. 文档说明

### 0.1 定位：这是一份「首屏视觉权重 + 货架效率 + 边界体验」的增量 PRD

v2.1（bench 三分法、主 CTA 恢复、stale 语言化）已落地并在本次走查中得到确认。本稿解决的是走查中新暴露的三类问题：

1. **边界体验（Boundary）**：窄屏 / 手机访问是死路；demo 资产占位符 404。按 **P0** 处理。
2. **首屏视觉权重（Visual Hierarchy）**：标题层级弱、双预览内容重复、氛围层过重、bench 在常见视口高度下贴底。按 **P1** 处理。
3. **货架效率（Shelf Efficiency）**：画册量已到 57 本，新建入口后置、无检索手段、卡片元信息扫读性差。按 **P1/P2** 处理。

### 0.2 走查总评（保留项，本稿不动）

以下是走查确认的**优势项**，v2.2 一律不动：

- 「Show, don't tell」双交付预览范式（16:9 卷轴 + 9:16 手机长图）
- H1 手写体情绪句「每一个瞬间，都值得再次相遇」+ Lead + 信任行（v2.1 已恢复）
- bench 三分法（主 CTA · 继续上次 · 最近画册 + ⚙）
- 恒常书架 + 「继续编辑」恢复卡的回访动线
- skip-link / aria / 键盘翻页 / 骨架屏 / 懒加载等工程质量

### 1.3 与北极星漏斗的关系

v2 漏斗：`homepage_view → cta_click → sheet_open → folder_picked → import_start → import_success`。

本稿假设：

- **H1**：手机 / 窄屏死路直接损失一部分 `homepage_view`（分享出去的链接在手机上打开即流失），D-20 将其转化为小程序阅读或"回电脑打开"的延迟转化。
- **H2**：书架效率（D-23 / D-24）主要作用于回访用户的 `cta_click`（新建）与画册打开率；57 本量级下线性翻页的检索成本已显著。
- **H3**：首屏视觉权重（HP22-03～06）作用于首访第一印象与 10s 理解率，间接影响漏斗第一跳。

## 3. P0 需求：边界体验

### 3.1 Unsupported 视口出口（D-20 · HP22-01 · **已交付**）

#### 需求

三种 unsupported 态在 title + lead 之下增加**动作区**：

| 态 | 保留文案 | 新增动作 |
|----|----------|----------|
| `unsupported_phone`（<768 触屏） | 请在电脑浏览器打开 Studio | ① 微信小程序码（阅读/分享入口）② 「复制电脑打开地址」按钮（复制 `http://<lan-ip>:8766/`，toast 确认） |
| `unsupported_narrow`（<768 桌面窄窗） | 请拉宽窗口至 1024px 以上 | 无需新增动作；lead 补充当前窗口宽度提示（如「当前 390px」），拉宽后**自动进入**工作台（现有 resize 监听保留） |
| `unsupported_rotate`（768–1023 竖屏） | 请旋转至横屏使用 Studio | 无需新增动作；旋转后自动进入（现状保留） |

#### 约束

- 小程序码资产：静态图片放入 `templates/studio/assets/miniapp-qr.webp`；服务端注入 `data-miniapp-qr="0|1"`（`inject_home_placeholders` 检测文件是否存在）。**无资产时不发起 QR 请求**，仅显示「小程序即将上线」占位 + 复制链接按钮。
- `viewport-logic.js` 的 `unsupportedCopy()` 返回结构扩展 `actions` 字段，保持纯函数可测。
- 深色 unsupported 页面背景保留，动作按钮对比度 ≥4.5:1。

### 3.2 demo 长图 URL 404（HP22-02a · **已修复**）

| 项 | 规格 |
|----|------|
| 根因 | `longshotPages[].url: "longshot-PLACEHOLDER.webp"` 为 demo 相对路径，但 `longshotPageUrl()` 走 `encodeTripAssetUrl()` 原样返回，浏览器解析为 `/longshot-PLACEHOLDER.webp` |
| 修复 | 新增 `resolvePageAssetUrl()`：相对路径 → `assetUrl()`（`/__studio/assets/demo-showcase/…`）；绝对 `/trips/…` 与外链行为不变；`pageImageUrl()` 同步 |
| 测试 | `tests/js/manifest.test.mjs` · 纳入 `test_v2_js_logic_node_units` |
| 防回归 | 既有 `test_ac_hp2_demo_assets_serve_200`（Playwright）继续断言 demo-showcase webp 均 200 |

### 3.3 demo 正式切图交付（HP22-02b · 非本期工程）

沿用 OQ-DEMO-ASSETS：设计交付后替换 `*-PLACEHOLDER.webp` 为 hash 文件名，递增 `manifest.version`。不阻塞 v2.2 其余项。

## 4. P1 需求：首屏视觉权重

### 4.1 标题层级补强（HP22-03）

| 项 | 规格 |
|----|------|
| H1 字号 | 桌面 ≥48px（现状约 32px 目测），手写体保留；`em` 强调段颜色加深一档 |
| 对比保障 | 文案区（eyebrow + H1 + Lead + 信任行）背后增加**局部 scrim**（径向渐变暗衬或 8px 毛玻璃），保证任意背景图下 H1 对比度 ≥4.5:1、Lead ≥7:1 |
| 层级级差 | eyebrow : H1 : Lead 字号比不低于 1 : 3 : 1.2，拉开三层差距 |
| 约束 | 文案内容一字不改（v2.1 §3.2 已冻结）；仅动视觉规格 |

### 4.2 双预览差异化（D-21 · HP22-04）

| 项 | 规格 |
|----|------|
| 默认帧错开 | 同一画册上台时：carousel 初始停**封面页**（pages[0]），手机框初始停**第 1 章节段**（非封面段）；两容器初始画面不得相同 |
| 翻页联动 | **不联动**（保持各自独立翻页，避免复杂化）；仅约束初始帧 |
| 校验 | 渲染完成后 DOM 检查：carousel 当前帧图源 ≠ 手机框当前段图源（AC-HP22-04） |
| 兜底 | 画册仅 1 页/1 段时豁免（如极小画册），允许相同 |

**Rationale**：首屏 2/3 面积是预览，两容器展示同一画面等于浪费一半橱窗。错开后首屏一眼呈现"封面 + 内页"两种版式，直接展示排版丰富度，也顺带回应 v2.1 R-03（"值得重新生成"的价值感知）。

### 4.3 氛围层减法与分区过渡（D-22 · HP22-05）

| 项 | 规格 |
|----|------|
| 装饰层 | `.v2-grain` 与 `.v2-vignette` **移除其一**（默认移除 vignette，保留细颗粒 grain；A/B 走查后定稿）；veil 不动 |
| 分区过渡 | hero 底缘 → 书架区顶部：增加 80–120px 渐变过渡带（hero 背景色 → 书架米色），消除硬分界线 |
| 性能 | 移除层同步删除对应 DOM 与 CSS，减少一层合成 |

### 4.4 首屏高度收敛（HP22-06）

| 项 | 规格 |
|----|------|
| 约束 | 视口高度 ≥720px 时，bench（含主 CTA 完整按钮）必须在首屏视口内完整可见，无需滚动 |
| 手段 | hero 区改用 `min(100vh - 预留, 上限)` 类高度策略；预览容器按视口高度等比收缩（保持 16:9 / 9:16 比例，缩尺寸不裁内容） |
| 校验 | 1024×768 / 1280×800 / 1440×900 三档自动化视口检查（扩展 AC-HP21-02 用例） |

**说明**：不改变 D-19（IdleReturning 主 CTA 在 bench）的位置决策，只保证该位置在常见视口内可见。
