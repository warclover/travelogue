> **定位**
>
> 预览页「编辑与设置」已把 Phase 4 能力收进四 Tab Sheet，但保存语义分裂、任务路径绕、命名偏工程，与 Phase 5「80% 零编辑」北极星仍有张力。
>
> 本 PRD 定义一次**体验层重设计**（非能力删减）：
>
> 1. **验货默认** — 打开预览 = 看成品；精修是显式次要模式。  
> 2. **情境侧栏** — 「这页 / 这本 / 导出与更多」替代模块四 Tab（**P1**）。  
> 3. **统一保存** — 文案立即生效；版面类改动收敛为「更新版面」；导出前拦截 pending（**P0**）。  
> 4. **命名分词** — 预览入口「精修」；首页设置改称「导入偏好」（**P0**）。
>
> **产品共识（五条铁律）**
>
> 1. **功能等价** — 现有文字 / 结构 / 排版 / 高级 / 页内控件能力不丢，只重组入口与心智。  
> 2. **主路径不弱化** — 80% 用户不打开精修即可导出；导出仍 ≤ 1 次点击（无 pending 时）；有 pending 时允许 +1（「更新并导出」）。  
> 3. **一种保存语义** — 禁止「半生效」：改了以为好了、导出仍是旧版。  
> 4. **反馈收敛** — 待办优先进 Task Dock；成功不刷屏 toast。  
> 5. **Share 不变** — `?share=1` 无编辑壳。
>
> **评审结论（2026-07-11）**：有条件通过（Conditional Go）· **批准 P0 开工**；Must-fix / 门禁见 §14。详细纪要见 [评审记录](./acceptance-records/preview-refine-v1-review-2026-07-11.md)。

## 1. 背景与问题

### 1.1 现状摘要

| 维度 | 现状（v4 Dock + v3 Sheet） | 用户感知 |
|------|---------------------------|----------|
| **入口** | Dock `⋯` →「编辑与设置」四 Tab | 像设置柜，不像编辑语境 |
| **文案** | 页内 inline-edit 立即保存；Sheet 文字 Tab 需「保存编辑」 | 两套规则 |
| **版面** | ★ / 拼图 / 同框 PATCH 后需「应用排版」 | 易漏；导出旧版风险 |
| **结构** | G1 埋在结构 Tab | pending 时不够醒目 |
| **导出设置** | 高级 Tab + Dock `▾` 并存 | 职责重叠 |
| **首页** | 「工作台设置」vs 预览「编辑与设置」 | 双设置，职责不清 |
| **反馈** | toast + Task Dock + 红点 + stale | 成功/待办需扫全屏 |

### 1.2 问题陈述（P-REF-*）

| ID | 问题 | 影响 |
|----|------|------|
| **P-REF-01** | 三种保存粒度并存 | 心智分裂；误以为已生效 |
| **P-REF-02** | 「应用排版」发现成本高 | 死胡同；错误导出 |
| **P-REF-03** | Sheet 按系统模块切 Tab | 与用户任务不匹配 |
| **P-REF-04** | 「编辑与设置」命名偏工程 | 80% 用户产生配置焦虑（断裂 O） |
| **P-REF-05** | 双「设置」入口未分词 | 导入偏好与单本精修混淆 |
| **P-REF-06** | 反馈面过碎 | 待办不可见、成功噪音 |
| **P-REF-07** | G1 藏在 Tab 内 | 结构待确认时路径绕 |
| **P-REF-08** | 导出相关设置进总 Sheet | 与主 CTA 脱节 |

### 1.3 核心判断

> **不删能力，改心智。**  
> 默认态是验货台；精修是情境侧栏；版面变更用一条「更新版面」收束；导出前系统盯着 pending。  
> 对齐 [PRD-PHASE5](./PRD-PHASE5.md) D13 / P5-3.7，并补齐 v3 Sheet 落地后仍未消解的保存语义与 IA 债务。

### 1.4 用户分层（沿用 Phase 5）

| Persona | 占比（估） | 本 PRD 策略 |
|---------|------------|-------------|
| **分享者** | ~80% | 验货 + 可选点字微调 + 导出；**零打开精修** |
| **编辑者** | ~20% | 精修侧栏「这页 / 这本」；更新版面后导出 |

## 2. 目标与非目标

### 2.1 产品目标

| ID | 目标 | 验收口径 |
|----|------|----------|
| **G-REF-01** | 零精修可完成主路径 | UX-P5-80-01 不回归；手测不打开精修可导出 |
| **G-REF-02** | 统一保存语义 | §4 保存矩阵 100% 落地；无半生效态可导出 |
| **G-REF-03** | 导出前拦截 pending | pending 时点导出 → 提示并一键更新版面（或取消） |
| **G-REF-04** | IA 按任务重组 | 侧栏三区替代四 Tab；能力保全表通过 |
| **G-REF-05** | 命名分词 | 预览「精修」；首页「导入偏好」 |
| **G-REF-06** | 反馈收敛 | 版面待办仅 Task Dock 一条；日常 inline 成功无「已保存到 trip.json」刷屏 |
| **G-REF-07** | G1 醒目 | pending 时顶栏横幅，不依赖打开侧栏 |
| **G-REF-08** | Share / 功能等价 | share 不变；§5 保全表 100% |

### 2.2 非目标

- 不重做排版引擎 / narrate / cohort 算法  
- 不引入独立富文本编辑器或协作编辑  
- 不改 Share minimal chrome  
- 不在本 PRD 解决 `trip.json` 写竞态乐观锁（见 [PRD-ARCH-OPTIMIZATION.md](./PRD-ARCH-OPTIMIZATION.md)；可并行 · **PK-02**）  
- 不把放映移出 Dock（**D-REF-03** / **PK-04**）  
- 不把首页导入偏好合并进预览精修  
- 不在本主题做章标题 inline（见 [PRD-CHAPTER-NAMING.md](./PRD-CHAPTER-NAMING.md) · **PK-01**）  
- **P0 不把阅读视图上 Dock**（避免四控件再挤；**PK-03** · P1 再定）  

### 2.3 成功指标（建议）

| 指标 | 目标 |
|------|------|
| 零打开精修完成导出占比 | ≥70%（种子用户样本） |
| pending 导致的错误导出 | → 0（导出前强制） |
| 「有编辑未更新版面」停留中位时长 | 较基线下降（Task Dock 可见后） |

| Dock 图标盲测 | ≥4/5 正确指认「精修」「长图」（§14.2 SF-02） |

### 2.4 主路径点击预算（评审补强）

| 步骤 | 计入？ | 预算 |
|------|--------|------|
| 返回 Studio | 否 | — |

| 有 `layoutPending` ·「更新并导出」 | 是 | **允许 +1**（合计 2；不可静默旧导出） |

## 4. 统一保存模型

### 4.1 心智一句话

> **字改完就定了；版式改完要点「更新版面」；导出前系统会帮你盯着。**

### 4.2 保存矩阵

| 操作 | 写入时机 | 画面生效 | 用户动作 |
|------|----------|----------|----------|
| Inline 文案（hook/lead/caption/…） | 立即 `save-copy` | 立即 | 无 |
| 杂志名（封面 / 侧栏） | 立即 | 立即 | 无 |
| 记忆锚点 / 章意图 / userNotes | 立即（失焦或 chip 变更） | 文案需重生才变 | 可选「按新意图重写」 |
| 封面版式 | 立即 | **自动更新版面**（D-REF-12） | 无（或短暂「正在更新…」） |
| 模板策略 | 立即 | 自动 rerender（维持）或并入更新版面 | 见实施注 |
| ★ 精选 | 立即 PATCH | **待更新** | 「更新版面」 |
| 拼图 ↔ 普通照片 | 立即 PATCH | **待更新** | 「更新版面」 |
| 旅行主角 · 同框 | 立即 | **待更新** | 「更新版面」 |

### 4.3 Pending 与导出拦截

```
layoutPending == true
  → Task Dock 常驻：「版面有更新 · 更新版面」
  → 精修图标红点（维持）
  → 点击「导出长图」→ 拦截 Modal（§4.3.1）
```

| 规则 | 说明 |
|------|------|
| 禁止 | pending 时静默导出旧长图（**MF-06**） |
| Task Dock「稍后」 | 可 dismiss 视觉，**不清除** pending；再次导出仍拦截 |
| 状态优先级栈（**D-REF-18**） | **G1（若有）> layoutPending > longshotStale**；同时最多一层主待办抢注意力 |
| 文案统一（**D-REF-07**） | 用户可见禁止再出现「应用排版」；一律「更新版面」 |

#### 4.3.1 拦截 Modal 规格（评审定稿 · MF-01）

| 项 | 规格 |
|----|------|
| 标题 | **版面尚未更新** |
| 正文（人话） | **你改过精选或拼图，导出前需先更新版面，否则长图仍是旧版。** |
| 禁止 | 正文出现 `layout` / `pending` / 英文内部词 |
| 按钮层级 | **主**「更新并导出」· **次**「仅更新版面」· **幽灵**「取消」——**禁止三颗同权** |
| 主按钮行为 | 更新版面（rerender）成功后自动开始长图导出 |
| 次按钮行为 | 仅更新版面；不自动导出 |
| 取消 | 关闭 Modal；pending 保留 |

### 4.4 反馈规范

| 场景 | 反馈 |
|------|------|
| Inline 保存成功 | 字段旁轻 ✓（≤0.8s）；**禁止**每次「已保存到 trip.json」 |
| 首次发现可编辑 | 保留一次 toast「点一下文案可修改」 |
| 版面类 PATCH 成功 | **不**只 toast；确保 Task Dock 出现待办 |
| 更新版面中 | Task Dock running + 可选整页 reload（维持现网） |
| 按新意图重写中 | 按钮 **busy/禁用**；完成前不可连点 |
| 错误 | toast 或 Task Dock error；人话 + 可重试 |

## 6. 方案规格

### 6.1 Icon Dock（验货默认）

```
┌────────────────────────────────────────────────────────────┐
│                                              ┌─────────────┐ │
│                                              │ ← ▶ ✎ [长图▾]│ │
│         封面 / 卷轴（验货）                    └─────────────┘ │
│           返回 放映 精修 导出（形象线描图标）                    │
└────────────────────────────────────────────────────────────┘
```

| 属性 | 规格 |
|------|------|
| 顺序 | **返回 · 放映 · 精修 · 导出**（D-REF-02/03） |
| 精修图标 | **笔形**（D-REF-01b）；tooltip / aria =「精修」 |
| 红点 | `layoutPending`；G1 优先横幅（P1） |
| 首访脉冲 | 脉冲**导出**（80% 路径）；精修不脉冲 |
| 导出主钮 | **图标 +「长图」文字**并存（纯图标首次认知偏弱 · 评审） |
| 导出 `▾` | 文案范围、图注/导语、按章/完整、清晰度 |
| 命中区 | 各图标按钮 **≥ 36×36px** |

#### 6.1.1 Dock 图标套件（D-REF-16 · 形象简洁）

> 原则：**一眼懂动作**；24×24 viewBox；描边 `1.75`；圆角端点；单色 `currentColor`；**禁止**装饰性齿轮齿、胶片齿孔、过密折角、折页阴影、双色描边。  
> 线框示意：[preview-refine-v1-wireframe.html](./wireframes/preview-refine-v1-wireframe.html) Tab「⑩ 图标」。

| 键 | 语义 | 图形隐喻 | 禁止 |
|----|------|----------|------|
| `back` | 返回 Studio | **左箭头**（简洁 chevron/arrow） | 复杂「合上的书册+折角」 |
| `play` | 放映 | **圆角画幅 + 实心播放三角** | 胶片两侧齿孔点阵 |
| `refine` | 精修 | **斜向钢笔/铅笔**（✎ 语义）；**笔尖与笔杆对比要够**，避免 18px 看成「/」 | 齿轮、`⋯`、六边形设置 |
