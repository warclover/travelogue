## 1. 年度目标

未来 12 个月只验证三项一级证据：

1. **首篇证据**：非开发者能在无指导情况下安装并完成第一篇；
2. **复用证据**：用户在 90 天内制作第二篇，或用于更高频的非旅行场景；
3. **付款证据**：至少一类非关联用户发生真实付款。

成功不是完成更多 Phase，而是形成可审计的用户和商业证据链。

## 2. 冻结原则

- 产品继续坚持本地优先、无需账号、照片默认不离开本机。
- Windows x64 是首个普通用户分发平台。
- 不并行开发 macOS、商店版或新桌面壳。
- 算法、模板和排版工作仅在真实用户证据表明其阻塞首篇、复用或付款时启动。
- 自动化测试不能替代干净机、真人、真照片和真实发群验收。
- 许可未决前，暂停新增“MIT”“永久免费”“永远开源免费”等对外承诺。
- 用户研究采用主动同意的观察、访谈、研究日志或本地导出，不以默认联网遥测破坏隐私承诺。

## 3. 指标口径

| 指标 | 定义 |
|---|---|
| 合格非开发者 | 非项目开发者；测试机无源码和 Python；此前未接受操作培训 |
| 独立完成首篇 | 自行安装启动，使用自己的至少 20 张照片完成导入、预览、保存 PNG，并找到产物；全程无操作指导 |
| 首篇完成率 | 独立完成首篇人数 ÷ 合格启动人数 |
| 90 日第二篇率 | 首篇完成后 7～90 天内，新建并导出另一篇作品的人数 ÷ 已成熟到 90 天的首篇完成者 |
| 非旅行扩展 | 使用聚会、婚礼、亲子、活动等素材完成独立作品；口头兴趣不计 |
| 真实付款 | 非项目成员、非直系亲友支付并结算；购买对象明确；14 天内未退款 |
| 有效样本 | 保存日期、设备、来源、协助情况、结果、耗时、失败点和证据链接 |

## 4. 阶段总览

| 阶段 | 时间 | 目标 | OMTM |
|---|---|---|---|
| S0 | 0～2 周 | 冻结口径，建立证据底座 | 5 人中独立完成首篇人数，目标 ≥4/5 |
| S1 | 2～8 周 | 交付安装版，验证完整首篇 | 独立首篇完成率，目标 ≥60%，N≥15 |
| S2 | 2～4 月 | 验证真实付款与场景扩展 | 真实付费用户 ≥3，至少 2 位非关联 |
| S3 | 4～8 月 | 验证 90 日第二篇与商业复现 | 90 日第二篇率 ≥30%，成熟 N≥20 |
| S4 | 8～12 月 | 受控放大并作年度决策 | 第二篇率维持 ≥30%，累计付费用户 ≥10 |

## 5. S0｜0～2 周：冻结口径，建立证据底座

### 阶段 OMTM

> 5 位合格非开发者中，独立完成当前可测首篇主路径的人数，目标 ≥4/5。

### 任务清单

#### GOV-001｜P0｜建立商业证据计分板

- [ ] 定义首篇、复用、付款等指标的分母、触发条件和排除条件。
- [ ] 建立样本登记表与周度证据看板。
- [ ] 明确每项指标 Owner。

- **验收**：禁止以下载量、Star、测试数替代一级指标。

#### LEG-001｜P0｜冻结许可与价格冲突文案

- [ ] 盘点 README、营销 PRD、安装器和官网材料中的许可承诺。
- [ ] 决定正式决策前的临时对外口径。
- [ ] 将待发布材料标记为不可上线或待决。

- **验收**：正式决策前不再新增 MIT、永久免费或付费承诺。
- **负责人建议**：项目负责人 + 法务/知识产权顾问。
- **工作量**：1～2 人日。

#### PROD-001｜P0｜评审桌面可安装版 V1

- [ ] 评审 `PRD-DESKTOP-INSTALLER-V1.md`。

- [ ] 形成 Gate A/B 实施与验收边界。

- **验收**：Gate A/B 不再停留于 Draft。
- **负责人建议**：产品 + 桌面工程 + QA。

#### QA-001｜P0｜建立真实状态与人工验收台账

- [ ] 按“未实现 / 代码完成 / 自动化通过 / 人工通过 / 真人通过”重建状态矩阵。
- [ ] 核验 Help W0～W3、Preview Refine、UX Trust、Export Facade 的真实状态。
- [ ] 给每个 Conditional Go 剩余条件指定 Owner。
- **交付物**：主题状态矩阵、人工验收 backlog。
- **验收**：无人工证据的主题不得标记为 Go。
- **负责人建议**：QA。
- **工作量**：2～3 人日。

#### UR-001｜P0｜执行首轮 5 人无指导测试

- [ ] 招募 5 位合格非开发者。
- [ ] 使用用户自己的照片完成主路径。
- [ ] 主持人不得提示点击位置。
- [ ] 记录安装、导入、等待、预览、导出、定位文件各阶段。
- **交付物**：5 份观察记录或录像、失败路径排序、耗时统计。
- **验收**：每个失败点可定位到具体步骤。
- **负责人建议**：用户研究 + 产品。
- **工作量**：3～5 人日。

#### COM-001｜P1｜设计首轮付费假设

- [ ] 只保留最多 3 个报价。
- [ ] 每个报价明确用户、交付、价格、成本和许可边界。
- [ ] 设计真实付款而非口头询问的验证方式。
- **交付物**：报价说明、访谈脚本、退款规则。
- **验收**：明确区分软件、服务和赞助。
- **负责人建议**：商业负责人 + 产品。
- **依赖**：实际收款等待 LEG-001 最低边界明确。

### Gate G0｜进入安装与外测

**Go**

- [ ] 5 位用户中 ≥4 位完成当前可测主路径；
- [ ] 状态矩阵完成；
- [ ] Installer PRD 已评审；
- [ ] 许可冲突已冻结。

**No-Go**

- 多数用户需要主持人提示；
- 主路径存在明显阻塞，团队却继续开发新算法；
- 许可冲突继续对外传播。

**No-Go 动作**

暂停新功能、官网扩建和推广，只修复前两大首篇阻塞点后复测。

## 6. S1｜2～8 周：交付安装版，验证非开发者首篇

### 阶段 OMTM

> 合格非开发者独立首篇完成率，目标 ≥60%，样本 N≥15。

### 任务清单

#### ENG-101｜P0｜交付 Windows Portable Gate A

- [ ] PyInstaller 改为 onedir。
- [ ] 收口 frozen 模板、schema 和静态资源路径。
- [ ] 关闭控制台黑窗，日志写入文件。
- [ ] 打包 demo、版本文件、SHA256 和中文使用说明。
- [ ] 无 Playwright 时仍可通过浏览器侧降级保存 PNG。
- **交付物**：Portable zip、构建脚本、冒烟脚本。
- **验收**：无 Python、无源码的 Windows 10/11 可双击完成 demo 与自有相册主路径。
- **负责人建议**：桌面工程。
- **工作量**：5～8 人日。

#### ENG-102｜P0｜交付 Windows Installer Gate B

- [ ] 每用户免管理员安装。
- [ ] 创建开始菜单入口。
- [ ] 用户数据迁移到 `%LOCALAPPDATA%\Travelogue\`。
- [ ] 覆盖安装保留作品。
- [ ] 卸载默认保留数据，可选删除。
- [ ] 发布 Installer、Portable 和校验和。
- **交付物**：Setup、卸载器、Releases 产物与发布说明。
- **验收**：安装、二次启动、升级和卸载均通过。
- **负责人建议**：桌面工程 + 发布工程。
- **依赖**：ENG-101。

#### QA-101｜P0｜执行干净机与真机矩阵

- [ ] 覆盖 Windows 10/11。
- [ ] 覆盖中文路径、OneDrive 路径、无 Python、无 Playwright和标准用户权限。
- [ ] 至少 5 台真机验证安装、导入、导出、升级和卸载。
- **交付物**：Installer 验收记录。
- **验收**：P0 阻塞缺陷为 0；虚拟机不替代全部真机。
- **负责人建议**：QA。

#### PROD-101｜P0｜只修首篇前三大阻塞

- [ ] 按发生率和严重度排序研究发现。
- [ ] 每轮最多处理 3 个首篇阻塞。
- [ ] 每项修复关联失败样本。
- [ ] 修复后必须由新用户复测。
- **交付物**：证据关联的修复清单。
- **验收**：不借机扩展 Help、模板或算法能力。
- **负责人建议**：产品 + 前端工程。

#### PERF-101｜P1｜决定是否默认开启并行优化

- [ ] 补齐 ingest→render 完整链路基线。
- [ ] 覆盖至少 3 档 Windows 机器。
- [ ] 验证无半写入、结构一致和内存门槛。
- [ ] 进行人工版式质量对比。
- **交付物**：默认开启或继续关闭的决策记录。
- **验收**：不得用不含 narrate/render 的 12.2 分钟结果直接放行。
- **负责人建议**：性能工程 + QA + 产品。

#### UR-101｜P0｜完成 15 人首篇漏斗测试

- [ ] 至少 15 名合格测试者。
- [ ] 至少 10 人不是开发者或摄影软件重度用户。
- [ ] 记录渠道、设备、完成、耗时、求助和失败步骤。
- **交付物**：首篇漏斗报告。
- **验收**：≥9 人独立完成；中位耗时 ≤30 分钟；安装启动成功率 ≥90%。
- **负责人建议**：用户研究。

#### OPS-101｜P1｜只运行两个种子渠道

- [ ] 选择一个作品传播渠道。
- [ ] 选择一个深度解释或垂直社区渠道。
- [ ] 从来源追踪到安装、首篇和后续报价。
- **交付物**：渠道招募素材与归因记录。
- **验收**：每渠道至少带来 5 名合格测试者；浏览量不作为成功。
- **负责人建议**：运营。

#### LEG-101｜P0｜确定最小可销售与研究合规边界

- [ ] 正式决定开源或专有许可方向。
- [ ] 完成隐私说明、购买条款、退款规则和第三方许可清单。
- [ ] 统一 README、营销、安装器和网站表述。
- **交付物**：许可决议、隐私说明、NOTICE 草案、销售条款。
- **验收**：照片版权和样例授权边界明确。
- **负责人建议**：项目负责人 + 法务顾问。

### Gate G1｜首篇可用性

**Go**

- [ ] N≥15，独立首篇完成率 ≥60%；
- [ ] 完成者中位耗时 ≤30 分钟；
- [ ] 安装启动成功率 ≥90%；
- [ ] 无数据丢失、静默导出失败或卸载误删；
- [ ] 许可与对外文案一致。

**No-Go**

- 独立完成率 <40%；
- 主要失败仍是安装、找不到入口或找不到导出文件；
- 试图用新增模板、算法或营销覆盖基础失败。

**No-Go 动作**

停止公开推广和新场景开发，追加 2～4 周可用性修复，再用 5 名新用户复测。

## 7. S2｜2～4 月：验证真实付款与初步场景扩展

### 阶段 OMTM

> 符合定义的真实付费用户数，目标 ≥3，且至少 2 位非关联用户。

### 任务清单

#### COM-201｜P0｜执行真实报价与收款实验

- [ ] 完成不少于 20 次明确报价。
- [ ] 记录接受、拒绝、支付、退款和购买理由。
- [ ] 订单中明确购买对象。
- **交付物**：报价页、订单记录、拒绝原因报告。
- **验收**：≥3 笔真实结算；至少 2 位非关联用户；14 天无退款。
- **负责人建议**：商业负责人。

#### PROD-201｜P0｜围绕付款阻力调整产品包

- [ ] 区分产品缺陷、报价缺陷与渠道错配。
- [ ] 收敛为一个主售卖对象。
- [ ] 删除无法清晰解释的版本差异。
- **交付物**：主产品包与交付边界。
- **验收**：80% 目标用户能复述“付钱得到什么”。
- **负责人建议**：产品 + 商业。

#### UR-201｜P0｜建立 90 日 cohort 跟踪

- [ ] 从首篇当天开始登记。
- [ ] 设计 D7、D30、D60、D90 回访。
- [ ] 区分自然复用和提醒后复用。
- **交付物**：cohort 台账与回访计划。
- **验收**：至少 20 位首篇完成者同意后续回访。
- **负责人建议**：用户研究。

#### UR-202｜P1｜验证两个非旅行场景

- [ ] 从真实用户需求中选择最多两个场景。
- [ ] 优先复用现有模板和管线。
- [ ] 不新建算法 Phase。
- **交付物**：场景试验记录。
- **验收**：每个场景 ≥3 人尝试；至少一个场景有 2 人独立完成并保存或分享。
- **负责人建议**：用户研究 + 产品。

#### QA-201｜P0｜建立月度外测发布门禁

- [ ] 每月最多一个外测候选版。
- [ ] 自动化主门禁通过。
- [ ] 3 台真机首篇冒烟通过。
- [ ] 数据目录、升级和回滚通过。
- **交付物**：月度发布清单与签字记录。
- **验收**：2714 项测试数量不作为单独放行依据。
- **负责人建议**：QA + 发布负责人。

#### OPS-201｜P1｜制作三份证据型案例

- [ ] 使用真实授权作品。
- [ ] 展示输入规模、耗时、结果和真实限制。
- [ ] 每份案例可归因到下载或报价。
- **交付物**：3 个真实案例。
- **验收**：取得书面授权；不使用未经验证的性能和许可描述。
- **负责人建议**：运营 + 法务复核。

### Gate G2｜付款证据

**Go**

- [ ] 至少 20 次明确报价；
- [ ] ≥3 笔真实付款，至少 2 位非关联用户；
- [ ] 明确至少一类购买对象和主要购买理由；
- [ ] 退款未显示严重价值落差。

**No-Go**

- 只有口头意愿、下载或点赞；
- 付款全部来自亲友；
- 购买的是大量人工服务，却被误记为软件验证。

**No-Go 动作**

暂停扩渠道，重新设计一个报价并再测试 10 次。连续两轮无付款，进入收缩或服务化评估。

## 8. S3｜4～8 月：验证 90 日第二篇与可重复商业路径

### 阶段 OMTM

> 成熟 cohort 的 90 日第二篇率，目标 ≥30%，成熟样本 N≥20。

### 任务清单

#### UR-301｜P0｜完成首个 90 日复用分析

- [ ] 统计自然第二篇率。
- [ ] 单列提醒后复用。
- [ ] 分析复用时间、放弃原因和非旅行场景。
- **交付物**：90 日复用分析报告。
- **验收**：成熟 N≥20；第二篇必须是独立新项目且成功导出。
- **负责人建议**：用户研究 + 数据分析。

#### PROD-301｜P0｜只修复用前三大障碍

- [ ] 每项障碍至少关联 3 名流失用户。
- [ ] 每轮最多 3 项改进。
- [ ] 优先处理恢复、最近项目和重复设置等摩擦。
- **交付物**：复用改进清单。
- **验收**：新 cohort 的 D30 领先指标改善。
- **负责人建议**：产品 + 工程。

#### COM-301｜P0｜确认单一主商业模式

- [ ] 比较付款、退款、支持工时和交付成本。
- [ ] 选择一个主报价和目标用户。
- [ ] 明确停止销售条件。
- **交付物**：定价页、成本结构和销售说明。
- **验收**：连续两个月存在非关联付款；单笔收入覆盖直接交付和支持成本。
- **负责人建议**：商业 + 财务/法务。

#### OPS-301｜P1｜建立轻量转介绍循环

- [ ] 为满意用户提供可选来源说明或推荐机制。
- [ ] 不强制水印。
- [ ] 归因到首篇和付款。
- **交付物**：推荐机制与归因记录。
- **验收**：至少 10 个合格线索来自现有用户转介绍。
- **负责人建议**：运营 + 产品。

#### ENG-301｜P1｜完成签名与发布运维

- [ ] 对主程序和安装包进行 Authenticode 签名。
- [ ] 建立证书续期、私钥管理和回滚流程。
- [ ] 抽样验证 SmartScreen。
- **交付物**：签名产物与发布手册。
- **验收**：3 台干净机无未知发布者硬阻断。
- **负责人建议**：发布工程 + 运维/法务。
- **依赖**：G2 通过后再投入高成本证书和发布基础设施。

#### LEG-301｜P0｜完成正式许可与内容授权治理

- [ ] 完成 LICENSE 或 EULA。
- [ ] 完成 NOTICE 与第三方依赖分发审查。
- [ ] 完成隐私政策与作品授权模板。
- [ ] 建立样例撤回流程。
- **交付物**：正式法务与许可文件。
- **验收**：代码许可、商业模式、安装器和样例作品授权一致。
- **负责人建议**：法务/知识产权顾问。

### Gate G3｜复用证据

**Go**

- [ ] 成熟 cohort N≥20；
- [ ] 90 日第二篇率 ≥30%，或一个非旅行场景由 ≥5 人独立完成且 ≥3 人再次使用；
- [ ] 连续两个月存在非关联付款；
- [ ] 支持与交付成本可控。

**No-Go**

- 第二篇率 <15%；
- 复用主要依赖人工催促或代制作；
- 付款不能覆盖直接交付成本。

**No-Go 动作**

暂停规模推广和平台扩张，在“一次性成册工具”“人工策展服务”“特定活动工具”中选择一个收缩方向。

- **交付物**：下一平台立项评估。
- **验收**：至少 10 名合格用户明确因平台流失，且其中 ≥3 人接受当前报价，才可立项。
- **负责人建议**：工程负责人 + 产品。

### Gate G4｜年度投资决策

**Continue**

- 90 日第二篇率 ≥30%；
- 累计真实付费用户 ≥10；
- 至少一个渠道可稳定带来首篇完成者；
- 严重数据事故为 0；
- 支持成本可承受。

**Narrow**

首篇和付款成立，但复用不足：收缩为一次性成册或活动交付工具。

**Pivot**

软件付款不足，但人工策展或代制作持续有人付费：转向服务产品，软件作为内部生产工具。

**Stop**

首篇、复用和付款连续两轮均未达门槛，且没有明确、可低成本修复的高频失败点。

## 11. 关键风险与缓解

| 风险 | 缓解 |
|---|---|
| 许可与商业模式冲突 | 先冻结营销承诺，再由负责人和法务决策 |
| 熟人样本产生假阳性 | 付款与规模 Gate 必须包含非关联用户 |
| 主持人过度帮助 | 禁止操作提示，受协助样本单列 |
| 零遥测导致复用难观测 | 主动同意回访、本地日志导出和研究日记 |
| Installer 消耗全部工程资源 | 只实现 Gate A/B 最小范围，高级能力后置 |
| 性能优化改变成书结果 | 质量等价与人工抽检拥有否决权 |
| 运营先于产品证据 | 渠道必须追踪到首篇和付款 |
| 服务收入被误读为软件验证 | 订单分别标记软件、服务、模板和赞助 |
| 90 日周期过长 | 从首个 cohort 当天开始 D7/D30/D60/D90 跟踪 |
