## 1. 文档目的

本 PRD 定义 Travelogue **智能排版** 的产品目标、可用信号（参数/指标）、排版策略、算法架构与分期路线，作为：

- 产品 / 算法 / 研发的**需求与验收基准**；
- 与 [PRD-LAYOUT.md](./PRD-LAYOUT.md)（版式 Composer）的分工补充：**PRD-LAYOUT** 侧重「怎么摆槽位」；**本文档** 侧重「按什么信号、什么策略决定顺序与分组」；
- 验收相册（mao / maomi / linzhi 等）差异解释与演进依据。

> **算法阈值与 pattern 白名单** 见 [LAYOUT-PLANNER.md](./LAYOUT-PLANNER.md)。  
> 本文档回答：**有哪些信号、策略如何组合、智能排版如何实现、分期做什么**。

## 2. 背景与问题

### 2.1 用户素材差异（实测）

| 来源 | 典型特征 | 对排版的影响 |
|------|----------|--------------|
| 手机/相机 **原生拷贝**（如 maomi） | EXIF 时间完整、分辨率高、可选 GPS | 时间切段准、低清剔除少、可按真实 chronology 编排 |
| **微信另存**（如 mao） | 压缩、EXIF 丢失、文件名日期粒度粗 | 连拍/phash 去重多、低分辨率剔除、同日扎堆 |

智能排版需在 ** heterogeneous 素材** 下仍产出可读、可解释的游记结构。

### 2.2 产品目标

| ID | 目标 | 衡量 |
|----|------|------|
| I-G1 | **时间主轴**清晰：读者感到「按旅程先后」阅读 | 章/屏顺序与 `takenAt` 单调性；G1 可解释切段理由 |
| I-G2 | **主题局部聚合**：同一段落内人物/宠物/风景尽量成组，不全局乱序 | 段内 run-length、混拼惩罚指标；人工抽检 |
| I-G3 | **版式匹配构图**：横竖全景各得其所 | 现有 screens/items 回归 + 金样例 |
| I-G4 | **可复现、可配置** | 同 trip + 同 config 重跑结果一致；权重可 YAML 配置 |
| I-G5 | **可 G1 干预** | 切段、封面、章序、拆/合 journey 可人工确认 |

### 2.3 非目标

- 全相册跨月 **同一人脸 ID** 全局聚类（误聚风险高、叙事乱序）
- 依赖 **相机 ISO/光圈/快门** 驱动排版（对游记叙事价值低）
- **RAW** 格式导入（产品已明确不支持；用户侧导出 JPEG/HEIC 即可）
- 像素级平面设计、自由拖拽 DOM
- 黑盒端到端排序且不可解释

## 3. 系统分层（现状）

```text
┌─────────────────────────────────────────────────────────┐
│  Layer 0  Ingest（Agent 0）                              │
│  EXIF、几何、质量、去重、人脸(弱)、启发式 tags            │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│  Layer 1  宏观结构 Curate（Agent 1）                      │
│  时间切段 → 日桶 → 章(3–5) → pattern(open/moment/…)       │
│  + 城市变化辅助切段                                       │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│  Layer 2  章内序（sort_bucket）                           │
│  takenAt ↑ → burstGroup 成块 → 组内 sharpness 排序        │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│  Layer 3  组屏 Layout / Screen Planner（Agent 1.5）     │
│  aspect run + person 标签 + 配额 + 时间邻近约束           │
└──────────────────────────┬──────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────┐
│  Layer 4  槽位渲染 Render（Agent 3）                      │
│  focalPoint, cover/contain, screen-tone                  │
└─────────────────────────────────────────────────────────┘
```

**规划新增（本文档核心）：** 在 **Layer 1 与 Layer 2 之间** 插入 **主题软聚类 + 段内序列优化**（Layer 1.5）。

## 4. 排版信号穷举

### 4.1 EXIF 与文件层

| 信号 | 字段/指标 | 现状 | 排版用途 |
|------|-----------|------|----------|
| 拍摄时间 | `takenAt` | ✅ | 排序、切段、章桶、混排时间窗 |
| 日期来源/置信度 | `dateSource`, `dateConfidence` | ✅ | 切段可信度；低置信降权 |
| GPS | `geo.lat/lon` | ✅ 读取 | geocode → `place.city`；切段辅助 |
| 城市 | `place.city` | ⚠️ geocode 可选 | 城市变化切段（`city_gap_days`） |
| 分辨率 | `nativeWidth/Height` | ✅ | `layoutEligible`、低清剔除 |
| 展示尺寸 | `width/height` | ✅ | 组屏、封面评分 |
| 长宽比形状 | `aspectKind` | ✅ | landscape/portrait/square/panorama/tall |
| 方向 | EXIF Orientation | ✅ 烘焙进像素 | 不单独存字段 |
| 相机 ISO/光圈/焦距等 | — | ❌ | 本期不做 |

**支持格式（Ingest）：** jpg/jpeg、png、webp、heic（需 pillow-heif）；**不支持 RAW**。

### 4.2 质量、去重与资格

| 信号 | 字段/指标 | 现状 | 排版用途 |
|------|-----------|------|----------|
| 清晰度 | `quality.sharpness` | ✅ | 封面/hero、连拍保留更清晰帧 |
|  perceptual hash | `dedupeGroupId` | ✅ | 近重复识别 |
| 连拍组 | `burstGroupId` | ✅ | 时间邻接成组；桶内排序 |
| 排版资格 | `layoutEligible`, `excludeReason` | ✅ | 是否进入版式池 |
| 素材类型 | `mediaClass` | ✅ | photo/screenshot/thumbnail/reupload/archive |
| 批次 | `ingestBatchId` | ✅ | 增量导入、调试 |

**配置（`config.yaml` · ingest）：** `phash_threshold`、`burst_seconds`、`low_res_*`、`detect_faces`、`face_min_size_px` 等。

### 4.3 内容识别与语义

| 信号 | 现状 | 粒度 | 排版用途 |
|------|------|------|----------|
| 人脸 | ✅ OpenCV Haar | 有/无 + `focalPoint` | contain、人物竖拼、封面加权 |
| person/face tags | ✅ | 布尔级 | 人物/风景分流组屏 |
| 时段 | ✅ 规则 | 早晨/白天/傍晚/夜景 | 标签、未来主题辅助 |
| 构图标签 | ✅ 规则 | 横图/竖图/方图/全景 | 标签 |
| 城市名 tag | ⚠️ geocode 后 | 字符串 | 标签 |
| **同一人 ID** | ❌ | — | 规划：`personClusterId` |
| **宠物** | ❌ | — | 规划：`subjectClass=pet` |
| **建筑/风光/食物…** | ❌ | — | 规划：vision / CLIP / VLM |
| 主色/色调 | ⚠️ 部分 | Web `screen-tone` | 规划：相邻屏色调连续 |

**配置（vision）：** `enabled`、`provider`（none | heuristic | clip | vlm）、`max_tags_per_asset`。

### 4.4 Trip / 章 / 叙事层

| 信号 | 现状 | 排版用途 |
|------|------|----------|
| 五类构图统计 | `curation.orientationSummary` | mosaic/九宫/拼图配额 |
| 时间段 | `cluster_time_segments` | 章数、多 journey 提示 |
| 章 pattern | open / moment / gallery / close | 章级叙事节奏 |
| 封面/hero 分 | `cover_score`, `hero_score` | 选 cover、章首 hero 屏 |
| exportLayout | mobile / web / auto | 双端不同规则与 cover |
| layoutEngine | legacy / screens | items vs screens |
| 用户锁 | pipeline.locks | structure / copy 锁定 |

### 4.5 版式约束层（组屏）

| 约束 | 说明 |
|------|------|
| Pattern 白名单 | landscape-1/4/6/9, portrait-1/2/3, mosaic-5, person-pair/triple… |
| 配额 | 如小 trip 不用 mosaic-5；九宫格按总量上限 |
| 人物竖图 | `contain`，避免裁脸 |
| 人物/风景 | 避免人物竖图与风景横图硬混 |
| 章首 hero | 章内 ≥5 张时横/全景开屏 |
| 时间混排窗 | `mixed_proximity_seconds`（默认 12s） |
| Mobile 拼图 | 总量 >30 才启用 puzzle 块配额 |

**配置（layout）：** `web_layout_engine`、`screen_plan_scope`（day | chapter）、`mixed_proximity_seconds`。

**配置（curate）：** `segment_gap_days`（默认 14）、`city_gap_days`（默认 3）、`min_bucket_size`（默认 3）。

### 4.6 与产品设想对照

| 设想策略 | 现状 | PRD 目标 |
|----------|------|----------|
| （1）时间线 | ✅ 主轴 | 保持，低置信日期降权 |
| （2）位置信息 | ⚠️ 辅助切段 | P1 增强 GPS 轨迹/停留点 |
| （3）同一人聚合 | ❌ | P2 段内 `personClusterId` + 时间/距离窗 |
| （4）宠物聚合 | ❌ | P1 标签 + 段内 run |
| （5）纯风景聚合 | ⚠️ 隐式分流 | P1 显式 `subjectClass` + 段内 run |

## 5. 排版策略规格

### 5.1 宏观分段（Layer 1 · 已有）

**输入：** 可排版 assets、`segment_gap_days`、`city_gap_days`、`place`

**规则：**

1. 按 `takenAt` 排序；
2. 相邻照片日期差 ≥ `segment_gap_days` → 新时间段；
3. 或城市变化且间隔 ≥ `city_gap_days` → 新时间段；
4. 段内再按 **日** 分桶；过小桶合并（`min_bucket_size`）；
5. 3–5 个桶映射为 3–5 **章**；首章倾向 `open`，末章 `close`，中段 `moment` / `gallery`。

**输出：** `chapters[]` 骨架、`TimeSegment` 警告（多 journey 提示）。

**G1：** 用户可合并段、拆成多本游记（见 ingest `journey_hints`）。

### 5.2 主题局部聚合（Layer 1.5 · 规划）

**原则：** 主题聚合必须是 **时间窗口内的局部优化**，不得打乱全局 chronology。

| 策略 | 推荐定义 | 默认窗口 |
|------|----------|----------|
| 同一人 | 相同 `personClusterId` 且时间差 < T | 同日或 2h（可配置） |
| 同一人 + 距离 | 上式且 GPS 距离 < D | D=500m（可选） |
| 宠物 | `subjectClass=pet` 连续 run | 同段、同日内 |
| 纯风景 | 无 person/pet 且 landscape/architecture | 连续 run，允许短间隔插入 1 张「过渡」 |

**禁止：** 跨 `TimeSegment` 因同一人/同宠物重排。

### 5.3 章内序列（Layer 2 · 增强）

**现状：** `takenAt` → `burstGroupId` 块 → 块内按 sharpness。

**目标（段内优化器）：** 在保持 **大致时间单调** 前提下，最大化软评分：

```text
Score(order) =
  + w_time    · chronological_smoothness
  + w_person  · same_person_adjacency
  + w_pet     · pet_run_length
  + w_scenery · landscape_run_length
  + w_aspect  · aspect_run_length
  - w_mixed   · person_scenery_alternation_penalty
  - w_jump    · large_time_gap_inside_run
  - w_tone    · adjacent_tone_discontinuity   （P1）
```

**实现建议：**

- 段长 ≤30：动态规划 / beam search；
- 更长：贪心构造 + 2-opt 局部交换；
- 硬约束：不重排 `layoutEligible=false` 资产；burst 块可整体移动不可拆（可配置）。

### 5.4 章 pattern 分配（Layer 1 · 可增强）

| 段内特征 | 倾向 pattern |
|----------|--------------|
| 段首、张数多 | open |
| 人物占比高 | moment |
| 竖图/风景多、张数多 | gallery |
| 末段 | close |

可由 **主题占比 + 张数 + 构图统计** 驱动，不仅靠索引位置。

### 5.5 组屏（Layer 3 · 已有，见 LAYOUT-PLANNER）

输入：优化后的 asset 序列 + tags + aspect。

规则摘要：

- 横图连续 run → stack-2/3、2×2、3×2、3×3；
- 人物竖图 → person-pair / person-triple / person-grid-8，fit=contain；
- 1 竖 + 2 横 → 时间跨度 ≤ `mixed_proximity_seconds`；
- 小 trip 禁用 mosaic-5 等（`MIN_TRIP_PHOTOS_FOR_MOSAIC`）。

### 5.6 槽位渲染（Layer 4 · 已有）

- `focalPoint` → WebP / cover 裁切中心；
- 人物 → contain；
- `screen-tone` 取自代表图主色（Web screens）。

## 9. 算法实现路线

### 9.1 设计原则

1. **硬约束 + 软评分**：硬约束保证可渲染（aspect ↔ pattern）；软评分做排序与聚类。
2. **时间主轴**：人物/宠物/风景聚合均为 **段内局部** 优化。
3. **可解释**：每章/段输出 `reason` 摘要供 G1 与验收记录。
4. **分阶段上线**：规则 → embedding → 可选 LLM 顾问（不改 DOM）。

### 9.2 流水线（目标态）

```text
Step 0  过滤     layoutEligible + mediaClass
Step 1  宏观分段  TimeSegment（时间 + 城市 [+ GPS 轨迹 P1]）
Step 2  主题标注  subjectClass, personClusterId（P1/P2）
Step 3  段内优化  软评分重排序（Layer 1.5）
Step 4  章分配    open/moment/gallery/close
Step 5  组屏      screen_planner / layout_planner
Step 6  G1        人工确认 / 锁 structure
Step 7  渲染      Render（零 LLM）
```

### 9.3 分期交付

| 阶段 | 内容 | 优先级 |
|------|------|--------|
| **P0** | 文档化现有信号；`dateConfidence` 低时弱化切段；调优 burst/mixed 参数；封面多目标（清晰+构图+非缩略图） | 高 |
| **P1** | CLIP/规则 `subjectClass`（pet/landscape/architecture）；段内软评分重排序；相邻屏色调连续 | 中 |
| **P2** | 人脸 embedding + **段内** `personClusterId`；GPS 停留点；LLM 章序顾问（仅建议，不绑死） | 低 |
| **不做** | 跨月全局同人聚类；ISO/光圈排版；RAW 支持 | — |

## 10. 验收标准

| ID | 描述 | 验收方式 |
|----|------|----------|
| I-ACC-01 | 原生 EXIF 相册（maomi 类）切段与 `takenAt` 一致 | 验收记录 + 日期单调 |
| I-ACC-02 | 微信压缩相册（mao 类）低清/去重行为可解释 | ingest 报告 + excluded 列表 |

| I-ACC-05 | P1 后段内优化不破坏全局时间序（段间不乱序） | 自动化：段边界前后 asset 序不变 |
| I-ACC-06 | G1 展示切段/多 journey 提示 | CLI WARN + 文档 |

## 11. 风险与对策

| 风险 | 对策 |
|------|------|
| 微信图日期假精度 | `dateConfidence` + filename 同日扎堆警告 |
| 人脸误检/漏检 | 仅作软信号；contain 仅在有 person tag 时启用 |
| 同人聚类误并 | 限制在 TimeSegment + 时间/距离窗；可 G1 拆段 |
| 主题模型过重 | 默认 heuristic；CLIP 可选、离线 |
| 与 PRD-LAYOUT 职责重叠 | 本文档管「序与组」；PRD-LAYOUT 管「槽与 pattern」 |
