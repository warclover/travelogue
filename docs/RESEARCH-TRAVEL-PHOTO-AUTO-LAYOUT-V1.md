## （1）用户真实需求整理

### 核心矛盾（一句话）

> 旅行拍了很多照片，但**整理 / 选图 / 写文 / 排版 / 分享**成本太高，结果大多「躺相册吃灰」；用户要的是**几分钟内可分享的故事成稿**，不是再学一套设计工具。

### 高频痛点（按出现频率）

| 层级 | 真实表述 | 典型证据 |
|------|----------|----------|
| **素材过载** | 一次行程 300–800+ 张，重复/糊图难筛，不知道留哪张 | 自驾 800 张拖 3 个月做相册；「90% 再也没打开」 |
| **叙事断裂** | 有图无文、时间线乱、忘了那天去哪/吃啥 | 「对着云相册刷半天也串不起故事」 |
| **表达门槛** | 不会写游记、九宫格装不下、朋友圈/小红书不知道怎么排 | 选图+文案+排版常需 2–3 小时 |
| **审美门槛** | 打印店模板呆板；Canva/PS 学习成本高；风格不统一 | 票根/手帐/杂志风诉求频繁 |
| **分享形态不匹配** | 相册「回忆」短视频不可控；链接打开率低；更想「一张长图发群」 | 微信群场景反复出现 |
| **隐私与归属** | 不愿把全家照片交给陌生云 SaaS | 「数据真正属于我」类自托管诉求 |
| **纪念物诉求** | 想给家人/孩子做实体相册或有仪式感的纪念卡 | 礼物、票根、手帐、打印书 |

### 需求分层（可直接当产品优先级）

**P0 · 完工效率（必须有）**

1. 一键导入本地/相册素材
2. 按时间 / GPS / 场景自动分章或故事线
3. 去重、去糊、挑「能讲故事的」图（或至少给可改的精选草案）
4. 自动版式（杂志/拼贴/长图），用户改草稿而不是从空白画布开始
5. 短文案/图注生成，可编辑
6. 一键导出可分享物（微信长图、PDF、链接等）

**P1 · 叙事与控制感**

- 保留删图、调章序、改标题/语气
- 主次构图（人像/风景主次、留白）
- 地图/地点 enrichment（可选）
- AI 出稿后「换一种布局」二次生成

**P2 · 场景延伸**

- 小红书/朋友圈专用尺寸与封面
- 实体相册书 / 票根 / 手帐风
- 亲子/家庭多人相册协作
- 短视频蒙太奇（Vlog 向，与「杂志游记」相邻但不同）

### 目标用户画像（检索共识）

| 画像 | 动机 |
|------|------|
| 旅行爱好者 / 摄影爱好者 | 快整理、有质感、可发朋友圈/群 |
| 亲子家庭 | 沉淀成长与出行记忆、做礼物 |
| 内容创作者 | 小红书/公众号出稿提速 |
| 隐私敏感用户 | 本地处理、不强制账号/云 |

### 检索来源摘要（用户声音）

| 来源类型 | 代表表述 |
|----------|----------|
| 创作者/黑客松提案（如「AI 旅行足迹」「AI 旅行手帐」） | 几百张照片没精力整理；筛选+排序+写文案拖数月；希望 5 分钟串成故事书 |
| 图文/拼图工具用户反馈（如 PagePop） | 不只是堆图，要按人像/风景安排主次；要像微型电影的长图 |
| 隐私向提案（如 TrailSnap） | 云相册只会分类搜索；票据/足迹串不起；不愿照片上第三方服务器 |
| 社交出稿场景（小红书/朋友圈） | 九宫格装不下；攻略/手帐/封面一键出稿；风格要统一 |

## （2）同类产品功能 vs Travelogue

### 赛道怎么切

```text
云端印刷相册书     社交图文模板      系统回忆/云相册      本地编辑台(本项目)
Journi / PastBook   美篇 / 黄油 / Canva   Apple/Google Photos   Travelogue
Chatbooks / 拾柒    PagePop / 红鸦AI      Immich(自托管)        桌面 Studio
```

### 功能对比表

| 能力维度 | Journi / PastBook / Chatbooks | Sidecar / PhotoBookLab / Sustain | 美篇 / 黄油 / Canva / PagePop | Apple/Google 相册 | **Travelogue（本项目）** |
|----------|-------------------------------|----------------------------------|------------------------------|-------------------|---------------------------|
| 定位 | AI 一键成**印刷相册书** | AI **数字旅行相册**（地图+时间线） | 模板/AI **社交图文** | 系统回忆短视频 | **本地杂志风游记编辑台** |
| 导入 | 手机卷/云盘 | 上传照片 | App/网页上传 | 系统相册 | **本地文件夹**（Studio） |
| 智能选图/去重 | 强（质量+重复） | 中–强 | 弱–中 | 中（回忆算法） | **有策展/聚类/可选 cull；Keep-All 等合同** |
| 时间线/GPS 分章 | 强（地图/邮戳） | 很强（Sidecar 主打） | 弱 | 中 | **EXIF 分章策展**；精确公开地图非主路径 |
| 自动排版 | 书页布局引擎 | 章节页+画册结构 | 模板/拼图/AI 布局 | 基本无杂志排版 | **杂志模板 + Mosaic/LSE 布局引擎** |
| 文案 | 弱–中（标题/图注） | 中（地点 enrichment） | 中–强（社交文案） | 弱 | **叙事填槽 + 可选 LLM**（NAS 可关） |
| 主交付物 | 实体书 / PDF | 分享链接 / 数字册 | 长图/笔记/海报 | 回忆视频 | **HTML 游记 + 微信长图 PNG**（zip 进阶） |
| 精修控制 | 「改成品」为主 | 可加个人回忆 | 强（拖拽模板） | 弱 | **预览精修 / 删图调序 / 双路径导出** |
| 隐私模型 | 云端上传为主 | 云端（Sidecar 称默认私密） | 云端 | 大厂云 | **本地优先、无强制账号** |
| 商业模式 | 印刷/订阅 | Freemium | 订阅/增值模板 | 生态绑定 | **买断实验中**（Community + Desktop License） |

### 各产品「会而本项目弱 / 不会而本项目强」

| 竞品强项（本项目相对弱或刻意不做） | Travelogue 差异化（竞品少见） |
|----------------------------------|------------------------------|
| Journi/PastBook：**实体印刷履约**、手机卷一键成书 | **桌面本地暗房**：照片默认不离机 |
| Sidecar：**足迹地图 + 地点百科式 caption** | **杂志装订感** HTML + **微信群可发长图** |
| 美篇/黄油：**社交生态、海量贴纸模板** | **策展管线**（ingest→curate→narrate→render）而非纯套模板 |
| Canva：**无限自由设计** | **稳定可预期版式**（模板填槽，非每次随机） |
| PagePop/HANYUAI：**生成式拼贴海报** | **整趟行程成册完工** + 预览/导出事务合同 |
| 系统相册：**零学习成本的回忆视频** | **可编辑、可归属的成稿**（zip/HTML/长图） |

仓库内既有结论仍成立（见 [PRD-WEBSITE-COMPETITIVE-RESEARCH.md](./PRD-WEBSITE-COMPETITIVE-RESEARCH.md)）：

> 在「**桌面 + 本地 + 摄影 + 长图 + 装订**」交叉点上，调研竞品几乎无人占满——这是 Travelogue 的护城河。

### 与用户需求的匹配度（对本项目的含义）

| 用户刚需 | Travelogue 现状匹配 | 竞品通常更强的点 |
|----------|---------------------|------------------|
| 几分钟出可分享成稿 | 主路径对齐（Studio → 长图） | 手机端入口、系统相册直连 |
| 自动分章/选图 | 强（布局/策展是核心工程） | 印刷书页美学库 |
| 朋友圈/微信群好看 | **长图是设计中心** | 小红书模板生态 |
| 隐私本地 | **章程铁律** | — |
| 实体相册书礼物 | 弱 / 非主业 | Journi、拾柒、Chatbooks |
| 地图足迹沉浸 | 弱–可选 | Sidecar、Journi |
| 完全自由 DIY | 非目标（稳定杂志心智） | Canva、黄油 |

### 代表性竞品速览

| 产品 | 一句话 | 与本项目关系 |
|------|--------|--------------|
| **Journi** | 手机端 AI 相册书：时间线 + 地图邮戳 + 印刷 | 同「旅行成册」，偏云端印刷 |
| **PastBook / Chatbooks** | 一键选图排版，分钟级出印刷书 | 同自动化，交付物为实体书 |
| **Sidecar Photo** | GPS→地图+时间线数字旅行册 | 同旅行叙事，偏足迹链接分享 |
| **PhotoBookLab / Sustain** | AI 章节/图注/主题数字画册 | 同「故事册」，云端 LLM 策展 |
| **美篇 / 黄油相机** | 社交图文模板与贴纸生态 | 同分享场景，偏手动模板 |
| **Canva** | 通用设计自由画布 | 同排版能力，学习成本高 |
| **PagePop / HANYUAI** | AI 拼图/相册页生成 | 同美学排版，偏单页/海报 |
| **Apple / Google Photos** | 系统回忆短视频 | 同「回忆整理」，不可控杂志成稿 |
| **Day One** | 本地/加密日记 | 同隐私心智，不做长图装订 |

---

## 简要结论

1. **真实需求**不是「再多一个拼图 App」，而是：**过载素材 → 有故事的成稿 → 低摩擦分享**，同时保留「改几笔就有人味」和「照片别被云端绑架」。
2. **竞品**大致分成：印刷书 AI、社交模板、系统回忆、数字足迹相册四类；Travelogue 落在 **本地桌面杂志游记 + 微信长图**，与章程一致。
3. **对标动作建议（仅洞察，非实施）**：继续打透「选文件夹 → 杂志成稿 → 发群长图」；地图/印刷/小红书模板可作周边，不宜稀释本地装订主叙事。
