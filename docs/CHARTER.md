## 1. 项目愿景

> **把智能体做成「旅行记忆的编辑」，而不是「旅行内容的工厂」。**

用户上传旅行中的照片与少量短视频，经智能策展与短文案填槽，输出 **可预览的杂志风 HTML 游记** 与 **微信长图 PNG**（Phase 2 主分享物）；zip 与小程序鉴权 HTML 为进阶选项。交付物归用户所有，默认本地处理。

> **2026-08-06 补记（定位不变，能力如实更新）**：主叙事仍是「一次做完的杂志游记 + 长图」，**不**重新定义为「多平台内容生成器」（见 §11 决策记录）。但截至本次补记，导出层已支持**六个平台一等公民导出**（微信群/朋友圈长图 · 小红书 · 公众号 · 画册 · 单张海报），且支持批量多选一次出全——这是「一次做完之后，随你发哪儿」的产出多样性延伸，不改变产品是什么、不作为独立主叙事对外宣传。海外社交平台扩展暂不评估。

> **2026-08-20 补记（第二形态，主叙事不变）**：可选「作品集」成册管线是显式第二产品形态，**默认仍是游记**；关旗行为与现网 GA 一致。不改写上文主叙事，不把作品集当成新的默认零步。

## 2. 问题与机会

| 现状 | 机会 |
|------|------|
| 相册乱序、重复、难讲故事 | 自动分章、去重、选封面 |
| 手写游记易拖延 | 20 分钟内得到可改草稿 |
| 通用 AI 写作流水账、与版式脱节 | 固定模板 + Agent 只填 `trip.json` |
| Vlog 工具重视频、博客平台重托管 | **照片 + 可选短视频 → 可分享 HTML 游记包** 缝隙 |
| 想搭旅行系统（Notion 日志/路线图）却常搁置 | **不卖终身 OS，卖这一趟成册完工** |
| 许多人只要「期待 → 照片汇总」，拒绝中间攻略工程 | **默认零步：选相册 → 出游记 → 分享** |

## 3. 项目目标（MVP）

| ID | 目标 | 成功信号 |
|----|------|----------|
| O1 | **可用**：从本地文件夹到可预览 HTML | 技术闭环跑通 |
| O2 | **好用**：种子用户 20 分钟内愿导出 | 3 次真实旅行平均时长 |
| O3 | **愿分享**：输出物可发给非开发者朋友 | ≥2 篇实际发出 |
| O4 | **稳定**：同数据重渲染版式一致 | 回归测试通过 |
| O5 | **可演进**：数据模型支撑后续托管分享 | `trip.json` v0.2 + schema |

## 4. 范围边界

### 4.1 In Scope（本项目做）

- 本地导入照片（≤250）与短视频（≤3）  
- EXIF / 分章策展 / 短文案生成 / 语音转写精简  
- 唯一模板 **`visual-journal`**（有声视觉相册）  
- 轻量 HTML（相对路径资源）+ zip 离线包 + 9:16 封面图（`preview.jpg`）  
- Agent 0 语义标签 + G1 记忆锚点（见 [adr/001](./adr/001-delivery-and-media.md)）  
- 3+1 Agent 流水线（见 `AGENT-ARCHITECTURE.md`）与 G1/G3 人工闸口  
- P0：CLI / 脚本；**Phase 2：Studio 工作台 + 服务端长图（微信群分享主路径）**  
- P1：轻量 zip 高级导出、PyInstaller exe  
- P3：小程序鉴权 HTML  

### 4.2 Out of Scope（本项目不做）

- 应用商店、账号体系、云同步、协作编辑  
- 多模板商城、自定义 CSS、评论与信息流  
- 完整 Vlog 剪辑时间线、长视频托管  
- 精确 GPS 公开展示、实时地图动画  
- SEO 站点、付费订阅、大规模运营

## 5. 干系人与用户

| 角色 | 诉求 |
|------|------|
| **项目发起人（P0）** | 自用验证、快速迭代、文档可支撑实现 |
| **种子分享者（P1）** | 比九宫格更有故事感、无需安装 App |
| **朋友（接收方）** | 微信/浏览器能打开、加载可接受 |

**MVP 只优先服务**：旅行结束后 **24–72 小时** 内想完成一篇分享页的用户。

### 5.1 需求截取（产品原则依据 · 2026-07）

一次旅行常被描述为「三次快乐」（决定出发 / 身在旅途 / 回家整理回味）。本产品**主职是第三次快乐的完工**——把照片变成可翻、可分享的成册；不与行前攻略库、终身旅行数据库竞争。

评论与调研中反复出现两类量产信号（须同时接住，且 FTUE 以更轻的一侧为默认）：

| 类型 | 行为 | 产品含义 |
|------|------|----------|
| **截取型** | 只要「期待 → 照片汇总」，跳过清单/模版/系统搭建 | 默认路径禁止「先建库再创作」 |
| **意向搁置型** | 羡慕完整旅行日志系统，常只做一趟路线图就停 | 成功看**本趟是否导出/分享**与**是否愿做第二趟**，不看是否搭好空系统 |

## 7. 核心原则（不可妥协）

### 7.1 工程与交付

1. **模板优先**：版式由模板与 manifest 决定，Agent 不直出 HTML。  
2. **先结构后文案**：章节确认（G1）后再叙事生成。  
3. **本地优先**：默认不上传用户 trip；API Key 仅本地配置。  
4. **隐私默认正确**：导出剥离精确 GPS；发布前确认。  
5. **人类在环**：用户可删图、改字、调序、补语音。

### 7.2 成册与防搁置（产品原则）

> 依据：旅行日志类内容的公开讨论与评论信号（如「只做首尾」「想做却搁置」）；与 Phase 17「最小用户干扰 · 直接给结果」同向。  
> **操作化 PRD**：[PRD-FINISH-THIS-TRIP-V1.md](./PRD-FINISH-THIS-TRIP-V1.md)（FTT · 「这一趟做完」）。

6. **成册完工，非旅行 OS**：主职是把**这一趟**做成可预览、可分享的游记；不卖终身知识库、不要求维护 Travel Planner。行前系统（Notion 等）可并存，但不得成为本产品前置。  
7. **默认按截取路径设计**：标准路径是 `选相册 → 出游记 → 分享`。任何「先配置系统 / 先填愿望清单 / 先学模板」只能后置可选，不得挡在第一次成稿之前。  
8. **汇总要珍贵，不要倾泻**：「照片汇总」交付的是策展后的稀疏成册（杂志气口、该拼才拼），不是网盘式全量倾倒，也不是朋友圈九宫格替代品。  
9. **防搁置优先于功能堆叠**：功能增减以是否提高「首趟真正导出/分享」与「第二趟仍愿再来」为准；增加仪式感或空置系统的能力，默认否决。  
10. **话术对齐完工，不绑生活方式人设**：对外强调「旅行结束，照片还在——游记一次做完」；不把自己绑成 Notion 替身或「只有 J 人才懂」的规划美学。

## 8. 成功标准与退出条件

### 8.1 MVP 完成（Go）

满足 `ACCEPTANCE.md` 中 **AC-01～AC-07** 全部通过（含微信群长图 AC-07）。

### 8.2 继续投入（P1）

- 至少 1 次非开发者正向反馈  
- 分享路径（zip 或静态托管）在微信内可读  

### 8.3 暂停或 pivot

- 3 次真实 trip 均无法在 30 分钟内得到「愿导出」结果  
- 模板/渲染稳定性无法保证（同 JSON 多次渲染不一致）

## 11. 决策记录（已拍板）

| 决策 | 结论 |
|------|------|
| 产品定位边界（2026-08-06） | 讨论"是否在制作初始即选平台走独立管线、正式改口为多平台内容生成器"后拍板：**主叙事不变**——不推翻竟品调研「本地+装订+长图」护城河判断，不将六平台导出升格为独立主叙事；多平台导出仅作为"完工之后随你发哪儿"的产出多样性能力如实记录（见 §1 补记）。海外平台扩展明确列为**暂不评估**，避免资源隐性偏移 |
| 作品集第二形态（PFM，2026-08-20） | 显式可选成册管线，**默认仍是游记**；关旗 ≡ 现网 GA。不改主叙事（AS-PFM-04） |
| 模板 | `visual-journal` v0.2.1，退役 `editorial-light` 为参考 |
| 断点 | 768px（48rem）；手机 9:16 深色 overlay，Web 16:9 浅色 |
| 交付形态 | **zip 包为主**；MVP 不做 Base64 单文件 HTML（ADR-001） |
| Agent 模型 | 0 ingest + 可选视觉标签；1 规则为主；2 LLM 填槽；3 零 LLM 渲染 |
| 数据版本 | `trip.json` **0.2** |
| 首版 UI | CLI + 脚本（Tauri 可延后） |
| 封面 | MVP：Pillow 固定版式 9:16 |
