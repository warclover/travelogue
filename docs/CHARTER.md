## 1. 项目愿景

> **把智能体做成「旅行记忆的编辑」，而不是「旅行内容的工厂」。**

Travelogue 是一款本地优先的照片成册工具。创作者在电脑上选定照片，系统基于统一页序完成自动编排，并优先生成适合手机阅读、可直接分享的竖版长图。16:9 网页、页图和 ZIP 是同一编排计划的派生留存产物，而不是并列的产品形态。

完成姿态见 [收敛任务清单.md](./收敛任务清单.md) `R0-01`：分享出去。交付物归创作者所有，默认本地处理。读者不安装、不注册、不学习操作。多平台导出不是独立主叙事，海外社交平台扩展暂不评估。

### 1.1 用户关系（已锁）

创作者在电脑上选照片并生成作品；朋友、家人是手机端读者，只接收分享结果，不需要安装、注册或学习操作。这两种角色不得混成「用户都会操作本产品」。

### 1.2 产物层级（已锁）

竖版长图是 v1.0 的第一交付物，也是「任务完成」的主要标志。16:9 网页、页图和 ZIP 是同一内容的**次级派生 / 留存产物**，不再与长图并列为另一套产品。次级派生只表达产品优先级，**不得因此降低质量门槛**。

### 1.3 数据模型（已锁）

只允许一份统一的 LayoutPlan / 页序作为事实源；竖版长图、移动预览和 16:9 输出都由它投影产生。禁止继续形成彼此独立的编排逻辑，也禁止新增第三套独立编排管线。

### 1.4 双管线终局（已锁）

series 是目标主路径，mosaic 是旧旅行兼容层和回归参照，不是永久并列产品。在 [收敛任务清单.md](./收敛任务清单.md) `SE-00a`、`SE-00b` 和质量门槛通过前，不得把「目标主路径」写成「当前已经可替换」。mosaic 的退出必须以旧数据可读、长图能力等价以及既定质量门槛通过为前提。工程上在 mosaic 退出前，双管线隔离（DPI）仍然有效。

## 2. 问题与机会

| 现状 | 机会 |
|------|------|
| 相册乱序、重复、难讲故事 | 自动分章、去重、选封面 |
| 手写游记易拖延 | 20 分钟内得到可改草稿 |
| 通用 AI 写作流水账、与版式脱节 | 固定模板 + Agent 只填 `trip.json` |
| Vlog 工具重视频、博客平台重托管 | **照片 + 可选短视频 → 可分享 HTML 游记包** 缝隙 |
| 想搭旅行系统（Notion 日志/路线图）却常搁置 | **不卖终身 OS，卖这一趟成册完工** |
| 许多人只要「期待 → 照片汇总」，拒绝中间攻略工程 | **默认零步：选相册 → 出游记 → 分享** |

## 3. 项目目标（MVP）

| ID | 目标 | 成功信号 |
|----|------|----------|
| O1 | **可用**：从本地文件夹到可预览 HTML | 技术闭环跑通 |

## 4. 范围边界

### 4.1 In Scope（本项目做）

收敛期以 [收敛功能生命周期.md](./收敛功能生命周期.md)（`R0-03`）为准：下列历史条目**不构成继续扩张的许可**。短视频、AI 文案、多平台导出预设为冻结维护；小程序鉴权 HTML 改为 post-1.0。

- 本地导入照片（≤250）；短视频既有能力冻结维护、不扩规格  
- EXIF / 分章策展  
- 唯一模板 **`visual-journal`**  
- 竖版长图为第一交付物；16:9 网页、页图、zip 为次级派生留存  
- P0：CLI / 脚本；Studio 工作台  
- Windows 安装版  

### 4.2 Out of Scope（本项目不做）

- 应用商店、账号体系、云同步、协作编辑、分享链接、小程序鉴权托管  
- 多模板商城、自定义 CSS、评论与信息流  
- 完整 Vlog 剪辑时间线、长视频托管、手机采集或手机编辑  
- 精确 GPS 公开展示、实时地图动画  
- SEO 站点、付费订阅、大规模运营  
- 新社交平台、新卡片比例、新的运行时 AI Agent  

### 4.3 收敛变更准入（2026-09-01 · `R0-03`）

任何新增需求必须关联现有收敛任务编号，并证明属于：完成 `R0-01` 主闭环、通过 `R0-04` 门槛、保障旧 trip 兼容、或减少现有复杂度。否则自动归入 post-1.0。未关联任务编号的新增功能不得进入 v1.0。

## 5. 干系人与用户

| 角色 | 诉求 |
|------|------|
| **创作者** | 在电脑上选照片、编排、导出；本产品的唯一操作者 |
| **读者（朋友、家人）** | 手机端只接收分享结果；不安装、不注册、不学习操作 |
| **项目发起人（P0）** | 自用验证、快速迭代、文档可支撑实现（属于创作者） |
| **种子分享者（P1）** | 比九宫格更有故事感（属于创作者） |

**MVP 只优先服务**：旅行结束后 **24–72 小时** 内想完成一篇分享页的用户。

### 5.1 需求截取（产品原则依据 · 2026-07）

一次旅行常被描述为「三次快乐」（决定出发 / 身在旅途 / 回家整理回味）。本产品**主职是第三次快乐的完工**——把照片变成可翻、可分享的成册；不与行前攻略库、终身旅行数据库竞争。

评论与调研中反复出现两类量产信号（须同时接住，且 FTUE 以更轻的一侧为默认）：

| 类型 | 行为 | 产品含义 |
|------|------|----------|
| **截取型** | 只要「期待 → 照片汇总」，跳过清单/模版/系统搭建 | 默认路径禁止「先建库再创作」 |
| **意向搁置型** | 羡慕完整旅行日志系统，常只做一趟路线图就停 | 成功看**本趟是否导出/分享**与**是否愿做第二趟**，不看是否搭好空系统 |

## 7. 核心原则（不可妥协）

### 7.1 工程与交付

1. **模板优先**：版式由模板与 manifest 决定，Agent 不直出 HTML。  
2. **先结构后文案**：章节确认（G1）后再叙事生成。  
3. **本地优先**：默认不上传用户 trip；API Key 仅本地配置。  
4. **隐私默认正确**：导出剥离精确 GPS；发布前确认。  
5. **人类在环**：用户可删图、改字、调序、补语音。

### 7.2 成册与防搁置（产品原则）

> 依据：旅行日志类内容的公开讨论与评论信号（如「只做首尾」「想做却搁置」）；与 Phase 17「最小用户干扰 · 直接给结果」同向。  
> **操作化 PRD**：[PRD-FINISH-THIS-TRIP-V1.md](./PRD-FINISH-THIS-TRIP-V1.md)（FTT · 「这一趟做完」）。

6. **成册完工，非旅行 OS**：主职是把**这一趟**做成可预览、可分享的游记；不卖终身知识库、不要求维护 Travel Planner。行前系统（Notion 等）可并存，但不得成为本产品前置。  
7. **默认按截取路径设计**：标准路径是 `选相册 → 出游记 → 分享`。任何「先配置系统 / 先填愿望清单 / 先学模板」只能后置可选，不得挡在第一次成稿之前。  
8. **汇总要珍贵，不要倾泻**：「照片汇总」交付的是策展后的稀疏成册（杂志气口、该拼才拼），不是网盘式全量倾倒，也不是朋友圈九宫格替代品。  
9. **防搁置优先于功能堆叠**：功能增减以是否提高「首趟真正导出/分享」与「第二趟仍愿再来」为准；增加仪式感或空置系统的能力，默认否决。  
10. **话术对齐完工，不绑生活方式人设**：对外强调「旅行结束，照片还在——游记一次做完」；不把自己绑成 Notion 替身或「只有 J 人才懂」的规划美学。

## 8. 成功标准与退出条件

### 8.1 MVP 完成（Go）

满足 `ACCEPTANCE.md` 中 **AC-01～AC-07** 全部通过（含微信群长图 AC-07）。

### 8.2 继续投入（P1）

- 至少 1 次非开发者正向反馈  
- 分享路径（zip 或静态托管）在微信内可读  

### 8.3 暂停或 pivot

- 3 次真实 trip 均无法在 30 分钟内得到「愿导出」结果  
- 模板/渲染稳定性无法保证（同 JSON 多次渲染不一致）

| 产物层级（2026-09-01 · `R0-02`） | 竖版长图是第一交付物，也是任务完成的主要标志。16:9 网页、页图和 ZIP 是次级派生 / 留存产物，不再与长图并列。次级派生 **不降低** 质量门槛。 |
| 用户关系（2026-09-01 · `R0-02`） | 创作者在电脑上操作；读者只在手机端接收分享结果，不安装、不注册、不学习。 |

| 作品集第二形态（PFM，2026-08-20） | **已被 2026-09-01 `R0-02` 取代。** 16:9 不再作为第二产品形态或并列主产品；仅为同一编排计划的次级派生 / 留存。关旗与 DPI 隔离在 mosaic 退出前仍按工程合同执行。 |
