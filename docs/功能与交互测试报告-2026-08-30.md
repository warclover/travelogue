## 3. 问题清单

### BUG-01｜示例画册“设为首页预览”操作必然失败，且反馈互相矛盾

- 优先级：P1
- 类型：功能错误 / 状态一致性 / 误导性反馈
- 复现率：100%

复现步骤：

1. 在没有用户画册的隔离环境进入首页；
2. 点击“试用示例”并等待生成完成；
3. 在成功页点击“设为首页预览”；
4. 观察首页预览和提示信息，随后刷新页面再次观察。

实际结果：

- 页面先提示“已设为首页预览”；
- 随即又提示“原预览画册已不可用，已切回示例”；
- 首页选择器仍显示“示例作品”且不可选择；
- 刷新后仍未形成可持久化的用户画册预览状态。

期望结果：

- 如果示例画册不允许成为用户首页预览，则成功页不应展示该按钮；
- 如果产品允许设置示例，则首页预览解析、持久化和选择器必须统一支持该状态；
- 一次操作不应同时出现成功和失败两种结论。

影响：

- 用户会误以为设置已经成功，刷新后又发现无效；
- 成功页的主操作失去可信度；
- 双重提示让用户无法判断最终状态。

源码证据：

- `templates/studio/homepage-v2/first-success.js:372-375`：只要存在 `tripId` 就展示“设为首页预览”，未排除示例画册；
- `templates/studio/homepage-v2/first-success.js:657-668`：写入后无条件提示成功；
- `templates/studio/js/constants.js:18-24`：`demo-album` 被明确识别为示例；
- `templates/studio/homepage-v2/trip-preview.js:58-59`：首页候选会过滤所有示例画册；
- `templates/studio/homepage-v2/bento-tabs.js:161-175`：无法解析被保存的示例 ID 后回退并提示“原预览画册已不可用”。

建议方案：

采用最小改动方案：成功页在 `isDemoTrip(result)` 为真时隐藏“设为首页预览”，或将按钮改为明确的“返回首页查看示例”。正常用户画册继续保留设置能力。不要让写入函数和预览解析函数对“合法 tripId”采用不同标准。

验收标准：

- 示例完成页不再出现无效的设置操作；
- 普通用户画册仍可设置为首页预览，并在刷新后保持；
- 单次点击只产生一个与最终状态一致的反馈；
- 增加示例与普通画册两类端到端用例。

### BUG-02｜明确选择“按章分开”，最终仍导出整篇单图

- 优先级：P1
- 类型：核心功能错误 / 用户配置被覆盖
- 复现率：100%

复现步骤：

1. 打开已生成画册的预览页；
2. 打开导出设置，选择“微信群”“带文字”“按章分开”；
3. 点击“确定”；
4. 再次打开设置确认“按章分开”仍为选中状态；
5. 点击长图导出并检查成功提示和导出清单。

实际结果：

- 设置面板正确保存并回显“按章分开”；
- 导出完成后提示“已导出 1 张微信群长图”；
- `导出文件/longshot-current.json` 显示 `kind: "whole"`，文件数组只有 1 项；
- 实际产物是 1 张 `856 × 14930` 的整篇长图，而不是按 3 个章节拆分。

期望结果：

- 显式选择“按章分开”后，导出产物应按章节拆分；
- 成功提示、清单元数据和文件数量应与设置一致；
- 如果当前平台不支持分章，设置项应禁用并提前解释，不能接受选择后静默覆盖。

影响：

- 用户配置未生效，导出结果不可预测；
- 长图可能过高、过大，增加查看和分享成本；
- 用户只能通过检查文件才能发现错误，容易误分享。

根因定位：

- `templates/studio/preview-toolbar/longshot.js:1138` 会把 `prefs.mode` 正确发送为 `segmentMode`；
- `travelogue/web/studio_handlers/export_handlers.py:596-605` 也正确解析和校验了请求值；
- 但 `travelogue/web/studio_handlers/export_handlers.py:749-753` 在解析输出配方后，根据 `recipe.layout` 再次覆盖 `segment_mode`。当配方为 `single` 时，用户显式选择的 `chapter` 被改回 `full`。

建议方案：

建立明确的优先级：用户显式选择 `full/chapter` > 配方默认值；只有 `segmentMode` 缺失或为 `auto` 时，才允许 `recipe.layout` 决定最终模式。建议在后端保留 `segment_mode_is_explicit`，避免在后续流程中丢失用户意图。

验收标准：

- 配方为 `single`、请求为 `chapter` 时必须分章；
- 配方为 `chapter`、请求为 `full` 时必须整篇；
- 请求为 `auto` 时才跟随配方；
- UI 选中态、请求体、成功提示、manifest 和文件数量五者一致；
- 增加后端集成测试和浏览器端产物测试，不能只断言偏好值已写入。

### BUG-03｜无效/不允许的本机路径未在确认前被阻断

- 优先级：P1
- 类型：输入校验 / 错误前置 / 无效操作
- 复现率：100%

复现步骤：

1. 首页点击制作入口；
2. 展开“其他导入方式”；
3. 输入 `C:/__travelogue_missing_folder__`；
4. 点击“使用此路径”；
5. 在确认页观察状态和主按钮，再点击“开始制作”。

实际结果：

- 页面显示“未能清点照片，可更换文件夹或直接开始”；
- “开始制作”仍然可用；
- 点击后服务端返回“不允许从该路径导入”。

期望结果：

- 对不存在、越界、不允许访问等永久错误，应在确认前明确阻断；
- 主按钮应变为“更换文件夹”或禁用“开始制作”；
- 只有清点超时、照片很多等可恢复/可降级情形，才允许用户继续制作。

影响：

- 用户被引导执行一个已知不会成功的操作；
- 错误反馈延迟，增加一次无意义等待；
- “未能清点”将权限错误、路径不存在、超时等完全不同的情况混为一谈。

源码证据：

- `templates/studio/homepage-v2/import-wizard.js:346-352`：所有 `failed` 状态统一显示“可更换文件夹或直接开始”；
- `tests/unit/web/test_import_wizard_payload_contract.py:86-95`：现有测试还冻结了这条允许继续的文案，导致错误交互被当作契约保护。

建议方案：

让路径预览接口返回可操作的错误分类，例如 `denied/not_found/not_directory/timeout/too_many`。前端按错误类别决定是否可继续：永久错误阻断并提供“更换文件夹”，瞬时或降级错误才允许“仍要开始”。不要仅依赖一个布尔型 `failed` 状态。

验收标准：

- 不存在、不允许、非文件夹路径不能进入可启动状态；
- 超时/照片过多仍可在明确风险提示后继续；
- 失败文案、按钮状态和后端最终可执行性一致；
- 为每类错误补充按钮可用性和下一步动作的端到端测试。

### BUG-04｜永久路径错误的“重试”会重复提交同一路径，且缺少可见恢复入口

- 优先级：P1
- 类型：错误恢复 / 操作闭环 / 文案一致性
- 复现率：100%

复现步骤：

1. 按 BUG-03 的步骤启动无效路径导入；
2. 在“导入失败”弹窗中点击唯一可见的“重试”；
3. 观察后续结果。

实际结果：

- 非鉴权失败时，可见操作只有“重试”；
- 点击后直接使用相同的 `albumPath` 再次调用导入，因此相同的永久错误再次出现；
- 页面没有可见的“换文件夹”“返回导入”或“留在首页”操作；
- 错误建议使用“Sheet 内的「浏览文件夹」”，属于实现术语，且当前弹窗中没有对应入口；
- 帮助页写着“导入失败 → 换文件夹重试 / 新建一篇”，与实际失败弹窗不一致。

补充说明：按 Escape 或点击遮罩可以退出，因此不是技术上的绝对死锁；但恢复动作不可发现，键鼠普通用户很容易在失败循环中反复点击主按钮。

期望结果：

- 永久路径类错误的主操作应为“更换文件夹”，并返回导入选择步骤；
- “重试”只适用于网络中断、临时服务错误等可恢复故障；
- 至少提供一个可见的退出/留在首页操作；
- 所有提示使用用户语言，例如“导入窗口”，不要暴露“Sheet”等内部组件名。

根因定位：

- `templates/studio/homepage-v2/import-failed.js:128-140`：非鉴权错误会隐藏“留在首页”，默认只保留“重试”；
- `templates/studio/homepage-v2/import-failed.js:261-278`：本机路径重试直接复用原 `pending.albumPath`；
- `templates/studio/js/errors.js:60`：`E_STUDIO_ALBUM_DENIED` 的建议包含“Sheet 内”术语；
- `templates/studio/studio-home-v2.html:466-467`：虽然模板存在“留在首页”，但运行时逻辑将其隐藏。

建议方案：

建立按错误码驱动的动作矩阵：

- `E_STUDIO_ALBUM_DENIED`、路径不存在、非目录、空相册等永久输入错误：主按钮“更换文件夹”，清理旧 pending 并回到选择步骤；
- 临时服务异常、超时等瞬时错误：主按钮“重试”；
- 所有失败页保留次要操作“留在首页”；
- 帮助文案和实际按钮保持同一套动作名称。

验收标准：

- 永久路径错误点击主按钮后回到路径/文件夹选择步骤；
- 不再自动重放同一个已知无效路径；
- 鼠标、键盘和触屏用户都能发现退出路径；
- 错误文案不再出现“Sheet”等内部术语。

### UX-05｜默认整篇长图体积和高度较大，导出前缺少风险预告

- 优先级：P2
- 类型：导出体验 / 性能感知
- 性质：优化建议，不属于导出失败

实测结果：

- 16 张示例照片的微信群整篇长图导出成功；
- 图片尺寸为 `856 × 14930`；
- 文件大小为 `17,314,485` 字节，约 `16.51 MiB`；
- 导出前没有突出展示预计高度、文件大小或大图风险。

潜在影响：

- 用户完成较长时间的导出后，才发现文件不适合当前设备或分享方式；
- 大图打开、预览和传输成本较高；
- BUG-02 会进一步放大此问题，因为用户无法通过“按章分开”主动规避。

建议方案：

- 在导出确认区给出预计张数、预计高度和粗略体积；
- 超过可配置的软阈值时建议“按章分开”或降低密度；
- 提供面向分享的压缩档位，同时保留高质量原图选项；
- 修复 BUG-02 后，再根据真实分章产物重新评估默认策略。

## 4. 自动化测试与质量保障问题

### QA-01｜现有导出测试停留在设置层，没有验证最终产物

本轮执行：

```text
node --test tests/js/longshot-export-panel.test.mjs tests/js/cqa-export-chapter-contracts.test.mjs
```

结果为 39/39 通过。其中已有用例验证“改用按章”会写入 `prefs.mode=chapter`，但没有继续验证请求经过输出配方解析后的最终 `segment_mode`，也没有检查 manifest 和文件数量。因此，设置层全部通过仍无法发现 BUG-02。

建议增加三层断言：

1. 前端请求体包含用户明确选择；
2. 后端解析后的最终模式不被配方覆盖；
3. 实际 manifest、文件数量和章节数符合预期。

### QA-02｜清点四态文案冻结测试已与实现结构脱节

定向运行 `test_m3_preview_four_states_copy_frozen` 时失败。测试仍要求字符串“已清点 ”直接存在于 `import-wizard.js`，但当前成功摘要已经改由 `import-wizard-logic.js:340` 的 `wizardPhotoSummaryLine` 生成。页面功能本身可工作，失败原因是测试对源码位置和字面量耦合，而不是行为断言。

建议将该测试改为：

- 单测 `wizardPhotoSummaryLine` 的输出；
- 浏览器测试四种清点状态下的可见文案和按钮状态；
- 同时修改“failed 仍可直接开始”的旧断言，按 BUG-03 的错误分类重新定义契约。

补充验证：后端非法 `segmentMode` 的定向测试通过，说明输入枚举校验仍然有效；缺陷发生在合法值进入输出配方后的优先级覆盖阶段。

1. 修复 BUG-02：确保显式分章配置具有最高优先级，并补齐后端集成与产物测试；

5. 在分章功能稳定后实施 UX-05 的体积预估和压缩提示。

## 7. 测试边界

- 本轮使用内置示例和隔离目录，没有读取、删除或修改用户真实照片；
