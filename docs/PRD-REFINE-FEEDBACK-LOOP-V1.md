> **定位**
>
> 精修骨架（验货默认 · 模式≠面板 · 首尾装帧 · 更新版面 · 导出拦截 · 帮助抽屉）已齐，但实机暴露两条**意图反馈断裂**：
>
> 1. **首尾装帧有能力、无发现** — 用户不知道「点候选缩略图 = 换封面/封底」。  
> 2. **精选有写入、无画面承诺** — 「更新版面」实际是 `/rerender`，不重跑策展；标已上屏图后几乎零变化，却被 toast 暗示「点更新版面后生效」。
>
> 本 PRD **不推翻**精修 V1 铁律（字即时 · 版式待更新 · 导出盯 pending），也 **不扩** Bookends / Curate 算法质量。只做一次**闭环对齐**：让用户知道「怎么换首尾」、明白「精选意味着什么」、并在精修路径上给出**可感知、可解释**的下一步——避免只加一句 tip 却留下上下游文案/门禁/导出拦截互相打架。

### 0.1 推荐总案 · D-FEED-01 方案 B′（分层反馈）

把「版式类改动」拆成三类，**禁止用同一句「点更新版面后生效」糊弄**：

| 改动类 | 代表操作 | 用户期望 | 系统应做 | 用户可见反馈 |
|--------|----------|----------|----------|--------------|
| **A · 渲染类** | 拼图↔普通、同框刷新 | 这一屏样子变 | **更新版面** = `/rerender`（维持） | 屏样式变化；Dock「更新版面」 |
| **B · 意图类** | ★ 标/取消精选 | 「这张更重要」被记住，且最好看见用途 | **立刻**写 `userTier`；★ 态同步；**不**假装 rerender 会换图位 | toast + 「这页」说明：影响放映精选 / 下次重排加权；可选 CTA「按精选重排」 |
| **C · 结构类** | 按精选重排、重新生成结构 | 封面/章首/屏构图可能变 | 显式确认 → `/curate`（或约定的轻量 repick）；busy 态零 L1 | 进度 + 完成后 diff 摘要（至少「封面是否更换」） |

> **一句话**：更新版面负责「画出来」；按精选重排负责「重新选片排版」；精选本身负责「留下意图」。三者不得同名。

## 1. 背景与问题

### 1.1 狗粮事实（2026-07-14）

| ID | 现象 | 用户解读 | 根因分层 |
|----|------|----------|----------|
| **P-FEED-01** | 想换封面/封底，不知道点哪里 | 「系统不能换」或「只能看」 | **发现性**：能力在「这本 → 首尾装帧 → 候选缩略图」，无首次 tip；「备选」一词只出现在低置信 banner |
| **P-FEED-02** | 一屏多张标 ★ →「更新版面」→ 几乎无变化 | 「精选没意义」或「排版坏了」 | **语义断裂**：promote 只写 tier；`/rerender` 不重跑 `run_curate`；已上屏图 ★ 仅弱样式；toast 却说「点更新版面后生效」 |
| **P-FEED-03**（衍生） | 帮助 H2 / 精修 hint 仍教「改精选要更新版面」 | 强化错误期望 | **上下游文案合同**与实现不一致 |
| **P-FEED-04**（衍生） | 导出拦截 Modal：「你改过精选或拼图…」 | 以为更新后构图会变 | **拦截文案**把意图类与渲染类捆在一起 |
| **P-FEED-05**（衍生） | ★ 只能升不能降 | 「标错了没法改」 | **对称性缺失** |

### 1.2 As-Is 技术事实（编码真值）

```text
★ promote-tier → trip.json userTier=featured → layoutPending=true（前端）
更新版面 → POST /rerender → render_trip（读现有 chapters/screens）
         ✗ 不调用 run_curate / apply_layout_to_trip
         ✗ 不重算 coverAssetId / folioPlan.featuredGridAssetIds

换封面/封底 → 首尾装帧候选 click → repick-opening/closing → 立即重渲染（已可感知）
重新生成结构 → POST /curate（G1 / 结构抽屉 / 首页 stale）→ 才消费 W_feat
```

| 承诺来源 | 承诺内容 | 现网是否兑现 |
|----------|----------|--------------|
| 精修 V1 §4.2 | ★ → 待更新 →「更新版面」 | 流程有；**「画面生效」对已上屏图常不可感知** |
| 附录 A §4 | featured 影响封面/章首/Plate/grid | **仅 curate 时**；预览 promote 后不自动 curate |
| 附录 A §6 | structure_locked 后改 tier → relayout 或 G1 解锁 | 预览无引导到该路径 |
| Phase 4 US | 「标精选 → 重跑排版时优先上屏」 | 「重跑排版」≠「更新版面」；用户不可见此分词 |
| 帮助 V1 H2 | 改精选请先点「更新版面」 | 强化 P-FEED-02 |
| Bookends / REFUX | 缩略图可点换封面 | **能力在**；发现性不足（P-FEED-01） |

### 1.3 为何不能「只加一句 tip」

| 若只修局部 | 仍会炸的上下游 |
|------------|----------------|
| 只加首尾 tip | 精选空洞感仍在；帮助仍教错 |
| 只改 ★ toast | 拦截 Modal / Dock / H2 仍说「精选要更新版面」 |
| 把 curate 塞进更新版面 | 耗时长、可能打乱已确认 G1 结构、与「忙碌态零 L1」冲突、分享者主链被重型化 |
| 取消 pending（精选不再拦导出） | 拼图改判与精选若共用门禁，可能误放行「未 rerender 的拼图态」；需分因后才能松 |

**结论**：必须 **分因 + 分路径 + 全文案合同一次对齐**。

## 2. 目标与非目标

### 2.1 目标

| ID | 目标 | 度量 |
|----|------|------|
| **G-FEED-01** | 首次进入首尾装帧的用户能在 **≤10s、无旁白** 完成「换一张封面或封底」 | AC-FEED-01～03；S-BE 新手脚本 N≥5 |
| **G-FEED-02** | 用户理解：★ = 留下「这张更重要」；**不等于**立刻重排整本 | AC-FEED-04～06；访谈「精选是什么」正确率 |
| **G-FEED-03** | 渲染类改动（拼图等）经「更新版面」**仍有可感知变化**；意图类改动有**诚实反馈 + 可选重排** | AC-FEED-07～10 |
| **G-FEED-04** | 帮助 / Dock / Modal / toast **同一套分词表**，禁止互相矛盾 | AC-FEED-11 |
| **G-FEED-05** | 导出拦截不回归；忙碌态零 L1 不回归 | AC-FEED-12；沿用 AC-HELP-13 |

### 2.2 非目标（V1 明确不做）

| 不做 | 说明 |
|------|------|
| 重做 Bookends / Cover 算法质量 | 属 Bookends / Cover 专项 |
| 全站 Product Tour | 与帮助 V1 铁律一致 |
| 把「更新版面」默认同义为 full `/curate` | 分享者主链不可被重型化 |
| 自动在每次 ★ 后后台 curate | 成本、锁定结构、不可预期跳动 |
| 正文屏拓扑大改（MCS / Screen Planner） | 越界 |
| 小程序换封面页 | 仍消费 Decision；本主题只 Studio |
| 「永不显示」总开关产品化 | 可复用帮助重播键即可 |

### 2.3 成功心智（对用户说的三句话）

1. **换封面/封底**：打开精修 →「这本」→「首尾装帧」→ **点缩略图**。  
2. **标精选**：告诉系统这张更重要；马上会出现在「放映精选」池；若要改封面/章首构图，请用 **「按精选重排」**（会确认）。  
3. **更新版面**：让拼图等**已经改过的版式**画进预览/长图；**不是**重新 AI 选片。

## 3. 体验合同

### 3.1 分词表（全局冻结 · 覆盖帮助/Dock/Modal/toast）

| 用户可见词 | 含义 | 禁止混用 |
|------------|------|----------|
| **更新版面** | 消化**渲染类** pending：`/rerender` + 刷新预览 | 「重新选片」「重新排版」「应用排版」 |
| **按精选重排** | 按当前 `userTier` 等意图 **重新策展/重排**（确认后） | 与「更新版面」做成同一按钮 |
| **重新生成结构** | 既有 G1/结构能力（可与「按精选重排」共用后端 `/curate`，但文案场景不同） | 在精选 toast 里偷换出现 |
| **完成** | 退出精修模式 | 更新版面 |
| **换封面 / 换封底** | 点首尾候选缩略图 | 「备选」单独作按钮名（banner 可用「备选有限」） |

### 3.2 保存矩阵（修订精修 V1 §4.2）

| 操作 | 写入 | 画面生效 | 用户动作 | pending 因 |
|------|------|----------|----------|------------|
| Inline 文案 | 立即 | 立即 | 无 | — |
| 封面版式 | 立即 | **自动更新版面**（维持 D-REF-12） | 无 | — |
| 拼图 ↔ 普通 | 立即 PATCH | **待更新** | **更新版面** | `media` |
| 同框 / cohort | 立即 | **待更新** | **更新版面** | `media` |
| ★ 标精选 | 立即 promote | ★ 立即亮；**不**承诺构图变 | 可选「按精选重排」；**默认不**因纯 tier 强制「更新版面」 | 见 **D-FEED-03** |
| ★ 取消精选 | 立即 demote | ★ 立即灭 | 同上 | 同上 |
| 换封面/封底候选 | 立即 repick | **立即**（可感知换图） | 无（已即时） | — |
| 按精选重排 | 确认后 curate | 结构可能变 | 确认 Modal | busy → 完成后清 |

#### D-FEED-03 推荐细则（待拍板）

| 方案 | 纯 ★ 是否置 `layoutPending` | 导出行为 | 推荐度 |
|------|------------------------------|----------|--------|
| **3a** | **否**（仅 `media` 置 pending） | 纯精选不拦导出；拼图仍拦 | **推荐**（诚实 + 少空操作） |
| **3b** | 是，但 Dock 文案改为「已记下精选 · 可选按精选重排」；导出不因纯 tier 拦截 | 需导出门禁读 reason | 可接受 |
| **3c** | 维持现状（纯 ★ 也 pending + 拦截） | 继续空跑更新版面 | **不推荐** |

> **拍板默认写入本文**：采纳 **3a**，除非评审改选 3b。  
> 混改（先 ★ 再改拼图）：pending 以 `media` 为准，拦截文案只提拼图/版式，不提「精选会变构图」。

### 3.3 首尾装帧发现性合同（D-FEED-02）

| 触点 | 规格 |
|------|------|
| **首次展开「首尾装帧」**（含从封面空态「去调封面与封底」深链） | 一次性可见 tip（toast 或区内 lead）：**「点下方缩略图，即可更换封面或封底」**；seen 键全局，可被帮助「重播」清除 |
| **区头文案** | Opening 组：`换封面 · 点选一张`；Closing 组：`换封底 · 点选一张`（替换仅靠 aria） |
| **点候选成功** | 轻反馈：选中角标「当前」+ 可选短 toast「已换封面」/「已换封底」（≤2s）；**禁止**再弹教学 tip |
| **低置信 banner** | 维持「备选有限…」；与教学 tip 不抢同一视觉层（banner 在上/tip 一次） |
| **忙碌态** | `isHelpL1Blocked()` 为真时不弹教学 tip；展开后可排队至 idle（对齐帮助 D-HELP-08′） |
| **与 L1 互斥** | 若长图 tip / 平台 tip 活跃，延后首尾 tip（同一时间只亮一个 L1） |

### 3.4 精选反馈合同（方案 B′）

#### 3.4.1 即时层（必做 · M1）

| 项 | 规格 |
|----|------|
| ★ 点击 | 立即亮/灭（demote 后）；同步「这页」镜像 |
| toast（promote） | **「已标为精选」**；副句二选一（合同句，禁止再写「点更新版面后生效」）：① 「会优先出现在『放映精选』」② 「若要按精选改构图，请用『按精选重排』」 |
| toast（demote） | 「已取消精选」 |
| 「这页」说明 | 固定一行：`精选 = 记下这张更重要；不会立刻重排整本` |
| present | 「放映精选」在 featured 池非空时可点；空池说明「先在正文点 ★」 |

#### 3.4.2 可选重排层（必做 · M2）

| 项 | 规格 |
|----|------|
| **入口** | ① Task Dock / 「这页」次按钮「按精选重排」；② 与 G1「重新生成结构」可共用确认壳，但标题/后果文案按场景区分 |
| **确认 Modal** | 标题「按精选重新排版？」；正文说明可能改动：封面候选加权、章首、部分屏构图；**已锁定结构（structure_locked）须明示风险**；主按钮「重新排版」· 次「取消」 |
| **执行** | `POST /curate`（`force` 策略与现网 G1 对齐，或后续轻量 `curate?scope=tier`——若 M2 来不及做 scope，允许复用 force curate，但文案必须诚实） |
| **完成反馈** | 「排版已更新」+ 若封面 asset 变化则附加「封面已更换」；自动清相关 pending |
| **失败** | 人话 + 可重试；不丢 `userTier` |

#### 3.4.3 明确不做的「假反馈」

- 禁止为通过验收而给 featured 加夸张高亮边框冒充「重排成功」。  
- 禁止 rerender 后 toast「版面已按精选更新」除非确有结构字段变化。

### 3.5 导出拦截人话（随 D-FEED-03）

| pending 因 | Modal 正文 |
|------------|------------|
| `media` | 「你改过拼图或版式相关设置，导出前需先更新版面，否则长图仍是旧版。」 |
| `media` + 其他 | 以 `media` 为准 |
| 无 pending | 不出现 |
| 纯 `tier`（若选 3a） | **不拦截** |

「更新并导出」仍只跑 **更新版面（rerender）**，不跑 curate。

## 11. 新手脚本（评审 / 手测）

### S-BE · 换封面（无旁白）

1. 打开任一成书预览 → 精修  
2. 找到并更换封面  
3. 观察：是否无需讲解找到「首尾装帧」并点缩略图  

### S-FEAT · 精选语义（无旁白）

1. 在正文屏标 1～2 张 ★  
2. 点「更新版面」（若出现）或尝试导出  
3. 口述：精选做了什么？若要让封面更可能用到它，下一步点什么？  

**通过**：能说到「记下更重要 / 放映精选」；若期望换构图，能指向「按精选重排」而非坚信「更新版面会换图」。
