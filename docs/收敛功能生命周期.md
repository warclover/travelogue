本页不是功能广告，也不是新 PRD。它盘点**现有用户能力和公开入口**的生命周期，并冻结每个分类**允许发生的变更**。

## 1. 定义

盘点现有用户能力和公开入口，确定其生命周期；收敛期间只有直接服务 `R0-01`、质量门槛、旧数据兼容和复杂度削减的变更可以进入 v1.0。

### 1.1 四类标签

| 标签 | 含义 | 允许变更 |
|------|------|----------|
| **v1.0** | 主闭环所必需 | 可以继续开发，但**只能为达到 `R0-04` 门槛**（含为达到门槛所必需的复杂度削减） |
| **冻结维护** | 现有功能保留 | 只修崩溃、数据丢失、安全和严重兼容问题；**不优化体验、不扩规格** |
| **post-1.0** | 当前不进入发布范围 | 可以记录想法；**不设计、不预埋接口、不建立 PRD、不建实现任务、不给兼容承诺** |
| **legacy** | 仅为旧 trip 可读、可预览、可导出而保留 | **禁止新建内容继续写入**；满足退役条件后删除生成侧，只留读取和再导出 |

「冻结」不是删除，也不是质量可以失控。冻结维护项停止增加平台、卡片比例、AI 模型入口和新的配置维度。

### 1.2 用户面 vs 内部支撑

工程设施（测试、编译器、质量门禁、DPI 隔离）**不与产品功能混判**。每项标 `用户面` 或 `内部支撑`；生命周期仍用上表四类。内部支撑若直接服务 `R0-01` / `R0-04` / 旧 trip 兼容 / 复杂度削减，标 **v1.0**，不得因为「不在 R0-01 那一句里」被误冻。

### 1.3 变更准入

收敛期间，任何新增需求必须关联现有任务编号（如 `LP-03`、`SE-00a`、`EX-03`），并证明属于以下至少一类：

1. 完成 `R0-01` 主闭环
2. 通过 `R0-04` 门槛
3. 保障旧 trip 兼容
4. 减少现有复杂度

否则自动归入 **post-1.0**。未关联收敛任务编号的新增功能不得进入 v1.0。
