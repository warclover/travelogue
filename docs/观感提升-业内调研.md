## 1. 一句话结论

业内几乎都把问题拆成 **「先选 subset（质量×多样性×故事）→ 再定结构（章节/节拍）→ 再填版式（设计师模板 + 硬约束）→ 最后用 pairwise 盲评验收」**。

开源里很少有 Apple 级全栈，但 **选片（DPP/ILP）、模板（YAML/SVG）、布局（justified/constraint pack）、裁判（pairwise aesthetic）** 均有成熟积木。Travelogue 缺的是把它们接到 **trip 级** 并用 **layout 盲评** 闭环，而不是再调 LSE 乘子。

---

## 2. 典范产品的共同架构

```text
原始照片池
    ↓ ① Subset Selection（质量 + 多样性 + 事件/场景覆盖）
代表照片集（通常比用户上传少 30–70%）
    ↓ ② Event / Story Structure（章、高光段、叙事角色）
大纲（opener / build / peak / breath / closer）
    ↓ ③ Page Design（设计师页型 + 硬约束，非规则网格填槽）
成稿 screens
    ↓ ④ Local Refinement（匈牙利、裁切、saliency — 最后、边际最小）
    ↓ ⑤ Judge（pairwise 人评 / 学习到的 ranker，不是 proxy 求和）
发布 / 迭代
```

Travelogue 当前栈把 **④ 当成主战场**，①②③⑤ 偏弱——与 LSE dogfood 结论一致。

## 3. P0 · 感知评估闭环

### 3.1 业内怎么做

| 做法 | 代表 | 要点 |
|------|------|------|
| **Pairwise 优于绝对分** | ICCV 2019 Lee；2026 FGAesthetics | 人评「A 还是 B 更好」比 1–10 分可靠；0.5 共识 = 无差异，应过滤 |
| **Album 级而非单图级** | Google Photos 产品迭代、Apple Memories | 评「这本像不像成品」，不是单张 aesthetic |
| **Learn-to-rank 当代理裁判** | NIMA ranking loss；ICLR 2025 ranking-aware CLIP adapter | pairwise 训练 ranker，**仅预筛 PR**，最终仍要人评门禁 |
| **Layout A/B + 盲评** | Shutterfly/Mixbook 内部 UX（行业惯例，少公开） | 固定相册集 + 双版本 + 胜率阈值 |

### 3.2 开源可参考

| 项目 | 用途 | 链接 |
|------|------|------|
| **idealo/image-quality-assessment** | NIMA aesthetic/technical 预训练，单图排序 | https://github.com/idealo/image-quality-assessment |
| **Google NIMA 博客** | 感知质量与 enhancement 闭环思路 | https://research.google/blog/introducing-nima-neural-image-assessment/ |
| **phase5/6/17 blind review（本仓库）** | 封面 / dogfood 盲评范式 | `scripts/phase5_blind_review.py`、`phase6_cover_blind_review.py`、`phase17_blind_review_score.py` |
| **cover_scoring_calibrate.py** | Pairwise LOO 标定 | 可复刻为 layout pairwise |
| **lse_flags_preview_ablate compare.html** | 并排成稿 UI | 扩展为投票表单 |

### 3.3 成熟产品

- **Apple / Google**：大规模内部 pairwise + 线上隐式反馈（停留、分享、删改）——短期学机制，不学数据规模。
- **Adobe Lightroom「Best Photos」**：聚类后 **组内推荐最佳**——评的是「这组里选哪张」，接近 album curation 粒度。

### 3.4 对 Travelogue 的深度建议

1. **门禁定义成 layout pairwise，不是 golden metrics**——8 本代表 trip × A/B × ≥3 人盲评，胜率 ≥60% 才合并。
2. **两层裁判**：L1 人评（季度复标）→ L2 轻量 ranker（CLIP + pairwise adapter）预筛 PR，**不能替代 L1**。
3. **别用 NIMA 直接当「好看」**——AVA 偏对比度/色彩；旅行照里文档/平淡但重要的片会误判。若用，只作 **组内 tie-break**，且在自有 trip 子集上校准。
4. **MVP（约 2 周）**：扩展 `compare.html` 输出投票 JSON；`phase17_blind_review_score.py` 汇总胜率；**在动 P1 前先跑 baseline 打分板**。

## 4. P1 · 选片升级（最大杠杆）

### 4.1 业内怎么做

| 做法 | 代表 | 机制 |
|------|------|------|
| **组内选代表** | Google [Summarizing a Photo Album](https://www.freepatentsonline.com/y2014/0233811.html) | 先聚类/分组，每组留 1 张 **多属性 quality** |
| **质量×多样性联合优化** | Google [8983193](https://www.freepatentsonline.com/8983193.html) | quality metric + similarity matrix，**全局**最大化 representativeness |
| **DPP（行列式点过程）** | [Kulesza & Taskar 综述](http://www.alexkulesza.com/pubs/dpps_fnt12.pdf) | 相似则互斥，天然 coverage subset |
| **「Best Photos」** | Google Photos、Apple Photos | 去重后 **推荐**，不是只剔 blur |
| **Curated cap** | [memoir](https://github.com/akshan-ish/memoir)「best 60」 | 长 trip 强制上限，逼代表性强 |

### 4.2 开源可参考

| 项目 | 可借鉴点 | 链接 |
|------|----------|------|
| **memoir** | 去重 + blur + **best N** | https://github.com/akshan-ish/memoir |
| **idealo/image-quality-assessment** | 组内 quality 分 | https://github.com/idealo/image-quality-assessment |
| **immich-book** | **先 curation 后 layout**——假设 album 已 curated | https://github.com/ch1bo/immich-book |
| **PhotoStoryAI** | EXIF + 日期/光照分组（轻量 narrative） | https://github.com/giuseppelupo1979/PhotoStoryAI |
| **本仓库 mosaic/diversity.py** | 已有 MMR/DPP，但用于 **pattern**——应 **上移到 asset subset** | `travelogue/curation/mosaic/diversity.py` |

### 4.3 成熟产品

- **Google Photos Auto Album**：事件检测 → best photos → Stories/Album。
- **Apple Photos / Memories**：人脸/场景/地点 → 选片；iOS 18+ **自然语言**再检索 subset。
- **Lightroom Best Photos**：**视觉相似聚类 + 组内推荐**——最接近 P1 MVP 的产品形态。

### 4.4 与 Travelogue 现状差距

```text
photo_cull:  质量门 + 组内最高分 + 配额截断
缺少:        全局 diversity、场景 coverage、story 代表、medoid
highlight:   mosaic ×1.25（排版阶段软 boost）
缺少:        决定「谁进书、谁当章首」
```

### 4.5 深度建议

1. **P1 MVP：Cluster-medoid + Coverage knapsack**（4–6 周）  
   - 在 `run_clustering_layer` 之后插入 `plan_asset_subset()`：每 cluster medoid + 全局 day×主题 coverage。  
   - 进 `plan_screens` 张数 **−30%**，盲评「故事是否更清楚」↑。
2. **Pass 2 升级**：`max(quality × representativeness)`，representativeness = 与同 cluster 平均 embedding 距离。
3. **Highlight 提前到 P1/P3 交界**：`detect_highlight_windows` → 锁定章首 hero，非 mosaic boost。
4. **不要先上大模型逐张选片**——[photoalbum-creator](https://github.com/SebastianBoehler/photoalbum-creator) 用 Gemini 推荐 layout，适合 demo，难盲评；先用 DPP + coverage 规则。

## 5. P2 · 模板 + 硬编辑约束

### 5.1 业内怎么做

| 做法 | 代表 | 要点 |
|------|------|------|
| **设计师页型库** | Shutterfly、Mixbook、Blurb | 页型是 **SKU**；出血、非对称、scale 是设计参数 |
| **Declarative template** | [kore/photobook](https://github.com/kore/photobook) | **YAML 选页型 + Twig SVG** → PDF |
| **Justified row** | [Flickr justified-layout](https://github.com/flickr/justified-layout) | 行高优化 + `fullWidthBreakoutRowCadence` 打破 rhythm |
| **Constraint packing** | [gridwiggle](https://github.com/kclemson/gridwiggle) | 子矩形分解 + hero prominence + **显式 reject** |
| **Commercial SDK** | [IMG.LY CE.SDK Photobook](https://img.ly/showcases/cesdk/photobook-ui/web) | 页型 + 主题 + 用户微调（B2B 参考） |

### 5.2 开源可参考

| 项目 | 映射到 Travelogue | 链接 |
|------|-------------------|------|
| **kore/photobook** | pattern manifest + 声明式页型 | https://github.com/kore/photobook |
| **flickr/justified-layout** | 新增 `screen-justified-row` 类 pattern | https://github.com/flickr/justified-layout |
| **gridwiggle** | 硬约束 + reject reason；学 dev workbench | https://github.com/kclemson/gridwiggle |
| **immich-book + justified-layout-wasm** | 印刷 PDF 流水线末端 | https://github.com/ch1bo/immich-book |

### 5.3 成熟产品

- **Shutterfly/Mixbook**：美学来自 **模板设计师 + 品牌字体/色**，不是匈牙利。
- **Canva**：**单一设计系统**强制一致——对应合并 tone 链 + violating tone → 否决 candidate。
- **Flipboard（历史）**：对开、留白是 **版式规则**，不是 metadata hint。

### 5.4 深度建议

1. **页型 SKU 化（先 3 个，设计师参与）**：非对称 hero、对开 spread、大留白单图；绑定 LTE + CSS token。
2. **hint → hard constraint**：dense ≥3 → 必须 `breath-pause`；禁止 silent fallback 到 unfiltered。
3. **Justified 作为第四种「引擎面」**：竖图 trip（东澳岛）可从 row rhythm 受益，MIT 许可成熟。
4. **学 gridwiggle 评估台**：合成集 + reject reason + batch shuffle，做 pattern 硬约束回归。

## 6. P3 · 结构级编排

### 6.1 业内怎么做

| 做法 | 代表 | 机制 |
|------|------|------|
| **事件分割 + 原型事件** | ACL 2016 [Prototypical Event Structure](https://aclanthology.org/P16-1167.pdf) | **ILP** 同时 segmentation + event ID |
| **Story graph** | [Visual story graphs](https://www.sciencedirect.com/science/article/abs/pii/S092359652030182X) | **Submodular**：coherence + coverage + connectivity |
| **叙事弧** | Apple Intelligence Memories（2024+） | NL → 选片 → **分章 + narrative arc** → 配乐 |
| **时间/光照分组** | PhotoStoryAI | date + golden hour 等轻量 segment |

### 6.2 开源可参考

| 项目 | 借鉴 |
|------|------|
| **PhotoStoryAI** | EXIF + 光照 chapter — **P3 phase 0** |
| **memoir** | 日期/地点 timeline + editorial mode |
| **ACL 2016 / story graph 论文** | paceRole 可用 greedy submodular，不必全 ILP |

### 6.3 成熟产品

- **Apple Memories Movie**：prompt → chapters with themes → narrative arc（[Apple 官方说明](https://www.apple.com/newsroom/2024/06/introducing-apple-intelligence-for-iphone-ipad-and-mac/)）。
- **Google Photos Trip/Stories**：事件级 album → highlight。

### 6.4 深度建议

1. **paceRole 标签**：opener / build / peak / breath / closer → 限制 pattern 池。
2. **Highlight 结构绑定**：top window → 章 **peak** + 强制 hero 开场。
3. **单遍 swap pass**：相邻 3–5 屏 swap，目标 = 盲评 ranker。
4. **长期**：story graph offline 分析，指导模板与 pace 先验（研究向，不阻塞 MVP）。

## 7. P4 · Solver / LSE（槽位填充）

### 7.1 业内怎么做

| 做法 | 代表 | 说明 |
|------|------|------|
| **Greedy + local search** | Flickr justified、多数 web gallery | 足够好，**前提是 input 已 curated** |
| **Constraint packing** | gridwiggle | Hero prominence + 可行域搜索 |
| **Hungarian / assignment** | 学术相册生成 | **仅在固定页型内** 排 slot |
| **Cassowary / ILP** | 杂志排版工具 | 全页约束；成本高，**最后阶段** |

### 7.2 结论

- **[gridwiggle](https://github.com/kclemson/gridwiggle)** 最接近「solver 仍有意义」的开源 demo——input 已 hero 标记 + smart crop。
- **[flickr/justified-layout](https://github.com/flickr/justified-layout)** 无 assignment，纯几何——许多产品 **不靠匈牙利**。
- **本仓库 LSE**：dogfood 证伪为观感主杠杆；冻结产品投入（见 [P17-LSE-处置建议](./P17-LSE-处置建议.md)）。

### 7.3 深度建议

- 仅当 P1–P3 盲评系统性胜出后，考虑匈牙利默认开 + beam 扩宽。
- 若做 solver，优先 **多 partition 策略 + 显式 reject**（gridwiggle 式），而非再加 soft weight。

## 11. 收敛建议

1. **别再找「一个开关/一个 solver」**——业内赢家是 **subset + structure + template + judge** 四段流水线。
2. **最大可复制开源块**：DPP/submodular 选片 + kore 式页型 + Flickr/gridwiggle 布局 + pairwise 盲评；**DPP 已在 mosaic，应上移并加 coverage**。
3. **immich-book 的产品教训**：layout 工具假设 **album 已 curated**；50%+ 工程应放在 curate 之前/之中。
4. **Apple/Google 不可复制部分**：私有 event 模型、十亿级偏好、设计师模板库规模——但 **机制**（组内 best、diversity subset、chapter arc、pairwise eval）均可中等规模实现。
5. **LSE 在业内的等价物**往往是印刷/SDK **最后一公里的 slot fill**——不是 Memories 魔法的主菜；与 dogfood 结论一致，可放心冻结。
