## 3. 分角色要点

### 3.1 架构

- **Atom 放 layout_engine，仅 planner memory**（对齐 `coarse_segments`「不持久化为 sceneId」）。不要写入 trip.json 当 SSOT，避免与 SSG/clustering 双源。
- **统一门**应抽成纯函数 policy（输入：asset_ids + assets_map + AtomPolicy），MCS / legacy / attach **同一调用**；禁止三处复制 if。
- **P0 修法**：不要把整个 `AppConfig` 塞进 `generate_window_candidates`。建议传入解析后的 `ShotGroupMosaicPolicy` / `AtomPolicy` 值对象（从 AppConfig 在 hook/planner 入口解析一次）。冲击小、难再静默失效。
- 配置：`shot_grouping.mosaic.atom` 可暂用，但长期应明确「边界政策属 layout 消费、curation 只产 shotGroup」。
- 遗漏风险：legacy 路径无 rejectFunnel；尾部合并无 telemetry；asset version / golden 可能因屏变碎而红。

### 3.2 算法

- 原文 atom **过严**：sc 强制 + 本册 56% `-1` → 过碎；且 **仍漏 #11**。
- 推荐 W1 判据（80 分）：
  1. **硬**：同 `shotGroupId`
  2. **硬**：相邻 gap ≤ **T_atom**（建议 **900s** 观察，或 600s 起步但配碎度护栏）
  3. **硬**：屏内 takenAt 跨度 **&lt; 2h**（直接灭 #4 类）
  4. **半硬**：`sceneClusterId` 仅当两侧皆非 `-1` 时要求相同；`-1` 不阻断同 sg 时间近邻（保住供给），但 **非 -1 不得与 -1 混**（可救 #3）
  5. **软**：`semanticTag.category` 跳变惩罚 / 观察一轮后再硬（助 #11/#10）
- **禁止**把 burst 当硬边界（维持方案）。
- 指标反作用：仅污染率会逼算法「全出单图」→ 必须加 **拼图屏占比下限（观察或 soft gate）**。

### 3.3 开发

- 触点补漏建议：`legacy.py`、portrait 合并路径、`compose.py`/`search.py` 的漏斗字段、`schemas` 仅在新增持久化 telemetry 时改、既有 `test_shot_group_gate` 必须加 **MosaicConfig 调用链回归**。
- PR 拆分：
  - **PR-W0**：policy 注入 + 漏斗可见 + MosaicConfig 回归测（&lt;1d）
  - **PR-W1a**：atom 门进 MCS + legacy 多槽
  - **PR-W1b**：尾部/carry 同源门 + 跨 2h 硬拒
  - **PR-W2**：系列切页（独立）
- 可回滚：全部挂 `atom.enabled`。

### 3.4 产品

- 「宁碎勿脏」**接受**，但用户怕的是「整本像废片单张墙」。
- 建议用户面指标（替代纯比率）：
  - **脏屏数 / 册**（目标 0～1）
  - **灾难屏数 / 册**（目标 0）
  - **多槽屏占比**（观察，W1 后相对基线降幅不超过约定阈值，如 30%）
  - 11 例：**污染类必须修；合并类不做 Go**
- 本期**不强制**做换图交互；W1 稳定后再考虑。
- W1 期间建议 **暂停三列等分实验 SKU 默认曝光**，避免归因混乱（与排版一致）。

### 3.5 拼图排版

- 同叙事原子第一性 **正确**；刻意对比跨页本产品现阶段可放弃（80 分产品）。
- 稀缺模板 `span≤300s` 过严 → 几乎不出。建议改为：**同 atom + 契约朝向匹配 + 质量门槛**，span 用 600–900s soft，而非 300s hard。
- 系列切页：保持时间序、避免同构图复读（近景克隆门继续）；同系列多屏用朝向变化换节奏。
- 收尾硬拼：允许同 atom 内 2 槽；跨 atom 只出单图 + breath，不要硬三拼。
- 视觉维度进聚类的性价比：① 时间跨度 ② 场景簇（非 -1）③ 类别跳变；裁切/人脸完整留在槽位层，不进 atom。

## 4. 对方案 §9 五题的合议投票

| # | 问题 | 合议 | 理由 |
|---|------|------|------|
| 1 | atom 是否强制同 sceneClusterId | **否（改半硬）** | 本册 -1 占 56%；强制过碎。改为「两侧皆有效 id 才要求相同；-1 不与非 -1 混」 |
| 2 | 类别跳变硬/软 | **W1 软，观察后升硬** | 助 #11，但硬切会把 atoms 打到 90、单张 54 |
| 3 | T_atom | **600s 起步，准备调到 900s** | p75=406、p90=1499；600 切在肩部。用碎度护栏校准 |
| 4 | #8/#10 合并是否进 W1 Go | **不进** | 符合 80 分；合并属 W2 加分 |
| 5 | W1 是否暂关三列等分实验 | **是** | 边界与模板同时变无法归因；dogfood 先验边界 |

## 5. 必须修改后再开工 W1 的条款（条件清单）

1. **P0 先合**：policy 值对象注入 + `rejectFunnel` 可见 `shot_group_cross` + MosaicConfig 调用链单测。
2. **改写 §3 P1 atom 定义**为上文「半硬 sc + 2h 跨度硬拒 + 类别软」；明确 **#11 为本期已知残差**（无 look 信号前接受，或用类别软惩罚降权）。
3. **统一门覆盖三条路径**（MCS / legacy / attach），禁止只修 MCS。
4. 验收增加 **多槽屏占比 / 脏屏绝对数**；污染率单独不够。
5. 稀缺模板准入去掉「300s hard」；W1 暂关实验 SKU 默认曝光。

满足以上 → **批准进入实现**。  
不改 atom 定义直接按原文做 W1 → **打回**。
