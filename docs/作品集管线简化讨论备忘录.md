## 1. 触发：作品集过河导微信长图不对

### 产品原话（大意）

原来的微信长图，设置里选了按章，实际仍是一整张；应有的拼图失效，变成单张连续。猜测是失去了游记管线。导出模式物理隔离了，但游记也要生成、作品集也要生成；当前只完成一种生成，却要面对两种导出，匹配总会失效。六种游记模式都要先有游记预览；作品集模式要先有作品集预览。现流程不会同时生成两套预览页。

### 核实

现象属实。根因比「FXI 把游记弄丢了」更具体：

作品集 × 微信群走的是 PFM **ISO-04** 专路 `export_portfolio_wechat_from_kept`：kept 池最多 24 张，Pillow 竖叠，`segmented=False` 写死，**不传** `segment_mode`，拼图资产还被 `is_collage_asset` 剔除。作品集预览不写 `index-longshot.html`，游记 Writer 要的 `section.chapter` 根本不存在。

这是故意的：禁止把 `page-*` 压进竖条（D-PFM-10 / ISO-04）。过河面板却复用了游记点法（按章 / 密度 / 要不要字），所以控件是假的。

六种不是同一类依赖：

| 过河模式 | 实际吃什么 | 要不要游记预览 |
|----------|------------|----------------|
| 微信群 | kept 竖叠，忽略按章 | 要才像游记长图；现在没有 |
| 朋友圈 | 拍 HTML 再切片 | 要游记卷轴 |
| 小红书 / 公众号 / 单张海报 / 印刷跨页 | kept + ECC | **不要**预览 HTML |

W3 华农小红书能出 5 张，是因为走了 ECC，不是因为生成了游记。

对照游记 `demo-65db8fd377`：同一套控件走 `export_journal_longshot`，拍 `index-longshot.html`，按章、拼图都在。

### 当时三条产品叉（未拍板）

1. **收口承诺**：过河微信不再假装是游记长图；藏按章 / 密度。
2. **去那本游记**：同夹已有游记就打开那本再导；没有则走「改做成游记」（改身份，不是 F2）。
3. **过河 sidecar**：当场用 kept 排一份不进书架的游记 HTML，再走游记 Writer。贵，等于新开一列。

不建议：在作品集 `index.html` 上直接跑游记长图 Writer（会 flatten `page-*`，ISO-04 红）。

## 2. 假设：导入就双管线、不再选身份

### 产品原话（大意）

若另做 sidecar，能否在指定文件夹后不再选游记 / 作品集，默认双管线，同时生成两套预览并独立保存；再按用户选的预览或导出模式，决定调用哪套预览。

### 结论

更合理的是 **「两本独立在、导出绑对那一本」**。  
不太合理的是 **「导入不再选身份，一个项目里两套预览，靠导出模式来切。」**

PIS 已签：游记和作品集是两本，同夹可以同时留，各有 `tripId`，覆盖只发生在同一身份。华农就是两本，不是一本的两张皮。

「不问身份、一个项目切面」会把三件已拆开的事捆回去：

1. 我现在拿着哪一本（预览、精修、票根、主 CTA）
2. 我这次要出门的是什么（页图 / 长图 / 小红书）
3. 磁盘上有没有对面那份 HTML

FXI 刚把 1 和 2 拆开。再用导出模式切预览，等于在 Studio 里重做「两种书并排」（SHD-PFM-06）。

其它阻力：第一眼仍要有身份；两本精修后立刻分叉（同步或过期都难）；双开是沉默税；一个 trip 两套 `index.html` 会穿 DPI。

### 三条路

| 路 | 含义 | 态度 |
|----|------|------|
| **A. 同夹双本自动化** | 两个 trip、两张票根；预览 = 打开那一本；过河微信调那本游记 | 把已签 PIS 往前推；导入问「做一本还是两本 / 先看哪本」 |
| **B. 过河 sidecar** | 只在吃卷轴的模式当场排、不进书架 | 修微信长图，不必改进口；给不了「精修过的那本游记」 |
| **C. 一个项目两套预览、mode 当路由器** | 同一屏两套精修、两个主钮 | **不建议** |

身份仍表示 **拿着哪一本**；导出表示 **这本怎么出门**。对面 HTML 用另一本 trip 或一次性 sidecar，不要做进同一本的第二张皮。

当时收口句（未拍）：过河微信是绑 **书架上那本游记**，还是绑 **当场 sidecar**。等待、新鲜度、精修预期完全不同。

## 3. 假设：统一作品集与游记的模板和管线

### 产品原话（大意）

若统一模板和管线，多种导出模式就能共享一条管线，问题会变简单。

### 结论

共享一条管线，**导出分发会变简单**——因为先把「两本」收成「一本的两种相机」。问题挪到匹配和产品形态上，没有消失。

游记是卷轴（`screen-*`、分章、拼图）；作品集是可翻的一本（`page-*`、16:9、三星、厚度档）。ISO-04 禁止把密页压成竖条。三种落法都不是免费的：

1. **以游记为真源**：作品集变成卷轴的分页投影 → 16:9 编辑性退回。
2. **以作品集为真源**：微信变成页的竖叠 → 按章 / 拼图失效变成唯一合法结果。
3. **更抽象的单元序列再投影**：这是第三条管线，短期更难。

「导入双开」是保留两本找绑定；「统一管线」是取消两本让绑定自动成立。两句不能一起真。

已共享、该继续共享：ingest、cull、封面、Studio 壳、kept。  
不该共享：`screen-*` / `page-*`、两套 CSS、`compose_trip` / `compose_portfolio_trip`。

产品若仍要两本：简单的是分发变老实，缺哪份就去做那本或 sidecar。  
若接受只做一种书：才配开「一条管线、多种导出」。那是重签主产品。

## 4. 作品集能否走与小红书一样的 ECC

### 第一轮（被理解成「整本改成 3:4 卡册」）

过河出小红书，作品集 **已经在走 ECC**。D-PFM-10：换种分享用 kept + ECC，禁止把 `page-*` 写入 ECC 模板库。ECC 画布是 3:4；作品集主路径是 16:9 `page-*`。

整本预览也改成和小红书一条管线 = 作品集变成能翻的卡册，要重签 PFM / PIS / 工坊星表。微信按章仍然不是 ECC（无章、不读 mosaic 拼图，BLK-ECC-05 已退役按章装箱）。

中间态「给 16:9 做一套像 ECC 的 Writer」是 folio 卡管线，**不能**共用 `card-aspect-3x4`。

### 产品澄清

小红书导出可以不依赖游记预览页。为什么作品集非要先生成预览页？能否模仿小红书，也不用预览页。

### 结论（对准这句）

可以模仿 **「不依赖预览页去出图」**。不能模仿成 **「连编排都不做」**。

小红书的真源是 kept + 张数，当场画 3:4；导出物就是渲染物。Studio 里没有「先翻完这 5 张卡再导」的一本小红书。

作品集今天把三件事叠在同一份 HTML 上：

1. **编排**（哪一页、哪张脸、哪些照片）→ `screens[]` / `page-*`
2. **给人看、给人精修** → 浏览器预览
3. **页图** = 拍这份预览；**这一本** = 把这份预览打包

所以看起来「不生成预览页就导不了」。

| 产物 | 能否学小红书「不出预览 HTML」 |
|------|------------------------------|
| **页图** | **可以，也值得。** 页序在 `trip.json` 里即可 Pillow 画 16:9，不必 `index.html`、不必 Playwright。预览变成投影，不是页图真源。 |
| **这一本**（仍是可点开翻的网页） | **不行。** zip 就是预览页。要去掉 HTML，就得改 PDF / 纯图翻页，或导出时再现场拼网页。 |
| **精修换脸、改厚度** | 不适合只在导出瞬间算一次。没有视觉面，人看不见。 |

更干净的拆法：

- 真源 = **页序**
- 预览 HTML = 可选投影
- 页图 PNG = 另一条投影（Pillow，学 ECC 的「出图不经过预览 DOM」）
- 这一本 = 仍要一种可翻载体（今天是 HTML）

导入仍然要跑匹配、写页序。想少等：可以先出页序 + 页图，HTML 后台再做，或精修时才做。

**作品集非要先生成的是页序，不是预览 HTML。** 小红书证明了「出图可以不经过预览页」，没证明「可以没有编排」。

## 5. 贯穿几轮的对照

| 想法 | 站得住的部分 | 站不住的部分 |
|------|--------------|--------------|
| 过河微信要游记卷轴 | 按章 / 拼图确实吃 `index-longshot.html` | 不是六种都要；小红书已经不吃 |
| 一种生成、两种导出会失效 | 对 **依赖 HTML 的长图** 成立 | 对 ECC 不成立 |
| 导入默认双开 | 两本独立保存、按书调用 | 取消选书、按导出模式冒充选书 |
| 统一模板和管线 | 分发变短 | 先删掉一种书 |
| 作品集学 ECC | **页图不拍预览** | 预览 / 这一本 / 微信按章不能整包并进 3:4 |

## 6. 若继续，值得先拍的一句

过河微信是：

- 绑 **书架上那本游记**，还是
- 绑 **当场 sidecar**（不进书架），还是
- **降级叠图**（收口承诺，不再假装按章）

这三句的等待、新鲜度、精修预期不同。没拍板前不改 `dispatch.py`。

页图若要学小红书，单独一列：**页序真源 + Pillow 出 PNG，预览 HTML 降为投影。** 不与统一管线、不与取消身份选择捆在一起。
