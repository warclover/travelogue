## 0. 文档说明

### 0.1 定位：这是一份「回归修复 + 层级重构」的增量 PRD

本稿**不改变** v2 冻结的核心范式（输出优先 Bento、双交付预览、Import Sheet、恒常首页 + 书架、D-14 预览选择器）。本稿解决的是 v2 落地后暴露的两类问题：

1. **回归类（Regression）**：实现偏离了 v2 PRD 已冻结的决策——主 CTA 文案与层级（§3.6）、信任话术可见性（§3.5）、Lead 价值主张可见性（§3.1）。这些按 **P0** 修复。
2. **增量类（New Decision）**：v2 PRD 未覆盖、或落地后新暴露的体验问题——工作台信息过载、内部术语外露、规格式微文案。这些以新决策 **D-15 ～ D-19** 冻结。

### 0.2 问题总览与优先级

| 优先级 | 编号 | 问题 | 性质 |
|--------|------|------|------|
| **P0** | HP21-01 | 主 CTA 退化为「新建」小卡片，视觉权重低于相邻缩略图 | 回归（违反 v2 §3.6 / G-HP2-02） |
| **P0** | HP21-02 | Lead 价值主张与信任话术在首屏不可见 | 回归（违反 v2 §3.1 / §3.5 / G-HP2-01） |
| **P1** | HP21-03 | 工作台（bench）8 类控件并列，任务项与设置项混排，「分析」标签歧义 | 新决策 D-15 |
| **P1** | HP21-04 | 通往画册的路径冗余：缩略图 / 预览选择器 / 继续上次 / 查看最近 四选一 | 新决策 D-16 |
| **P1** | HP21-05 | 「算法待更新」内部术语以告警色角标外露于首屏 | 新决策 D-17 |
| **P2** | HP21-06 | 微文案为交互规格（「横滑·一屏一页·到头停止」等），非用户语言 | 新决策 D-18 |

### 0.3 设计决策摘要（v2.1 新增，编号续 v2）

| # | 决策 | 说明 |
|---|------|------|
| **D-15** | **Bench 三分法** | 工作台只保留三件事：**开始制作（主 CTA）· 继续上次（次 CTA）· 最近画册**；配色 / 高级选项 / Dev 收入右上角「设置」入口；见 §4 |
| **D-16** | **删除「查看最近」按钮** | 书架恒常存在于 Bento 下方（v2 D-08），滚动即达，无需独立按钮；预览选择器保留（D-14 不变） |

## 1. 背景与问题证据

### 1.1 现状截图观察（2026-07-02 · sky 主题 · IdleReturning）

- 首屏视觉焦点被两个预览容器（16:9 carousel + 9:16 手机框）平分；文案区仅剩手写体 H1「每一个瞬间，都值得再次相遇」，**Lead 与信任话术未见**。
- 底部 bench 从左至右并列：新建（小卡）· 3 张最近缩略图（带橙色「算法待更新」角标）· 预览画册 Combobox · 继续上次 · 查看最近 · 配色下拉 · 高级选项 · Dev 按钮。
- Carousel 当前帧为暗调照片，左右箭头与 dots 对比度不足；hint 文案「← 横滑 · 一屏一页 · 到头停止 · 共 5 张 →」。

### 1.2 代码现状定位（工程输入）

| 问题 | 现状代码位置 |
|------|--------------|
| HP21-01 主 CTA | `templates/studio/studio-home-v2.html` L111-115：`#v2-cta` 为 `.v2-bench__create-card`，label「新建」，与 recent 卡同尺寸同容器 |
| HP21-02 Lead/信任 | 同文件 L60-62：Lead 存在于 DOM（`.v2-bento__lead--script`）但当前布局下不可见/弱化；bench meta 信任话术（v2 §3.5）已不存在于 bench DOM |
| HP21-03 bench 过载 | 同文件 L98-222：`.v2-bench__quick` 内 4 个 `v2-bench__side` 分组（预览画册 / 快捷操作 / 配色 / 分析） |
| HP21-05 stale 角标 | `homepage-v2/bento.js` L217/L234、`homepage-v2/shelf.js` L83/L149、`homepage-v2/bento-preview-picker-logic.js` L21：字面量「算法待更新」 |
| HP21-06 规格微文案 | `homepage-v2/carousel.js` L146、`studio-home-v2.html` L92 / L251、`homepage-v2/phone-strip.js` L279-280 |

### 1.3 与北极星漏斗的关系

v2 漏斗：`homepage_view → cta_click → sheet_open → folder_picked → import_start → import_success`。

本稿假设（H1）：**主 CTA 层级不足与价值主张缺失是 `cta_click` 转化的首要抑制因子**。P0 两项直接作用于漏斗第一跳；P1 通过降低首屏决策成本间接作用；P2 作用于第一印象与信任。

## 2. 目标与指标

### 2.1 目标

| ID | 目标 | 定性验收 | 代理指标（对比 v2.0.6 基线） |
|----|------|----------|------------------------------|
| **G-HP21-01** | 首访 10s 内找到并理解主 CTA | 5/5 被试指出「开始制作我的游记」 | `cta_click` / 空态 PV **提升 ≥20%（相对）** |
| **G-HP21-02** | 首访 10s 内能复述"这个产品做什么" | 5/5 复述「照片→自动生成画册/长图」 | 30s 内 `sheet_open` 或 `lightbox_open` ≥45% |
| **G-HP21-03** | 首屏信任话术可见 | 「照片留在本机 · 无需注册」出现在首屏视口内 | 自动化 DOM 可见性检查 |
| **G-HP21-04** | 回访 5s 内继续作品 | 「继续上次」为 bench 次焦点 | `bench_resume_click` / 回访 PV 不下降 |
| **G-HP21-05** | 首屏无内部术语 | 术语走查：0 处「算法待更新」「到头停止」等 | 字面量扫描（CI grep） |

### 2.2 非目标（v2.1 明确不做）

- 不做首页范式重构（沉浸式滚动叙事、杂志封面化首页 → 归入 v3 探索，另立文档）
- 不动 Import Sheet 内部流程、Lightbox、书架布局（M14）
- 不动 D-14 预览选择器交互与数据契约
- 不改后端 API / manifest schema
- 不做配色主题的增删（仅移动其入口位置）

## 3. P0 需求：CTA 层级与价值主张

### 3.1 主 CTA 恢复（HP21-01）

#### 需求

| 项 | 规格 |
|----|------|
| 文案 | **开始制作我的游记 →**（恢复 v2 §3.6 冻结文案；禁止「新建」「+」作为唯一 label） |
| 形态 | bench 左栏首位**独立主按钮**：实底强调色（`--gold` 系）、高度 ≥56px、宽度 ≥200px；与 recent 缩略图卡**不同容器、不同视觉等级** |
| 行为 | 打开 Import Sheet（不变）；焦点归还规则沿用 v2 §7.1 |
| 层级校验 | 主 CTA 应为 bench 区域内**面积 × 对比度**最高的元素（设计走查项） |

#### 现状 → 目标

```
现状：[新建(小卡)] [缩略图A] [缩略图B] [缩略图C] | 预览画册… 继续上次 查看最近 配色 分析
目标：[ 开始制作我的游记 → ]  [缩略图A] [缩略图B] [缩略图C] | 预览画册… [继续上次] ⚙
```

### 3.2 首屏价值主张与信任话术（HP21-02）

#### 需求

| 位置 | 文案（冻结） | 说明 |
|------|--------------|------|
| H1 | 每一个瞬间，都值得再次相遇 | 保留手写体情绪句，不动 |
| Lead（H1 下，必须首屏可见） | 选一次旅行的照片，**自动分章 · 配文 · 排版**，生成大屏卷轴 + 微信长图。 | 恢复 v2 §3.1；字号 ≥15px，正文字体（非手写体），对比度 AA |
| 信任行（Lead 下或主 CTA 旁） | **照片留在本机 · 无需注册** | 恢复 v2 §3.5；带锁形/本机图标可选 |

#### 约束

- Lead 与信任行在 **≥1024px 与 iPad 横屏** 两档视口的首屏视口内可见（不依赖滚动）。
- 遵守 D-09：产品 chrome 内用「自动」，禁止「AI 自动生成」。Eyebrow 中「智能游记画册」属营销层命名，本期**保留**，但新增文案一律用「自动」。

### 3.3 空态 CTA 上移（D-19 · HP21 新增）

| 状态 | 主 CTA 位置 |
|------|-------------|
| **IdleEmpty**（无用户画册） | 文案区 Lead 下方（首屏黄金位）；bench 左栏不再重复放主 CTA，仅保留示例信息 |
| **IdleReturning**（有用户画册） | bench 左栏首位（§3.1）；文案区不放 CTA，避免与「继续上次」抢焦点 |

**Rationale**：空态用户唯一有意义的动作就是开始制作，应放在视线主路径上；回访用户的首要动作是"继续"，CTA 留在工作台与最近画册同一语境。

## 4. P1 需求：工作台三分法（D-15 / D-16）

### 4.1 目标结构

bench 收敛为**三件事 + 一个设置入口**：

```
┌────────────────────────────────────────────────────────────────┐
│ [ 开始制作我的游记 → ]   [最近A] [最近B] [最近C]                  │
│                                        预览画册 [Combobox ▾]     │
│                                        [ 继续上次 ]        [⚙]  │
└────────────────────────────────────────────────────────────────┘
```

| 保留项 | 说明 |
|--------|------|
| 主 CTA | §3.1 |
| 最近画册缩略图（≤3） | 行为不变（导航 + `is-previewing` 描边） |
| 预览画册 Combobox | D-14 全部规格不变（位置可随布局微调，控件 ID 不变） |
| 继续上次 | 升为**次 CTA**（描边按钮，视觉权重仅次于主 CTA） |

| 移除/迁移项 | 去向 |
|-------------|------|
| **查看最近** 按钮 | **删除**（D-16）。书架恒常在下方；若无书架，原 toast 场景不再存在 |
| **配色** 下拉 | 迁入右上角 **设置（⚙）Popover** |
| **高级选项**（含「分析」标签） | 迁入设置 Popover 的「导入选项」分节；Import Sheet 内保留既有入口（若有）不受影响 |
| **Dev 按钮** | 迁入设置 Popover 底部（仍仅 loopback / `?dev=1` 可见，沿用 AC-HP2-23 门控） |

### 4.2 设置入口规格

| 项 | 规格 |
|----|------|
| 位置 | 首屏右上角固定图标按钮（⚙），44×44px 触控热区 |
| 形态 | Popover（`role="dialog"`，Esc 关闭，焦点 trap 与归还，同 v2 §7.1 标准） |
| 分节 | ① 外观（配色下拉，逻辑复用 `theme.js`）② 导入选项（原 `#v2-advanced-popover` 四项整体迁入，控件 ID 不变）③ 开发者（Dev Panel 入口，门控不变） |
| 持久化 | 配色 / 高级选项的 localStorage 键**全部不变**（仅 DOM 挂载点迁移） |

### 4.3 迁移约束（工程护栏）

- `#v2-theme-select`、`#studio-cfg-*` 等控件 ID 与事件绑定**保持不变**，只移动 DOM 位置，避免破坏 `theme.js` / `advanced-options.js` / 既有测试。
- `#v2-bench-recent-btn`（查看最近）删除时同步清理 `bento.js` 中的绑定与相关测试断言。
- Dev Panel 注入点从 bench 改为设置 Popover，`dev-panel.js` 的显隐门控逻辑不变。

## 5. P1 需求：stale 状态用户语言化（D-17 · HP21-05）

### 5.1 分层展示策略

| 层 | 展示 | 文案 |
|----|------|------|
| **bench 最近缩略图**（首屏） | 中性小徽标（灰蓝底，非告警橙） | **可更新** |
| **书架卡片** | 徽标 + 次行说明 | 可更新 · 重新排版可获得新版式 |
| **Bento stale bar**（选中该画册预览时） | 保留现状机制，文案调整 | 这本画册可以用新版式重新排版 → [重新排版] |
| **预览选择器选项**（`bento-preview-picker-logic.js`） | 徽标 | 可更新 |

### 5.2 约束

- 「算法」「待更新」等实现视角词汇**禁止**出现在首页任何用户可见文案（G-HP21-05 · CI 字面量扫描）。
- `algorithmStale` / `longshotStale` 数据字段与判定逻辑不变，仅改展示层字面量（涉及 `bento.js`、`shelf.js`、`bento-preview-picker-logic.js` 三处）。
- 「长图待更新」同步改为「长图可更新」。

## 6. P2 需求：微文案与预览质感

### 6.1 微文案内容化（D-18 · HP21-06）

| 位置 | 现状 | 目标 |
|------|------|------|
| Carousel hint（`carousel.js` L146） | ← 横滑 · 一屏一页 · 到头停止 · 共 5 张 → | **{画册名} · 第 {n} / {N} 页**（随翻页更新；示例作品前缀「示例 · 」） |
| Carousel hint 初始（HTML L92） | ← 横滑 · 一屏一页 · 到头停止 → | 同上格式的初始态（第 1 / N 页） |
| 手机框 caption（HTML L251) | ←→ 切换 · 一屏一章 | **微信里收到的样子**（hint 仅保留「共 {N} 章」） |
| 手机框 aria（`phone-strip.js` L279-280） | 微信长图 · N 段 · 左右切换章节 · 章内可上下滚动 | **保留**（aria 面向读屏，允许操作性描述） |

**原则**：可见文案答"这是什么内容"；操作方式由箭头、dots、手势与 aria-label 承担。「到头停止」「clamp」类实现语言仅存在于 PRD 与代码注释。

### 6.2 预览来源标注补全（HP21-07 · 补强 D-06）

| 场景 | 标注 |
|------|------|
| 预览 = 示例作品 | demo-flag「示例作品」——carousel footer 与手机框 caption **两处均显示**（AC-HP2-02 复核） |
| 预览 = 用户画册 | carousel footer 显示来源徽标：**我的画册 · {画册名}**（替代 demo-flag 位置，样式区分） |

**Rationale**：D-14 允许任意画册上台后，"台上这本是谁的"必须始终可辨；现状仅在 demo 时有标注，用户画册时信息缺位（截图中「斯里兰卡风光精选」即无任何来源标识）。

### 6.3 Carousel 控件对比度与首帧（HP21-08）

| 项 | 规格 |
|----|------|
| 箭头 / dots | 半透明深色底衬（scrim）+ 白色图形，任意底图上对比度 ≥3:1（WCAG 非文本对比）；复核 AC-HP2-20 |
| 示例首帧 | demo manifest `pages[0]`（封面）素材要求：明亮、主体清晰、可承载文字叠加 → 更新 [DEMO-ASSETS-BRIEF](./studio-homepage-v2/DEMO-ASSETS-BRIEF.md) 验收项 |
| 用户画册首帧 | 不做算法挑图（非本期范围）；靠 scrim 保证控件可见性即可 |
