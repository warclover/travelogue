## 0. 一句话总纲

> **Travelogue —— 旅行照片，一次生成一本可以发群的杂志。**
>
> 网站只做三件事：**5 秒让访客看懂价值 → 用真实作品建立信任 → 让访客进小程序做出第一张长图。**

网站不处理照片、不上传、不注册。它是产品的 **门面**，不是产品的 **入口**——入口在微信里（**手机微信与电脑微信皆可**）。

> **双端原则**：网站必须同时服务 **电脑端访客**（大屏浏览、照片多在电脑里、倾向在电脑微信内用小程序）与 **手机端访客**（碎片浏览、照片在相册、扫码即用）。二者的浏览设备、进入方式、心智略有不同，网站需 **按设备自适应引导**，而非默认「都去扫码」。

## 1. 为什么需要这个网站

### 1.1 小程序的先天短板，正是网站的使命

| 小程序的短板 | 网站如何补 |
|--------------|------------|
| 几乎无法被搜索引擎发现 | 承接 SEO / 外链 / 社区引用 |
| 屏幕小，讲不完整故事 | 用大屏样例与滚动叙事讲透价值 |
| 分享出去只有一个码，缺乏说服力 | 提供「可被转发的一个链接」，替代冷冰冰的小程序码 |
| 信任成本高（要上传照片） | 用隐私专页 + 真实作品把顾虑讲清楚 |
| 无沉淀，用户走了就走了 | 作品墙 / 案例库形成长期资产 |

### 1.2 目标（90 天可衡量）

| ID | 目标 | 衡量 |
|----|------|------|
| **G-W-01** | 访客首屏 5 秒内理解「照片→杂志长图」 | 首屏停留 P50 ≥ 8s；跳出 < 60% |
| **G-W-02** | 扫码转化：访客 → 打开小程序 | 扫码/跳转事件 ≥ 访客 8% |
| **G-W-03** | 深度转化：访客 → 小程序内完成长图 | 归因完成 ≥ 访客 3% |
| **G-W-04** | 信任达成：访客理解「云端处理 + 可删原图」 | 隐私页到访率 ≥ 15%；无信任类差评集中 |
| **G-W-05** | 作品资产：真实授权样例上墙 | ≥ 12 篇真实 trip 长图 |

> 与整体「1 万完成用户」目标衔接：网站是漏斗最上层，主要对 G-W-02/03 负责。

### 1.3 非目标

- ❌ 网站内在线上传照片 / 在线生成（一律引导进小程序）
- ❌ 账号体系、Web 端登录
- ❌ 电商、卖课、卖预设、Affiliate
- ❌ 首版多语言（仅简体中文）
- ❌ 重型 CMS / 博客系统（静态站足够）
- ❌ 夸大式「AI 一键生成大片」话术

## 2. 目标访客与心智

### 2.1 三类访客

| Persona | 占比 | 从哪来 | 心里第一个问题 | 决策时长 |
|---------|------|--------|----------------|----------|
| **V-A · 旅行后想发群的人**（主力） | 60% | 微信群/朋友圈看到别人的长图 | 「这长图怎么做的？我也能做吗？麻烦吗？」 | 30 秒 |
| **V-B · 爱记录的旅行者/摄影爱好者** | 25% | 小红书/即刻/社区 | 「排版好不好看？我的照片会被上传到哪？会删吗？」 | 2 分钟 |
| **V-C · 自媒体/博主** | 15% | 同行推荐 | 「能不能带我的信息？粉丝能一键保存吗？」 | 1 分钟 |

### 2.2 电脑端 vs 手机端访客差异（关键）

同一个人可能在两种设备到访，但 **场景、照片位置、进入方式** 不同。网站需按设备自适应。

| 维度 | 电脑端访客 | 手机端访客 |
|------|-----------|-----------|
| **典型场景** | 认真整理一次旅行、大屏挑图与看排版 | 碎片时间被长图种草、想立刻试 |
| **照片在哪** | 多在 **电脑硬盘**（相机/手机已导入） | 在 **手机相册** |
| **浏览耐心** | 高，愿意读完整叙事、看作品墙 | 低，几屏内要击中 |
| **进入小程序方式** | ①手机扫码在手机用 ②**在电脑微信内打开小程序**（大屏挑图更顺手） | 微信内一键跳转 / 长按识别 / 复制口令 |
| **决策深度** | 更在意排版质量、隐私、能否长期用 | 更在意「快、好看、能发群」 |
| **CTA 最优形态** | 小程序码 + 「在电脑微信里打开」引导 | 直接跳转小程序 |

**产品判断**：
- **电脑端是「深度转化」的沃土**——照片就在电脑里、大屏看排版体验最好，适合完成一本用心的杂志；网站在电脑端要 **讲透价值 + 明确「电脑也能用」**。
- **手机端是「即时转化」的入口**——被种草后要 **最短路径** 进小程序，别让用户找。
- 网站 **不假设** 访客一定用手机；「扫码」不是唯一动作。

> **重要澄清**：网站按钮无法在电脑上「一键唤起」电脑微信小程序（不同于手机微信内跳转）。电脑端访客进入小程序有两条现实路径：**(a) 手机扫码 → 在手机用**；**(b) 打开电脑版微信 → 顶部/侧栏「小程序」搜索「Travelogue」→ 在电脑用**。网站需把 (b) 讲清楚（配图指引），因为「照片在电脑里」的用户最需要它。具体唤起能力（URL Scheme / URL Link 在 PC 的表现）见 §14 OQ-W-07。

### 2.3 「黄金 5 秒」必须传达

1. **这是什么**：旅行照片 → 一本可发群的杂志长图
2. **凭什么信**：一张真实、够好看的长图就在眼前
3. **怎么开始**：手机扫码，或在电脑微信里打开——**电脑手机都能用**

### 2.4 三条信任红线（访客顾虑，必须正面回答）

| 顾虑 | 网站的回答（诚实，不回避） |
|------|----------------------------|
| 「照片传到哪？」 | 加密上传云端处理，**默认 7 天删除原图**，可主动删除 |
| 「要花钱吗？」 | 首篇免费；清楚标注收费边界（P2 后） |
| 「会不会很难？」 | 选图 → 等一会儿 → 保存长图，三步 |
| 「电脑能用吗？」 | 能，**电脑微信里就能用**；照片在电脑里更方便 |

> **不回避「云端」**：与桌面 Studio 的「本地」叙事分区表达（见 §6）。诚实是这个品类最强的营销。

## 3. 品牌与创意方向

### 3.1 核心隐喻：「杂志编辑部，只不过编辑是算法」

不主打「AI」，主打 **「像请了一位懂排版的编辑」**。语气克制、审美优先、结果导向。

### 3.2 三个可延展的创意主题（供设计选择）

| 主题代号 | 概念 | 视觉语言 | 适合 |
|----------|------|----------|------|
| **T1 · 印刷体（推荐）** | 「把相册装订成刊」 | 大留白、衬线标题、纸张质感、页码、装订线 | 摄影/审美人群 |
| **T2 · 旅途卷轴** | 「一次旅行，一条时间线」 | 横向滚动、地图点位、章节分隔 | 强调故事感 |
| **T3 · 群聊现场** | 「发到群里那一刻」 | 微信气泡、长图在对话里被点开 | 强调即时价值 |

建议 **T1 为主视觉 + 首屏用 T3 的场景截图作为社会证明**，兼顾审美与「有用」。

### 3.3 文案基调

- **动词优先**：「导进来 · 排好版 · 发出去」
- **结果可视**：永远配真实长图，不用 icon 占位
- **不承诺魔法**：避免「10 秒出大片」；用「几分钟，一本杂志」
- **尊重照片**：强调「策展、排版、配文」，不用「美颜/滤镜/修图」

## 4. 信息架构与页面清单

### 4.1 站点地图

```
/                    首页（承载 90% 转化）
/gallery             作品墙（真实长图案例）
/how-it-works        它是怎么工作的（3 步 + 长图剖析）
/privacy             隐私与数据（信任专页）
/pricing             价格（P2 上线；P1 显示「首篇免费」）
/faq                 常见问题
/studio              桌面工坊入口（次要，给重度用户）
/about               关于与联系
```

首版必做：`/`、`/gallery`、`/privacy`、`/faq`。其余可迭代。

### 4.2 全局元素

| 元素 | 内容 |
|------|------|
| 顶栏 | Logo · 作品墙 · 怎么工作 · 隐私 · **主 CTA「微信体验」** |
| 主 CTA（自适应） | **电脑端**：点击弹出面板 = 小程序码（扫码用手机）+「在电脑微信里打开」图文指引；**手机微信内**：直接跳转小程序；**手机非微信**：长按识别码 / 复制口令 |
| 页脚 | 备案号 · 隐私政策 · 用户协议 · 联系方式 · Studio 入口 |
| 悬浮 CTA | 滚动 >1 屏后出现；文案随设备变（电脑「电脑/手机都能开始」，手机「立即体验」） |

> 主 CTA 的核心原则：**永远给出「当前设备最省事的那一条路」**，把「另一条路」作为次选，而不是把同一个「扫码」丢给所有人。

## 5. 首页逐屏规格（核心）

> 首页是整个网站的成败所在。以下为自上而下的 **屏（section）** 规格。

### 屏 1 · Hero「一眼看懂 + 一眼想要」

| 项 | 规格 |
|----|------|
| 背景 | 一张 **真实旅行长图**（竖版，缓慢视差滚动或轻微 parallax） |
| 主标题 | **「旅行照片，排版成一本能发群的杂志」** |
| 副标题 | 选好照片，剩下的交给它：自动分章、配文、排版，生成竖版长图 |
| 主 CTA（**电脑端**） | **「在微信里开始」** → 弹出面板：小程序码（扫码用手机）+「电脑微信也能用 →」指引 |
| 主 CTA（**手机端**） | **「微信一键开始，做第一本」**（微信内直接跳转；非微信长按识别） |
| 次 CTA | 「看看别人做的 →」（锚点到作品墙） |
| 信任条 | 「加密处理 · 原图 7 天删除 · 首篇免费 · **电脑手机都能用**」小字 |

**验收**：
- 首屏无需滚动即可看到「真实长图 + 主标题 + 与设备匹配的 CTA」。
- 电脑端首屏必须让访客明白 **「电脑也能用，不是只能手机」**（副标题或信任条体现）。

### 屏 2 · 痛点共鸣「你是不是也这样」

三栏对比，唤起场景：

| 之前 | 之后 |
|------|------|
| 旅行回来，几百张照片躺在相册 | 选一选，几分钟出一本杂志 |
| 发九宫格，讲不出故事 | 一张长图，群友一路看到底 |
| 想写点字，又懒得写 | 自动配上标题和短文案 |

### 屏 3 · 三步演示「原来这么简单」

横向 3 步 + 微动画（GIF/Lottie/短视频）。**演示画面随设备切换**，让访客看到「跟我一样的场景」：

| 步骤 | 手机端演示画面 | 电脑端演示画面 |
|------|----------------|----------------|
| 1. 选照片 | 手机相册多选 | 电脑微信小程序内选电脑里的照片 |
| 2. 等一会儿 | 进度：整理 → 排版 → 生成 | 同（大屏可看更完整进度） |
| 3. 拿长图 | 保存到相册 → 发微信群 | 保存到电脑 / 发送到手机 → 发群 |

底部小字：「全程在微信里，无需下载 App——**手机、电脑都能做**。」

> 电脑端要特别打消「小程序=只能手机」的默认认知：明确「照片在电脑？直接用电脑微信做，更省事」。

### 屏 4 · 作品剖析「好在哪里」

拿 **一张真实长图** 逐段标注：封面 → 章节 → 图文混排 → 结尾。让访客看到「排版是有讲究的」，区别于九宫格与通用 AI。

### 屏 5 · 作品墙预览「不是我说好，是作品说好」

3–6 张真实长图缩略瀑布流 + 「查看全部作品 →」进 `/gallery`。

> 社会证明用 **作品数 / 创作者数**，不用「XX 万用户在用」（易反感且难自证）。

### 屏 6 · 信任「你的照片，你做主」

| 承诺 | 一句话 |
|------|--------|
| 加密上传 | 仅用于排版与生成 |
| 原图默认 7 天删除 | 也可随时手动删除 |
| 长图归你 | 发到哪、发不发，你决定 |

CTA：「了解我们如何处理照片 →」进 `/privacy`。

### 屏 7 · 差异化「和别的有什么不一样」

对比表（克制、不点名贬低）：

| | 九宫格 | 通用 AI 写作 | 修图 App | **Travelogue** |
|---|:---:|:---:|:---:|:---:|
| 讲一段完整旅程 | ✗ | 部分 | ✗ | ✓ |
| 杂志级排版 | ✗ | ✗ | ✗ | ✓ |
| 一张长图发群 | 部分 | ✗ | ✗ | ✓ |
| 不用学工具 | ✓ | 部分 | ✗ | ✓ |

### 屏 8 · 终局 CTA「现在就开始」

大留白 + 一句话 + **自适应 CTA**：**「你的下一次旅行，值得一本杂志。」**
- 电脑端：小程序码 + 「电脑微信里也能打开」
- 手机端：一键进入按钮

### 首页节奏原则

- **每一屏都能看到一张真实长图**（产品即广告）
- **CTA 至少出现 3 次**（Hero / 中部 / 结尾），且 **每次都按当前设备给最省事的路径**
- **双端皆一等公民**：屏 1/3/6/8 在 **电脑宽屏与手机窄屏都必须完美**；不做「移动端优先、桌面凑合」，也不做「桌面华丽、手机塞不下」
- 电脑端可利用宽屏做 **横向叙事 / 长图并排**；手机端折叠为纵向卡片

## 6. 「云端」与「本地」的叙事分区（关键决策）

网站同时代表 **小程序（云端）** 与 **Studio（本地）** 两条线。**不可混淆承诺**。

| 区域 | 承诺 | 措辞 |
|------|------|------|
| 首页 / 小程序相关全部 | 云端处理 | 「加密上传 · 7 天删原图」 |
| `/studio` 专页 | 本地处理 | 「照片留在本机 · 无需注册」 |
| `/privacy` | 两者分列 | 明确「用小程序=上传；用 Studio=本地」 |

> **红线**：绝不在小程序语境写「照片不上传」；绝不在 Studio 语境暗示「云」。诚实分区是信任的地基。

## 7. 作品墙 `/gallery` 规格

| 项 | 规格 |
|----|------|
| 内容 | 真实、**已获授权** 的 trip 长图 |
| 展示 | 缩略瀑布流 → 点开看完整长图（网页内滚动，非小程序） |
| 元信息 | 目的地 · 张数 · （可选）创作者署名 |
| 授权 | 每篇需 **书面授权**；页脚注明「作品版权归创作者」 |
| CTA | 每篇底部「我也要做一本 → 扫码」 |
| 隐私 | 展示图 **剥离精确 GPS/EXIF**（与产品一致） |

作品墙是网站最有复利的资产：**越多真实作品，转化越高，SEO 越强**。

## 8. 隐私专页 `/privacy` 规格（信任核心）

必须用 **人话** 讲清，而非法律文本堆砌（法律全文另附链接）：

1. 我们收集什么（照片、EXIF、微信 openid）
2. 用来做什么（排版、生成长图、排障）
3. 存多久（原图默认 7 天；长图/trip 30 天）
4. 谁能看到（默认只有你；长图发群由你决定）
5. 怎么删除（小程序内删除 trip）
6. 第三方（云存储；若启用 LLM 则说明）
7. 与 Studio 的区别（本地不上传）

> 与 [PRD-MINIAPP-P1.md](./PRD-MINIAPP-P1.md) §4 数据留存保持 **数字一致**（7/30 天等以那份为准）。

## 9. 转化与埋点

### 9.1 主转化路径（双端）

```
电脑端访客 → 大屏看懂/看作品 → 点 CTA ┬─ 扫码 → 手机小程序 ─┐
                                      └─ 电脑微信打开小程序 ─┤
手机端访客 → 被种草 → 点 CTA → 微信跳转小程序 ─────────────┤
                                                            ↓
                                              小程序完成长图（深度转化）
```

### 9.2 CTA 形态（分设备 · 细化）

| 访客环境 | 主 CTA 行为 | 次选路径 |
|----------|-------------|----------|
| **电脑浏览器** | 点击弹面板：① 大号 **小程序码**（手机扫→手机用）② **「在电脑微信打开」图文指引**（打开电脑微信 → 小程序面板 → 搜「Travelogue」） | 提供 **URL Scheme/URL Link**（若 PC 微信支持唤起则一键；见 OQ-W-07） |
| **手机微信内** | `<wx-open-launch-weapp>` **直接跳转小程序** | 失败兜底：长按识别码 |
| **手机浏览器（非微信）** | 「长按识别小程序码」或「复制口令 → 去微信打开」 | 引导「用微信扫一扫上方码」 |

**设计要求**：
- 用 UA 检测当前设备与是否在微信内，**默认展开最省事的那条**，其余折叠为「其他方式」。
- 电脑端 **不要只给码**——必须同时给「电脑微信也能用」的指引，否则「照片在电脑」的用户会流失。

### 9.3 埋点事件（最小集）

| 事件 | 触发 | 归因用途 |
|------|------|----------|
| `page_view` | 各页（带 `device=pc/mobile`、`in_wechat` 维度） | 漏斗基数 + 双端分析 |
| `hero_cta_click` | 点主 CTA（带设备维度） | G-W-02 |
| `qr_shown` | 展示小程序码 | 扫码意向（多为电脑端/手机非微信） |
| `pc_wechat_guide_view` | 展开「电脑微信打开」指引 | 衡量 PC 深度转化意向 |
| `gallery_open` | 打开作品 | 内容效果 |
| `privacy_view` | 到访隐私页 | G-W-04 |
| `weapp_launch` | 微信内跳转小程序成功 | 手机转化 |

深度转化（小程序内完成长图）需与小程序埋点 **通过 scene 参数打通**，并 **区分来源设备**（见 §11）。

### 9.4 分析工具

隐私友好优先（如 Plausible / Umami 自托管），避免过度追踪与 Cookie 弹窗负担。

## 10. 视觉与技术规格

### 10.1 视觉

| 项 | 规格 |
|----|------|
| 主色 | 纸白 + 墨黑 + 一个克制强调色（建议旅行感的靛蓝或赭石） |
| 字体 | 衬线标题（杂志感）+ 无衬线正文；中文用高质量开源字体 |
| 图片 | 全部真实长图；WebP + 响应式 srcset；懒加载 |
| 动效 | 克制的滚动揭示；尊重 `prefers-reduced-motion` |
| 基调 | 留白充足，像翻一本好杂志 |

### 10.2 技术

| 项 | 选型建议 |
|----|----------|
| 站点类型 | **静态站**（Astro / Next 静态导出 / Hugo 皆可） |
| 部署 | CDN 静态托管；国内需 **备案域名** |
| **响应式** | **双端一等公民**：≥1024px 宽屏布局 + ≤768px 窄屏布局，中间自适应；关键屏（Hero/三步/CTA）在两端各自出稿 |
| **设备/环境探测** | UA 判断 pc/mobile 与是否在微信内，驱动 CTA 自适应（§9.2） |
| 性能 | 移动 4G LCP < 2.5s；桌面 LCP < 2.0s；首屏图优先加载 |
| SEO | 语义化 HTML、OG 卡片（分享到微信有大图）、结构化数据 |
| 无障碍 | 对比度达标、alt 文本、键盘可达 |
| 可维护 | 作品墙内容用 Markdown/JSON 驱动，非硬编码 |

### 10.3 分享优化（微信内传播）

- **OG / 微信分享卡**：标题 + 一张长图缩略 + 一句话
- 网站链接被转发到群里时，要 **自带一张好看的长图预览**（这是二次获客关键）

## 11. 与小程序的打通

| 打通点 | 做法 |
|--------|------|
| 扫码进入 | 小程序码带 `scene` 参数，标记来源=官网 + **设备来源（pc/mobile）** |
| 归因 | 小程序读 scene → 上报「来自官网 / 哪种设备」，闭合 G-W-03 并 **区分双端转化质量** |
| 电脑端进入 | 若 PC 微信支持 URL Scheme/Link 唤起则一键；否则「电脑微信搜索打开」路径也应带可追踪标识（如引导用户搜索专属名/口令） |

| 隐私一致 | 网站隐私页与小程序首次确认页 **同一套数字与措辞** |
| 深链 | 支持带活动/渠道参数的落地页（如 `/?from=xhs`） |

## 14. 风险与开放问题

### 14.1 风险

| 风险 | 缓解 |
|------|------|
| 「云端上传」引发信任流失 | 首屏即诚实说明 + 强隐私页 + 7 天删原图 |
| 作品授权不足，作品墙空 | 冷启动用自有 trip + 种子用户书面授权 |
| 网站流量进不去小程序（跳转限制） | 微信内用 `wx-open-launch-weapp`；非微信给码/口令 |
| **电脑端访客误以为「只能手机」流失** | 首屏 + 三步 + CTA 明确「电脑微信也能用」；给图文指引 |
| **电脑端无法一键唤起小程序** | 提供扫码（转手机）+「电脑微信搜索打开」双路径；不强求一键 |
| 与 Studio 叙事打架 | §6 分区叙事，物理分页；注意 **「电脑微信小程序（云端）」≠「Studio（本地桌面）」**，勿混淆 |
| 备案/合规延迟 | 提前备案；隐私政策先行 |

### 14.2 开放问题

| ID | 问题 | 建议默认 |
|----|------|----------|
| **OQ-W-01** | 主视觉主题 | T1 印刷体 + T3 场景社会证明 |
| **OQ-W-02** | 域名与备案主体 | 尽早启动备案 |
| **OQ-W-03** | 是否首版即上价格页 | 否，P1 显示「首篇免费」 |
| **OQ-W-04** | 分析工具 | 自托管 Plausible/Umami |
| **OQ-W-05** | 作品墙是否开放用户投稿 | P1 手动收录；P2 再评估 |
| **OQ-W-06** | 是否需要英文站 | 否，首版简体中文 |
| **OQ-W-07** | 电脑浏览器能否「一键唤起」电脑微信小程序（URL Scheme/Link 在 PC 的实际表现） | 待技术验证；不确定前 **以扫码 + 电脑微信搜索指引为准** |
| **OQ-W-08** | 电脑端小程序对「选电脑本地照片」的能力与体验 | 与 [PRD-MINIAPP-P1.md](./PRD-MINIAPP-P1.md) 对齐；若受限则 PC 引导措辞相应调整 |
| **OQ-W-09** | 双端流量预估占比（影响首屏默认排布） | 上线后按 `device` 埋点校准；初期两端等重对待 |

## 15. 成功定义（网站侧三级）

| 级别 | 指标 | 含义 |
|------|------|------|
| **L1** | 首页跳出 < 60%，扫码率 ≥ 5% | 访客看懂且想试 |

| **L3** | 网站成为 **主要获客渠道之一**，作品墙自然带来外链 | 长期复利资产 |
