## 1. 文档目的

本 PRD 定义 Travelogue **智能排版** 的产品目标、可用信号、排版策略、算法架构、评估方法、学习回路与分期路线，作为：

- 产品 / 算法 / 研发的**需求与验收基准**；
- 与 [PRD-LAYOUT.md](./PRD-LAYOUT.md) 的分工：**PRD-LAYOUT** 管「pattern 白名单与槽位渲染」；**本文档** 管「**按什么信号、按什么策略、按什么数学目标决定章序、屏序、屏内序**」；
- 验收相册（mao / maomi / linzhi 等）差异解释与演进依据。

> 本文档回答的四个核心问题：**有哪些信号？策略如何组合？如何数学化与评估？如何形成学习回路？**

## 2. 背景与问题

### 2.1 用户素材差异（实测）

| 来源 | 典型特征 | 对排版的影响 |
|------|----------|--------------|
| 手机/相机 **原生拷贝**（如 maomi） | EXIF 完整、分辨率高、可选 GPS | 时间切段准、低清剔除少、可按真实 chronology 编排 |
| **微信另存**（如 mao） | 压缩、EXIF 丢失、文件名日期粒度粗 | 连拍/phash 去重多、低分辨率剔除、同日扎堆 |

智能排版需在 heterogeneous 素材下仍产出**可读、有节奏、可解释**的游记结构。

### 2.2 产品目标

| ID | 目标 | 衡量 |
|----|------|------|
| I-G1 | **时间主轴**清晰：读者感到「按旅程先后」阅读 | 段间 `takenAt` 逆序对比例 < 1% |
| I-G2 | **主题局部聚合**：段内人物/宠物/风景成组，不全局乱序 | `subject_run_score` > baseline；人工抽检 |
| I-G3 | **版式匹配构图**：横竖全景各得其所 | `aspect_pattern_match_rate` ≥ 95% |
| I-G4 | **美学节奏（新增）**：屏间密度变化合理、色调连续、章有起承转合 | 主观盲评胜率 ≥ 60% vs baseline |
| I-G5 | **可复现、可配置** | 同 trip + 同 config 重跑结果一致；权重 YAML 可调 |
| I-G6 | **可 G1 干预、可学习** | `g1_edit_distance` 全链路可采、可离线分析 |

### 2.3 非目标

- 全相册跨月 **同一人脸 ID** 全局聚类（误聚风险高、叙事乱序）。
- 依赖 **相机 ISO/光圈/快门** 驱动排版（游记品类信噪比低）。
- **RAW** 格式导入（产品已明确不支持）。
- 像素级平面设计、自由拖拽 DOM、自由 grid 编辑器。
- **端到端 LLM 生成 DOM**（不可解释、不可回归、不可验收）。
- 黑盒端到端排序、无 G1 闸口。

### 2.4 适用品类（新增）

| `meta.genre` | 主轴 | 当前覆盖 |
|---------------|------|----------|
| `travel`（默认） | 时间 + 地点 | ✅ 本文档主场景 |
| `portrait` | 主体 + 时间次轴 | ⏳ 预留 |
| `theme`（风光集 / 美食集） | 主题聚类 + 视觉相似 | ⏳ 预留 |
| `diary`（长期日记） | 月/季节为粒度的时间 | ⏳ 预留 |

未在 trip 元数据中显式声明则默认为 `travel`。本 PRD 算法与默认权重以 `travel` 为目标，预留 `genre` 字段以便未来不同主轴接入。

## 5. 画册设计原语层（新增）

> 现有 pattern + slot 已能保证「摆得对」；本节定义让画册「**有节奏、有呼吸、有情绪**」的原语。这是 v2 相对 v0.1 的核心增量。

### 5.1 节奏（Rhythm）

**定义**：章内屏与屏的「图数密度」变化，例如 `1 → 1 → 4 → 1 → 2`。

**指标**：屏内图数序列的**信息熵** + **峰位置**。

**软约束**：
- 章内 ≥3 屏时，至少存在一次「多图 → 单图」或「单图 → 多图」的密度切换。
- 避免连续 ≥4 屏都是相同 pattern。

### 5.2 跨屏对位（Spread）

**定义**：相邻两屏作为一个整体看，应在颜色 / 构图方向 / 主体上有呼应或对比。

**软约束**：
- 相邻屏 `dominantTone` 的 ΔE（CIE76）∈ [10, 40]：太近闷、太远跳。
- 相邻屏避免「同色 + 同主题 + 同 pattern」三重重复。

### 5.3 呼吸（Breathing）

**定义**：章间、peak 后、章末需要「留白屏」让阅读节奏停顿。

**实现**：
- 章末若为高密度（4+ 槽）拼图，强制下一屏为 single hero 或文字屏。
- `peak` 后紧接的章首 hero 应是单图横/全景，给情绪缓冲。

### 5.4 视觉重量平衡（Weight）

**定义**：人脸 / 深色 / 高对比 / 大块色块都贡献「视觉重量」。屏内多槽位时重量应平衡。

**指标**：每张图重量 = `α · sharpness + β · 1[has_face] + γ · luminance_variance`，归一化后比较屏内方差。

**软约束**：四宫格屏内重量方差 < 阈值。

### 5.5 景别梯度（Shot-Type Gradient）

**定义**：远景 → 中景 → 特写 是画册基础节奏（电影叙事亦同）。

**软约束**：
- 章内屏序的 `shotType` 序列尽量呈现「远-中-近-中-远」类弧形或单调梯度。
- 避免「远-远-远-远」一路平铺。

### 5.6 章叙事弧（Narrative Arc）

**v2 关键变更**：章 pattern 从 4 段扩为 **5 段叙事弧**。

| 段位 | pattern | 倾向特征 | 视觉手法 |
|------|---------|----------|----------|
| 1 | `open` | 钩子、地点感 | 横/全景单图、城市/风光、白天 |
| 2 | `rise` | 铺陈、节奏中等 | 中等密度，混合人物风景 |
| 3 | `peak` | 高潮、最强视觉 | 包含 trip 内 `hero_score` 最高若干张；密度可峰值 |
| 4 | `fall` | 余温、情绪降温 | 中低密度，倾向人物特写或细节 |
| 5 | `close` | 收尾、留白 | 单图、傍晚/夜景/室内、低饱和 |

**分配规则**：
- 章数 = 3 时，使用 `open / peak / close`。
- 章数 = 4 时，使用 `open / rise / peak / close`。
- 章数 = 5 时，全弧。
- 章数 > 5 时，中段重复 `rise / peak / fall`，但 `peak` 全 trip 只 1–2 个。

**`peak` 必含**：trip 内 `hero_score` Top-K 的至少 1 张。

### 5.7 章首 / 章末契约

| 位置 | 契约 |
|------|------|
| Trip 封面 | 与 hook 文案意象一致；倾向横/全景；非缩略图、非截屏 |
| Trip 第一章首屏 | 与封面**不重复**；倾向白天/早晨；地点感强 |
| 每章首屏 | 横/全景大图；含人脸时焦点居中 |
| 每章末屏 | 单图或低密度；倾向情绪缓冲（傍晚、室内、特写） |
| Trip 末章末屏 | 倾向夜景/傍晚/低饱和；与 `epilogue` 文案呼应 |

### 5.8 图文耦合

**软约束**：
- 含长 `lead`（>40 字）的章首屏倾向单图，给文字留白。
- 含长 `caption`（>30 字）的屏倾向横单图或 2 槽，避免高密度拼图压缩文字空间。
- 无文案的章末屏可用密度更高的拼图（情绪让位给视觉）。

## 6. 排版策略规格

### 6.1 宏观分段（Layer 1 · 已有）

**输入**：可排版 assets、`segment_gap_days`、`city_gap_days`、`place`

**规则**：
1. 按 `takenAt` 排序；
2. 相邻照片日期差 ≥ `segment_gap_days` → 新时间段；
3. 城市变化且间隔 ≥ `city_gap_days` → 新时间段；
4. 段内按 **日** 分桶；过小桶合并（`min_bucket_size`）；
5. 桶 → 章；章数映射到 5 段叙事弧（§5.6）。

**输出**：`chapters[]` 骨架、`TimeSegment` 警告。

**G1**：用户可合并段、拆成多本游记。

### 6.2 主题局部聚合（Layer 1.5 · P1）

**原则**：主题聚合是**时间窗口内的局部优化**，禁止跨 `TimeSegment` 重排。

| 策略 | 定义 | 默认窗口 |
|------|------|----------|
| 同一人 | 同 `personClusterId` 且时间差 < T | 同日或 2h |
| 同一人 + 距离 | 上式且 GPS 距离 < D | D = 500m（可选） |
| 宠物 | `subjectClass=pet` 连续 run | 同段、同日内 |
| 纯风景 | 无 person/pet 且 `subjectClass ∈ {landscape, architecture}` | 连续 run，允许短间隔插入 1 张过渡 |
| 食物/室内 | `subjectClass ∈ {food, indoor}` | 同日内成 run |

### 6.3 Screen-aware 联合规划（Layer 2+3 · 重写）

v2 关键变更：**段内序与组屏合并为一个联合优化器**，目标是屏内、屏间、段内三层评分的加权和最大化。

**输入**：段内 assets + tags + aspect + subjectClass + dominantTone

**输出**：`screens[]`（每个 screen 已选 pattern + slot 分配）

**算法主流程**：

```
1. 候选屏生成（candidate generation）：
   用现有 screen_planner 在 assets 上生成多套 candidate screens
   （不同 burst 切分、不同 person/scenery 分流策略）

2. 屏序枚举（beam search）：
   状态 s = (i, last_subject, last_aspect, last_tone, density_window)
   动作 a = 选择下一个 candidate screen
   束宽 beam_width = 8

3. 评分（详见 §7）：
   每条 beam 路径累加屏内 + 屏间 + 段内三层评分
   保留 Top-beam_width 条

4. 输出：得分最高的 screens 序列 + decision_log
```

**复杂度**：`O(n · beam_width · |candidates|)`，n ≤ 60 时实时可行。

### 6.4 章 pattern 分配（更新）

| 段内特征 | 倾向 pattern |
|----------|--------------|
| 第一段、张数多 | `open` |
| 张数中等、人物占比 50% 左右 | `rise` |
| 含 trip Top-K `hero_score` | `peak`（每 trip 1–2 个） |
| 张数中等、人物或风景特写多 | `fall` |
| 最后一段、张数少、傍晚/夜景多 | `close` |

驱动信号：**主题占比 + 张数 + hero_score + 时段 tag**。

### 6.5 槽位渲染（Layer 4 · 已有）

- `focalPoint` / `salientBox` → WebP / cover 裁切中心；
- 人物 → contain；
- `screen-tone` 取自代表图 `dominantTone`。

## 7. 评分函数：数学化（重写）

### 7.1 总体形式

```
Score(plan) = Σ_i  w_i · f_i(plan) ,
其中  Σ w_i = 1,   每个 f_i ∈ [0, 1]
```

**所有评分项必须归一化到 [0, 1]，权重和恒等于 1**。这保证：

- 增加新评分项不破坏整体尺度；
- 权重可比、可手调、可学习；
- 总分总在 [0, 1]，可作为单一 metric 跟踪。

### 7.2 评分项分层

| 层 | 评分项 | 含义 |
|----|--------|------|
| **段内序** | `f_time` | 时间单调平滑 |
|  | `f_subject_run` | 同主题成 run |
|  | `f_person_adj` | 同人物相邻（段内） |
| **屏内** | `f_aspect_match` | aspect ↔ pattern 命中 |
|  | `f_weight_balance` | 屏内视觉重量平衡 |
|  | `f_burst_integrity` | burst 不被拆 |
| **屏间** | `f_tone_continuity` | 相邻屏色调 ΔE 在 [10, 40] |
|  | `f_shot_gradient` | 景别梯度 |
|  | `f_rhythm` | 密度变化熵 |
|  | `f_spread_diversity` | 相邻屏避免三重重复 |
| **章/Trip** | `f_arc_match` | 5 段叙事弧匹配度 |
|  | `f_hero_diversity` | 相邻章 hero 构图差异 |
|  | `f_cover_thesis` | 封面与 hook 意象一致（P2） |

### 7.3 归一化函数定义

每个 `f_i` 必须给出明确定义：

```text
f_time(order)
  = 1 - mean( clamp(Δt_i / Δt_seg_p95, 0, 1) )
  其中 Δt_i 为相邻 asset 时间差，Δt_seg_p95 为段内时间差 95 分位
  含义：段内时间间隔越接近 p95 越是 "跳跃"，扣分越多

f_subject_run(order)
  = mean( min(run_length / target_run, 1) ) for all runs
  其中 target_run = 3
  含义：同主题 run 越接近 3 张越好（过长也不再加分）

f_person_adj(order)
  = same_cluster_adjacent_pairs / total_same_cluster_pairs
  含义：同人物 cluster 中，相邻配对占总配对比例

f_aspect_match(plan)
  = aspects_matching_pattern / total_slots
  含义：例：landscape 进 landscape-* pattern 算命中

f_weight_balance(screen)
  = 1 - clamp( σ(weights_in_screen) / σ_max, 0, 1 )
  其中 σ 为屏内图视觉重量的标准差
  含义：屏内重量越平衡越好

f_burst_integrity(plan)
  = preserved_burst_groups / total_burst_groups
  含义：burst 组未被拆比例

f_tone_continuity(screens)
  = mean( triangular(ΔE_i, low=10, peak=25, high=40) )
  其中 triangular 是三角窗（10–40 之间得分，25 处最高）
  含义：相邻屏色调差距适中

f_shot_gradient(screens)
  = 1 - monotonic_break_count / (n_screens - 1)
  含义：景别序列的 "突变" 越少越好

f_rhythm(screens)
  = clamp( entropy(density_sequence) / log(K), 0, 1 )
  其中 K 为出现的不同密度类别数
  含义：屏密度有适度变化（熵越高越有节奏）

f_spread_diversity(screens)
  = 1 - triple_repeat_count / max(1, n_screens - 1)
  含义：相邻屏 (tone, subject, pattern) 三重相同的对越少越好

f_arc_match(chapters)
  = matched_chapters / total_chapters
  含义：章特征与对应叙事弧位置的匹配比例

f_hero_diversity(chapters)
  = distinct_aspect_pairs / max(1, n_chapters - 1)
  含义：相邻章 hero 的 aspect 不同的比例
```

### 7.4 默认权重

```yaml
weights:
  # 段内序
  time:           0.12
  subject_run:    0.08
  person_adj:     0.06

  # 屏内
  aspect_match:   0.15
  weight_balance: 0.05
  burst_integrity:0.08

  # 屏间
  tone_continuity:0.10
  shot_gradient:  0.08
  rhythm:         0.06
  spread_diversity:0.04

  # 章/Trip
  arc_match:      0.12
  hero_diversity: 0.06
  # 合计 = 1.00
```

> 默认权重的设计原则：硬指标（aspect_match、arc_match、time）占比偏高；美学指标各自较低但累加足够影响排名；burst_integrity 高是为了保护连拍叙事。

### 7.5 硬约束（不可违反）

下列**硬约束**直接过滤候选，不进入软评分：

| 约束 | 说明 |
|------|------|
| aspect 不匹配 pattern slot | 例：portrait 不能进 `screen-landscape-1` 主槽 |
| `layoutEligible=false` 入版 | 必须排除 |
| burst 组被拆（除非 `allow_burst_split=true`） | 默认禁止 |
| 段间顺序逆转 | 段是不可重排的硬边界 |
| 封面是 thumbnail/reupload | 强制换 |
| 章首 hero 与封面同图 | 强制换 |

## 8. 联合优化算法（重写）

### 8.1 状态空间

```
状态 s = (
    next_asset_pool,      # 段内尚未排入的 asset id 集合
    emitted_screens,      # 已发出的 screens 序列
    last_subject,         # 上屏主题
    last_aspect,          # 上屏主导 aspect
    last_tone,            # 上屏 dominantTone
    density_window,       # 最近 W 屏的密度序列（如 W=3）
    burst_state,          # 各 burst 组的发出情况
    arc_position,         # 当前在叙事弧的哪一段
)
```

### 8.2 转移与剪枝

**候选动作**：在 `next_asset_pool` 上调用现有 `screen_planner` 的子例程，列出 Top-K 个 candidate screens（K=5 默认）。

**剪枝规则**（在动作生成阶段就排除）：
1. 违反任一硬约束的 candidate（§7.5）；
2. 与 `last_subject` 同时段且与前两屏构成 (tone, subject, pattern) 三重相同；
3. burst 组只发出一半的中间状态（必须整组发出或暂不发出）。

### 8.3 搜索算法

**Beam Search**（默认）：

```python
beams = [initial_state]
while not all_terminal(beams):
    new_beams = []
    for beam in beams:
        for candidate in generate_candidates(beam, top_k=5):
            next_state = apply(beam, candidate)
            score = incremental_score(next_state)
            new_beams.append((score, next_state))
    beams = top_k_by_score(new_beams, beam_width=8)
return best(beams)
```

**复杂度**：`O(n_screens · beam_width · K) ≈ O(60 · 8 · 5)` ≈ 2400 评估，毫秒级。

**降级**：当 n_screens > 60 时按段切片分批 beam search，段间贪心拼接。

### 8.4 增量评分

为避免每次重算全局，每条 beam 维护：
- 段内序累计：`f_time`、`f_subject_run`、`f_person_adj` 的运行和；
- 屏间累计：`f_tone_continuity`、`f_shot_gradient`、`f_rhythm`、`f_spread_diversity` 的运行和；
- 屏内：每屏 emit 时一次性计算 `f_aspect_match`、`f_weight_balance`、`f_burst_integrity` 并累加。

章/Trip 级（`f_arc_match`、`f_hero_diversity`）在 beam 终止时一次性算。

### 8.5 决策日志

每次 emit 一个 screen 时写入 `decision_log`：

```json
{
  "ts": "2026-05-26T16:50:00Z",
  "tripId": "maomi",
  "stage": "screen-aware-plan",
  "screenId": "ch-02-sc-03",
  "patternId": "screen-landscape-4",
  "assetIds": ["asset-013","asset-018","asset-022","asset-027"],
  "scoreBreakdown": {
    "aspect_match": 1.0, "weight_balance": 0.82, "burst_integrity": 1.0,
    "tone_continuity": 0.71, "shot_gradient": 0.66, "rhythm": 0.58
  },
  "reasonTop": "aspect_match + burst_integrity + tone_continuity",
  "rejected": [
    {"candidate":"...","reason":"violates spread_diversity"}
  ]
}
```

此日志是 §10 反馈回路的根基。

## 9. 评估方法学（新增）

### 9.1 三层评估

| 层 | 评估对象 | 方法 | 频率 |
|----|---------|------|------|
| **L1 单元测试** | 算法行为、归一化、约束 | pytest | 每次 PR |
| **L2 黄金样本** | 端到端排版 | 5–10 个手工标注的 trip，比较 chapter/screen 序列 | 每次发版 |
| **L3 主观盲评** | 真实观感 | 3 人对 A/B 两版盲打分（节奏、连贯、舒适），统计胜率 | 每个里程碑 |

### 9.2 关键指标

| 指标 | 定义 | 目标 |
|------|------|------|
| `time_inversion_rate` | 段间 `takenAt` 逆序对 / 总对 | < 1% |
| `aspect_pattern_match_rate` | aspect 命中 pattern slot 比例 | ≥ 95% |
| `subject_run_score` | 同主题 run 加权长度（归一化） | ≥ 0.6 |
| `tone_continuity_score` | 相邻屏 ΔE 在 [10,40] 占比 | ≥ 0.7 |
| `arc_match_rate` | 章 pattern 与 5 段叙事弧匹配 | ≥ 0.8 |
| `cover_diversity` | cover 候选 aspect/day 不同数 | ≥ 3 |
| `total_score` | 加权总分（§7.1） | 单调上升 |
| `g1_edit_distance` | 用户在 G1 修改了几处 | 单调下降 |

`g1_edit_distance` 是**最终真理**：它把用户行为反过来作为算法的训练信号。

### 9.3 黄金样本规约

每个 golden trip 包含：

```text
trips/_golden/<trip-id>/
  trip.json                  # 锁定的输入
  golden.layout.json         # 期望的 chapter/screen 序列
  golden.metrics.json        # 期望的指标基线
  README.md                  # 该样本的代表场景与验收要点
```

**初始黄金集**（建议从已有验收相册派生）：
1. `mao-golden`：微信图、同日扎堆 → 验证去重与低清剔除
2. `maomi-golden`：跨月多 journey → 验证切段与多段提示
3. `linzhi-golden`：长旅程 → 验证大 trip 配额
4. `portrait-heavy-golden`：人像密集 → 验证 person-pair/triple 与 contain
5. `landscape-heavy-golden`：风光为主 → 验证横图组屏与全景

每次发版跑 `pytest tests/test_golden_layouts.py` 比较：
- `chapter_id_seq`、`screen_pattern_seq` 必须完全相同（除非显式更新 golden）；
- `total_score` 不得低于 golden baseline。

### 9.4 主观盲评流程

```
1. 准备 A/B 两版（如 baseline vs 新算法）渲染产物
2. 同一 trip 在两版下各生成 PNG 长图
3. 3 名评审独立打分：节奏(1-5)、连贯(1-5)、舒适(1-5)、是否愿意分享(yes/no)
4. 统计胜率：B 胜 A 的 trip 数 / 总 trip 数
5. 胜率 ≥ 60% 算改进有效
```

### 10.1 数据采集

| 数据 | 触发时机 | 字段 |
|------|----------|------|
| `decision_log.json` | 每次 curate / layout 完成 | §8.5 |
| `g1_edit.json` | 每次 G1 锁 structure 前 | 用户修改的 chapter/screen diff |
| `subjective_eval.json` | 主观盲评时 | trip_id、版本、各维度分 |
| `render_telemetry.json`（可选） | render 完成 | 渲染耗时、产物大小 |

### 10.2 g1_edit_distance 定义

```
g1_edit_distance = (
    chapter_reorder_ops +
    screen_swap_ops * 0.8 +
    asset_move_across_screens * 0.6 +
    cover_change_ops * 0.5 +
    hero_change_ops * 0.3
)
```

理想算法下该值应单调下降。

### 10.3 离线学习的最小路径

不必现在就上 ML。建议步骤：

```
阶段 A：积累期（前 50 个 trip）
  仅采集 decision_log + g1_edit_distance
  权重保持默认（§7.4），不学习

阶段 B：分析期（50–200 trip）
  对每个 trip 提取：
    X = score_components 向量（11 维归一化项）
    y = g1_edit_distance（标量）
  用线性回归 / LightGBM 拟合 X → y
  分析重要性，发现：
    - 哪些项与 G1 编辑高度相关 → 应加权
    - 哪些项几乎不相关 → 可降权或移除
  人工 review 后，调整默认权重

阶段 C：上线期（200+ trip）
  按用户分桶（cohort）做 A/B
  胜率达标后切流
```

**关键**：**不做强化学习 / 端到端神经网络排版**，理由：
- 标注成本高；
- 不可解释；
- 与 G1 闸口冲突；
- 线性模型已能拿到 80% 收益。

### 10.4 LLM 顾问（P2，可选）

LLM 在排版中**只**承担两个边角任务：

| 任务 | 输入 | 输出 |
|------|------|------|
| 章序顾问 | 章列表 + 主题占比 + 叙事弧位置 | 建议章序调整（仅建议，不强制） |
| 封面意象顾问 | 封面候选 + hook 文案 | 推荐与 hook 意象最匹配的 cover |

**禁止**：LLM 直接生成 DOM、修改 screens、决定 pattern。

## 11. 失败模式与降级策略（新增）

| 失败模式 | 触发条件 | 降级策略 |
|----------|----------|----------|
| **素材稀疏** | trip 总数 < 6 | 跳过段内优化器；用 single-column 节奏；强制 3 章 |
| **素材超密集** | 单段 > 100 张 | 段内分批 beam search，段间贪心拼接 |
| **全人物** | person 占比 > 90% | 关闭 `f_subject_run`、`f_shot_gradient`；以人物子聚类驱动 |
| **全风景** | person 占比 < 5% | 关闭 `f_person_adj`；提升 `f_tone_continuity` 权重 |
| **无日期** | `dateConfidence` 全 low | 退化为「按文件名顺序 + aspect 节奏」；CLI WARN |
| **混搭旅行** | 检测到 ≥3 segments | 默认合一本并提示拆分；权重弱化 `f_tone_continuity`（不同地点色差大正常） |
| **vision 失败** | CLIP/VLM 不可用 | 降级到 heuristic tags；关闭依赖 subjectClass 的评分项 |
| **GPS 全缺** | geo 全空 | 切段仅按时间；不影响其他评分 |
| **总分异常低** | total_score < 0.4 | 自动降级为「最朴素时间序 + aspect 分组」；CLI WARN，等待 G1 |

降级时**必须在 decision_log 写入降级原因**，便于排查。

## 14. 实现路线与分期

### 14.1 设计原则

1. **硬约束 + 软评分（归一化 + 权重和=1）**：保证可渲染 + 可调可学。
2. **时间主轴 + 段内局部**：聚合永远是局部优化。
3. **可解释**：每屏 emit 时写 `decision_log`，附 `scoreBreakdown` 与 `reasonTop`。
4. **可降级**：失败模式 §11 全覆盖。
5. **可学习**：`g1_edit_distance` 是单一最终指标。
6. **分阶段上线**：规则 → 轻语义 → 离线学习 → LLM 顾问。

### 14.2 流水线（目标态）

```text
Step 0  过滤        layoutEligible + mediaClass
Step 1  宏观分段     TimeSegment（时间 + 城市）
Step 2  主题标注     subjectClass / dominantTone / shotType / salientBox（P1）
Step 3  章分配       5 段叙事弧（§5.6）
Step 4  联合规划     Screen-aware beam search（§8）
Step 5  G1           人工确认 / 锁 structure
Step 6  渲染         Render（零 LLM）
Step 7  采集         decision_log + g1_edit_distance
```

### 14.3 分期交付

**P0（1–2 周，零模型）**

| 任务 | 价值 |
|------|------|
| 评分项落地到 `layout/scoring.py`（归一化、权重） | 地基 |
| `decision_log.json` 输出 | 反馈回路的根基 |
| `time_inversion_rate`、`aspect_pattern_match_rate` 等 metric 进 pytest | 防回归 |
| 黄金样本 5 套（mao/maomi/linzhi/portrait/landscape）冻结 | L2 评估 |
| 章 pattern 改为 5 段叙事弧（§5.6） | 节奏立即提升 |
| 章首 hero ≠ 封面 / 相邻章 hero 构图差异 | 视觉契约 |
| 失败模式 §11 全部实现 | 鲁棒性 |

**P1（2–4 周，轻语义）**

| 任务 | 价值 |
|------|------|
| CLIP zero-shot / 本地模型打 `subjectClass` + `shotType` | 主题聚合入场券 |
| ingest 写入 `dominantTone` + `salientBox` | 无人脸图也有 focal |
| Screen-aware 联合 beam search 上线 | 核心引擎 |
| 跨屏色调连续 + 景别梯度 + rhythm 评分 | 美学跃迁 |
| 主观盲评机制 + 首轮 A/B | 验证收益 |

**P2（更远，可选）**

| 任务 | 价值 |
|------|------|
| 人脸 embedding + 段内 `personClusterId`（限段内 + 时间/距离窗） | 真正的「同一人邻近」 |
| GPS 停留点检测（DBSCAN） | 同一 POI 更紧凑 |
| 离线学习权重（LightGBM on `g1_edit_distance`） | 真正智能化 |
| LLM 章序顾问、封面意象顾问 | 边际收益高、风险低 |

### 14.4 不做的事

| 不做 | 理由 |
|------|------|
| 端到端 LLM 生成 DOM | 不可解释 |
| 跨月全局同人聚类作为主轴 | 误聚 + 叙事乱序 |
| 让算法独占决策、无 G1 闸口 | 用户失去信任 |
| ISO/光圈/焦距驱动排版 | 游记品类信噪比低 |
| 自由 grid / 拖拽编辑器 | 与「自动出版」定位冲突 |
| RAW 格式 ingest | 已明确不支持 |
| 强化学习 / 端到端神经排序 | 标注成本高 + 不可解释 |

## 16. 风险与对策

| 风险 | 对策 |
|------|------|
| 微信图日期假精度 | `dateConfidence` 低时弱化切段、提示 G1 |
| 人脸误检/漏检 | 仅作软信号；contain 仅在有 person tag 时启用 |
| 同人聚类误并 | 限制在 TimeSegment + 时间/距离窗；可 G1 拆段 |
| 主题模型过重 | 默认 heuristic；CLIP 可选、离线 |
| 评分项膨胀失稳 | 强约束「权重和=1、归一化到[0,1]」；新增项必须随附 fixture |
| 权重不可比 | 同上 |
| LLM 顾问越权改 DOM | 架构上隔离：LLM 只产 suggestion，规则层决定 DOM |
| 黄金样本固化导致创新难 | 区分「行为黄金」（必同）与「指标黄金」（允许提升） |
| Beam search 卡顿 | 段内 ≤60，超出走分批降级 |
| 与 PRD-LAYOUT 职责重叠 | 本文档管「序与组」；PRD-LAYOUT 管「槽与 pattern 白名单」 |
| 学习权重过拟合早期数据 | 阶段性 review，cohort A/B 验证后才切流 |
