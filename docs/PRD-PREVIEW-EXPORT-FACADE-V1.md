> **定位**
>
> 精修体验 V1 已堵住「半生效可导出旧长图」的结构性漏洞，并把导出口径统一为「长图 / 更新版面 / 更新并导出」。  
> **本 PRD 不扩精修能力、不改 IA**，只打磨 **Dock 导出门面** 从「点长图」到「知道怎么发群」的最后一公里：可靠性、可感知进度、文案层级、认知收口、成功引导与漏斗观测。
>
> **与精修 V1 的关系**
>
> | 主题 | 解决什么 |
> |------|----------|
> | **精修体验 V1** | 验货默认 · 保存语义 · 导出前拦截 · 命名分词 · 三区 IA |
> | **导出门面 V1（本文）** | 拦截之后的续跑可靠 · Modal/仅更新后的旅程闭合 · Dock 认知 · 成功发群一句 · 商业化埋点 |
>
> **产品共识（四条铁律）**
>
> 1. **三条体验合同不变** — 无 pending = 1 次点击出长图；有 pending = 绝不能静默旧图；用户可见词只有一套（更新版面 / 更新并导出 / 长图）。  
> 2. **不弱化 80% 路径** — 不把平台选择大面板、zip、LLM、阅读视图抬到 Dock；导出 ▾ 继续收纳高级项。  
> 3. **不加第四个 Modal 按钮** — 维持主「更新并导出」· 次「仅更新版面」· 幽灵「取消」。  
> 4. **成功以「愿发出去」为终点** — 长图落盘不是终点；门面须告诉用户下一步怎么发微信。

## 1. 背景与问题

### 1.1 As-Is（精修 V1 落地后）

| 能力 | 现状 | 来源 |
|------|------|------|
| 导出拦截 | `layoutPending` 时点导出 → Modal，禁止静默旧长图 | MF-01 / MF-06 |
| 主按钮续跑 | 「更新并导出」写 `sessionStorage` → 版面刷新 → `consumeExportAfterLayout` 自动 `runLongshotExport` | `longshot.js` |
| 文案统一 | 用户可见「应用排版」→「更新版面」 | MF-02 |
| Dock | 返回 · 放映 · 精修 ✎ · 长图（含标签） | MF-03 · D-REF-16 |
| 首访脉冲 | 脉冲打在导出，不打精修 | M2 |
| 优先级栈 | G1 > layoutPending > longshotStale | D-REF-18 |
| 埋点 | 已有 `longshot_export_start` / `success` / `fail` | 现网 |
| 图标盲测 | SF-02 **合入后补签**（条件 Go 豁免） | ACCEPTANCE §6 |

### 1.2 仍存在的断裂（P-EXP-*）

| ID | 问题 | 影响 | 用户 |
|----|------|------|------|
| **P-EXP-01** | 「更新并导出」续跑失败/中断时，反馈不足或 flag 残留语义不清 | 以为会导出但没有；或误以为已导出 | 编辑者为主 |
| **P-EXP-02** | 更新/续跑过程缺少连贯状态文案 | 刷新空窗像卡死，连点加重负载 | 双 persona |
| **P-EXP-03** | Modal 标题偏工程（「版面尚未更新」）；「仅更新」后无下一步提示 | 分享者以为出错；编辑者更新完不知道再点长图 | 双 persona |
| **P-EXP-04** | Dock「长图」与部分文案「导出长图」并存；脉冲可能反复出现 | 首次认知不稳；干扰验货 | 分享者 |
| **P-EXP-05** | 长图成功后缺少「怎么发群」一句 | 落盘 ≠ 发出；商业北极星「愿分享」断在最后一米 | 分享者 |
| **P-EXP-06** | 拦截 → 更新并导出 → 成功 漏斗无专用事件 | 无法判断半生效教育是否失败、主按钮完成率 | 产品/运营 |
| **P-EXP-07** | SF-02 图标盲测未闭环 | P0 Go 条件项未完结；笔尖/长图箭头对比度可能不足 | 全量 |

### 1.3 核心判断

> **导出门面不是新功能面，是主 CTA 的可靠性与闭环。**  
> 精修 V1 解决「会不会导出旧版」；本文解决「点了更新并导出之后，人是否始终知道系统在干什么，以及长图落盘后是否知道怎么发」。

### 1.4 用户分层（沿用精修 V1 / Phase 5）

| Persona | 占比（估） | 本 PRD 策略 |
|---------|------------|-------------|
| **分享者** | ~80% | 无 pending 一键长图；成功后一句发群引导；不被 Modal/脉冲吓到 |
| **编辑者** | ~20% | pending 拦截人话；「更新并导出」全程可感知；「仅更新」后仍知道如何导出 |

## 2. 目标与非目标

### 2.1 产品目标

| ID | 目标 | 衡量方式 |
|----|------|----------|
| **G-EXP-01** | 「更新并导出」从点击到长图开始（或明确失败）**全程可感知** | AC-EXP-01～03；无「静默无反馈」空窗 |
| **G-EXP-02** | 续跑失败/ trip 不一致/ 用户离开 **不幽灵导出、不误导已导出** | AC-EXP-04～06 |
| **G-EXP-03** | Modal +「仅更新」后旅程闭合 | AC-EXP-07～08；种子手测不迷路 |
| **G-EXP-04** | Dock 导出口径一致；首访脉冲只出现一次有效周期 | AC-EXP-09～10；SF-02 ≥4/5 |
| **G-EXP-05** | 长图成功后用户知道下一步（发微信） | AC-EXP-11 |
| **G-EXP-06** | 拦截漏斗可观测 | 埋点 §8 事件齐全；可出周报 |

### 2.2 非目标

| 类别 | 非目标 |
|------|--------|
| **IA / 精修** | 不改三区、不改 G1 横幅规格、不加精修能力 |
| **Dock 扩容** | 不上阅读视图、zip、LLM、平台大面板到 Dock（维持 PK-03 精神） |
| **Modal** | 不增加第四按钮；不做「仍导出旧版」逃生舱（禁止半生效） |
| **渠道** | 不做小程序/SaaS/插件；不做「一键发到微信群」系统级分享（本机 Studio 无此 API 承诺） |
| **算法** | 不改长图渲染/分段策略（属 Longshot 2.0） |
| **安装包** | 不纳入 Desktop Installer |

### 2.3 成功指标（建议）

| 指标 | 目标 |
|------|------|
| 「更新并导出」完成率（拦 → 长图 start） | 种子样本 ≥80%（失败须有明确错误，不计分子） |
| 「仅更新」后 5 分钟内再点导出占比 | 可观测；用于判断是否需要更强下一步提示 |
| pending 静默旧导出 | **= 0**（回归铁律） |
| 零精修导出（UX-REF-80-01） | **不回归** |
| 图标盲测「精修」「长图」 | ≥4/5（收口 SF-02） |
| 成功页/态含发群引导曝光 | 100% 成功路径 |

## 3. 体验合同与点击预算

### 3.1 三条体验合同（不可破坏）

| # | 合同 | 说明 |
|---|------|------|
| **C1** | 无 `layoutPending` → **1 次点击**完成「开始导出长图」 | 脉冲、红点、Task Dock 不得抢导出主焦点或额外强制点击 |
| **C2** | 有 `layoutPending` → **禁止静默导出旧长图** | 必出拦截 Modal；「稍后」不清除 pending |
| **C3** | 用户可见词 **仅一套** | 「更新版面」「更新并导出」「长图」；禁止回潮「应用排版」「编辑与设置」 |

### 3.2 点击预算（沿用精修 V1 §2.4）

| 路径 | 计入主路径？ | 预算 |
|------|--------------|------|
| 无 pending · 导出长图 | 是 | **1 次** |
| 有 pending ·「更新并导出」 | 是 | **允许 +1**（合计 2；不可静默旧导出） |
| 打开精修 / 导出 ▾ 高级项 | 否 | — |
| 返回 Studio | 否 | 不计入 |

### 3.3 注意力优先级（沿用 D-REF-18）

```text
G1（若有）> layoutPending > longshotStale
```

同时最多一层主待办抢注意力。本 PRD 要求：**导出钮保持金色主 CTA**，不得因 pending 改成警告色（红点可留在精修笔上）。

## 4. 「更新并导出」续跑可靠性（P0）

### 4.1 现状机制

```text
layoutPending → 点长图 → Modal
  → [更新并导出] → sessionStorage(EXPORT_AFTER_LAYOUT=tripId)
                 → applyLayoutRerender（通常整页刷新）
                 → init 时 consumeExportAfterLayout
                 → tripId 匹配且无 pending → runLongshotExport
  → [仅更新版面] → 不写续跑 flag → 只 rerender
  → [取消] → 无操作
```

### 4.2 需求（F-EXP-*）

| ID | 需求 | 优先级 |
|----|------|--------|
| **F-EXP-01** | 点击「更新并导出」后，在 rerender/刷新开始前或同时进入 **busy 态**：导出钮与主按钮不可连点；Task Dock / 导出区展示「正在更新版面…」 | P0 |
| **F-EXP-02** | `applyLayoutRerender` **失败**时：清除续跑 flag；**错误 toast/告警**：「版面没有更新成功，长图尚未开始」；不进入 `runLongshotExport` | P0 |
| **F-EXP-03** | `consumeExportAfterLayout`：`flagged !== tripId` 时 **清除 flag、不导出**（防串 trip） | P0 |
| **F-EXP-04** | 续跑成功开始长图时，状态文案切换为现网导出态（如「正在保存…」），形成 **更新 → 导出** 两段连贯感知 | P0 |
| **F-EXP-05** | 续跑 flag **仅同标签页会话有效**；建议写入时间戳，超过 TTL（默认 **10 分钟**）则丢弃并打点 `export_after_layout_expired` | P0 |
| **F-EXP-06** | 用户在更新过程中离开预览页（关闭/回书架）导致无法 consume：下次进入同 trip **不自动导出**（flag 已无或过期）；若仍 pending，行为同 C2 | P0 |

### 4.3 状态机（产品可见）

| 状态 | 用户可见文案（建议） | 可点导出？ |
|------|----------------------|------------|
| idle | — | 是（无 pending） |
| blocking_modal | Modal 打开 | 否（等选择） |
| updating_layout | 「正在更新版面…」 | 否（busy） |
| starting_export | 「开始导出长图…」/ 现网 running | 否 |
| export_running | 现网「正在保存…」等 | 否 |
| export_done | 成功态 + §7 发群引导 | 是（再导出） |
| update_failed | 「版面没有更新成功，长图尚未开始」 | 是（仍 pending 则再拦） |

## 5. 拦截 Modal 与「仅更新」旅程（P0）

### 5.1 Modal 文案修订（相对精修 V1 §4.3.1）

| 项 | 精修 V1（现行） | 导出门面 V1（本版） |
|----|-----------------|---------------------|
| 标题 | 版面尚未更新 | **导出前先更新一下**（D-EXP-01 · 已确认） |
| 正文 | 你改过精选或拼图，导出前需先更新版面，否则长图仍是旧版。 | **保留**（人话已够；可微调用「改过精选或拼图」） |
| 主按钮 | 更新并导出 | **不变** |
| 次按钮 | 仅更新版面 | **不变** |
| 取消 | 取消 | **不变** |
| 层级 | 主 / 次 / 幽灵 stacked | **不变**；禁止三颗同权 |

**决策 ID**：**D-EXP-01**（标题改分享者向）· **D-EXP-02**（不增加第四按钮）。

### 5.2 「仅更新版面」之后（F-EXP-07）

| 项 | 规格 |
|----|------|
| 时机 | rerender **成功**且未走续跑导出（整页刷新后） |
| 反馈 | Task Dock **残留**下一步（`showNextStepHint`）：主句「版面已更新」· 副句「再点「长图」即可导出」；长图钮轻高亮；无 Dock 时降级 toast |
| 禁止 | 再弹 Modal；禁止自动开始导出；**不以 ≤2s 闪消失为唯一反馈**（评审 MF-EXP-02） |

### 5.3 「稍后」与再次导出（沿用精修 V1）

- Task Dock「稍后」可 dismiss 视觉，**不清除** `layoutPending`。  
- 再次点长图仍拦截。  
- **F-EXP-08**：pending Task Dock 展示时副文案含 **「导出时仍会提醒」**（降二次惊吓）。

## 6. Dock 导出门面认知（P0 / P0.5）

### 6.1 词与标签一致（F-EXP-09）

| 表面 | 规格 |
|------|------|
| Dock 主钮可见标签 | **「长图」**（与精修 V1 评审一致：图标+文字） |
| `aria-label` / tooltip | **「导出长图」**（完整动作名，供读屏与悬停） |
| 成功/进度文案 | 可使用「长图已保存」「正在导出长图」——「长图」为产品词，「导出」为动作 |

禁止在 Dock 主钮上再写满「导出长图」与旁路「长图」两套可见主标签并存（以「长图」为可见主标签）。

### 6.2 首访脉冲（F-EXP-10 · D-EXP-06）

| 项 | 规格 |
|----|------|
| 脉冲目标 | **仅导出（长图）钮**；精修不脉冲 |
| 停止条件（满足任一） | ① 用户已点击过 **长图主钮**（**不含**仅打开 ▾）；② 本 trip 已成功导出过长图；③ `localStorage` 已写「导出门面已提示」（仅由①/②写入，**禁止首屏零点击写入**） |
| 禁止 | 每次进入预览都重新无限脉冲；打开导出设置 ▾ **不**停止脉冲 |
| 存储 | `travelogue.studio.exportPulseSeen`（全局）· `travelogue.studio.exportPulseSeen.{tripId}` |

### 6.3 导出钮色彩（F-EXP-11）

- 导出保持 **金色主 CTA**。  
- `layoutPending` 时红点在 **精修**（或 Task Dock），**不要**把导出钮改成警告红。  
- `longshotStale` 可用现网 stale 样式，但不得压过 layoutPending 主待办（D-REF-18）。

### 6.4 图标盲测收口（F-EXP-12）

| 项 | 规格 |
|----|------|
| 动作 | 完成精修 V1 **SF-02**：5 人盲测返回 / 放映 / 精修 / 长图 |
| 门禁 | 「精修」「长图」≥4/5 正确指认 |
| 未达标 | Follow-up：提高笔尖对比度或长图箭头识别度；**不**为此重开 IA |

### 6.5 导出 ▾（维持）

- 默认平台：微信群（`wechat_chat`）。  
- 清晰度 / 按章·完整 / 其他平台 → ▾ 内；**80% 路径不强制展开**。

## 7. 导出成功：发群引导（P0）

### 7.1 原则

长图 **落盘成功** 是工程终点；产品终点是用户 **知道如何发到微信**。本机 Studio **不承诺**系统级「一键发群」API；用文案引导即可。

### 7.2 需求（F-EXP-13）

| 项 | 规格 |
|----|------|
| 触发 | `longshot_export_success` 对应 UI 成功态（结果抽屉 / 完成条） |
| 主句（默认 · Windows 本地 Studio） | **「已保存到本机 · 拖进微信群即可」** |
| 多段长图 | 主句不变；可附「共 n 张，可按章发送」 |
| 次要动作 | 维持现网「在文件夹中显示」等；不取代主句 |
| 分端预留 | 文案表按 `platformHint` 可扩展（电脑微信 / 手机相册）；**P0 只交付默认句** |

**决策 ID**：**D-EXP-03**（成功引导为 P0 必达，不算渠道功能）。

## 8. 观测与埋点（P0）

### 8.1 新增 / 补齐事件

在现有 `longshot_export_*` 之外，至少具备：

| 事件名 | 触发 | 主要属性 |
|--------|------|----------|
| **`longshot_export_blocked_pending`** | pending 时点导出弹出 Modal | `trip_id` |
| **`layout_update_and_export`** | 用户点「更新并导出」 | `trip_id` |
| **`layout_update_only`** | 用户点「仅更新版面」 | `trip_id` |
| **`layout_update_failed`** | rerender 失败（含拟续跑被取消） | `trip_id` · `error_code?` |
| **`export_after_layout_consumed`** | consume 成功开始导出 | `trip_id` · `latency_ms?` |
| **`export_after_layout_expired`** | flag 过期丢弃 | `trip_id` |
| **`export_after_layout_trip_mismatch`** | tripId 不一致丢弃 | `flagged_id` · `current_id` |
| **`longshot_success_share_hint_shown`** | 成功态展示发群引导 | `trip_id` · `segment_count?` |

现有 `longshot_export_start` / `success` / `fail` **保留**；`start` 可增加 `from: "direct" | "after_layout"` 以区分路径。

### 8.2 运营解读（非功能，供周报）

| 信号 | 解读 |
|------|------|
| `blocked_pending` 过高 | 半生效教育不足，或 ★/拼图误触过多 |
| `update_and_export` 完成率低 | 续跑可靠或状态感知有问题（对照 G-EXP-01） |
| `update_only` 高且后续无 `export_start` | 「仅更新」后下一步提示偏弱 |

## 10. 验收标准（AC-EXP-*）

| ID | 用例 | 期望 |
|----|------|------|
| **AC-EXP-01** | pending ·「更新并导出」 | 立即 busy；可见「正在更新版面…」；不可连点 |

| **AC-EXP-05** | flag tripId ≠ 当前 | 不自动导出；flag 清除 |
| **AC-EXP-06** | flag 超过 TTL | 不自动导出；打点 expired |

| **AC-EXP-10** | 脉冲 | 满足停止条件后再次进入预览 **不再脉冲** |
| **AC-EXP-11** | 长图成功 | 可见「已保存到本机 · 拖进微信群即可」（或多段补充） |

| **AC-EXP-13** | SF-02 | ≥4/5 指认「精修」「长图」；结果回写 ACCEPTANCE |
| **AC-EXP-14** |「稍后」后再导出 | 仍拦截；pending 未清 |
