## 0. 一句话结论

现网裁切对**人像特写还可用**，对**全身照 / 环境人像几乎无效**——不是非标槽把算法用坏了，而是算法只保护「脸框外扩到锁骨」，切脚、切膝、切环境本来就不算失败。

本项目需要的算法优先级是：

1. **硬约束 1**：人体尽量不被切。
2. **硬约束 2（兜底）**：人体保不住时，至少人脸不被切（现网 `face_hard_gate`）。
3. **软目标**：人体在窗内时，裁切要好看（头上留白、视线空间、不切关节、环境人像不往人脸上推近）。

**不要**用端到端审美网络（GAIC / A2-RL）替换 `crop_solver`。几何求解器留下；换的是保护对象（人框 vs 脸框）和窗内构图偏置。

## 1. 产品需求（本备忘录的钉）

装配照片到非标宽高比槽位时（杂志拼图、卡片、封面、导出），用户不可接受的失败是：

| 失败 | 典型观感 | 现网是否当错误 |
|------|----------|----------------|
| 切脸 | 半张脸、削顶、切下巴 | **是**（`face_clipped` → 可 contain） |
| 切人体 | 切脚、切膝、腰斩、手出画 | **否**（人框不存在；半身 protect 装不下只是软信号） |
| 环境人像被「推近」 | 风景没了，只剩一个小头 | **否**（焦点在脸上就会把场景裁掉） |
| 无人物死中心 | 地平线/主体贴边 | 部分（无脸时 `(0.5, 0.45)`） |

目标策略：

```
if 检出人体:
    先求一个 cover 窗，使人框（发顶→脚，含少量 padding）完整在窗内
    若可行 → 在松弛量里做「人体构图」偏置（§6）
    若不可行 → 降级为人脸硬闸（现网行为）
               仍不可行 → contain / 换槽（受 bleed 名单约束）
else if 仅检出人脸:
    走现网脸保护（特写路径）
else:
    风景显著性或中心裁
```

「无法避免切人体」时**允许切身体，但不允许切脸**。切身体时仍应避开关节（§6.3），这是兜底路径的观感底线，不是第一优先。

## 2. 现网 As-Is（为何特写行、全身不行）

### 2.1 流水线

1. Ingest：`subject_detect.analyze_subject` → Haar 正脸 + 侧脸，`minSize=48`。
2. 保护框：`protect_box_from_faces`，相对**脸高**外扩  
   上 0.35 / 下 1.6 / 左右 0.25 → 保护高度 ≈ **2.95× 脸高**（发顶到锁骨/上胸）。
3. 装配：`crop_solver.solve_slot_focal` 在 CSS `object-fit:cover` 下只**滑动** `object-position`，不额外放大。
4. 硬闸：只有 `face_clipped` 才允许 contain flip；protect 装不下是软信号。  
   注释原文大意：半身 pad 经常比窄窗高，但脸仍能装下——**不得**因此破坏满幅合同。
5. 焦点默认 `(0.5, 0.45)`；有脸时焦点在脸并集中心，**无头上留白 / 视线空间**。

### 2.2 几何事实（全身照）

成人全身约 7.5–8 头身。脸高 ≈ 身高的 1/8。  
保护框 2.95× 脸高 ≈ 身高的 **37%**（头+胸），到不了腰，更到不了脚。

若人约占画面高度 70%，protect 只约占画面 **26%**。cover 窗通常比它大 → 脸很容易在窗里 → `feasible=true`、`face_clipped=false` → **算法报告成功，观感切脚**。

环境人像脸面积常见 **0.02–0.04**（见 SSG 验收记录；look 门曾用 0.15，旅行全身几乎全被挡）。Haar 再漏检小脸 → 退回中心裁，效果「几乎没有」。

### 2.3 非标槽如何放大问题

cover 只切「比例多出来的那一条边」：

- 竖幅全身 → 横槽 / 近方槽：切上下。求解器保脸 → **切脚**。
- 横幅环境人像、人在三分线上 → 竖槽：切左右。漏检则切人；检到则把人推到窗中心、**裁掉环境**。

特写有效，是因为脸 ≈ 主体，2.95× 外扩刚好罩住头肩，求解器被硬约束逼着挪窗。全身/环境无效，是因为**主体已经不是脸**。

## 3. 外部算法谱系（与本需求的匹配）

自动裁切不是一个问题。和本项目相关的有四类：

| 族 | 做什么 | 对本项目 |
|----|--------|----------|
| A 启发式 | 边缘 / 熵 / 肤色 / 三分法（smartcrop.js） | 仅适合**无人**风景 fallback |
| B 人脸中心 | 最大脸居中、脸框外扩 | 特写可用；**全身必切脚** |
| C 人体 / 姿态 | YOLO `person`、Pose 33 点、实例分割 | **全身硬约束的正确输入** |
| D 审美学习 | GAIC / A2-RL / GAFIC | 风景或可打分；无「整个人必须在画里」；只可给 **已通过人/脸硬闸的候选窗** 排序 |

生产 CDN（Cloudinary `g_auto`、imgix `crop=faces,entropy,center`）是回退链：脸 → 主体 → 显著性 → 中心。本项目要把「主体」从脸升级为**人体**，并加景别分流，而不是再做一条 `g_face`。

## 4. 开源项目对照（回答「是不是都只对大脸好」）

**是：凡按脸工作的，全身/环境一样差。** 换 YuNet/RetinaFace 只能减少漏检，不能把保护范围从头肩变成整个人。

| 项目 | 方法 | 全身 / 环境 | 建议 |
|------|------|-------------|------|
| [autocrop](https://github.com/leblancfg/autocrop) | OpenCV 最大脸居中 | 差：宽槽切脚 | 头像批次，不采用 |
| [smartcrop.js](https://github.com/jwagner/smartcrop.js) / [smartcrop.py](https://github.com/smartcrop/smartcrop.py) | 边缘+饱和+肤色+三分；`boost` 可挂脸 | 不稳定；肤色对旅行照不稳 | **无人**页 fallback |
| [cropimage](https://github.com/haofanwang/cropimage) | MTCNN + 显著性；`completeness` 脸 vs「人」 | 「人」仍多半是脸再扩，不是 COCO person | 可借鉴开关语义，不直接当求解器 |
| [face-crop-plus](https://github.com/mantasu/face-crop-plus) | RetinaFace 对齐 + 超分 | 更差（故意做成大头） | 不采用 |
| [FaceCrop](https://github.com/hlb/FaceCrop) | MediaPipe + 去背 | 抠像，不是 cover | 不采用 |
| [GAIC](https://github.com/HuiZeng/Grid-Anchor-based-Image-Cropping-Pytorch) | 网格锚点美学 | 无人体硬闸 | 仅对人/脸安全窗打分 |
| [zensally](https://github.com/imazen/zensally) | UltraFace + MicroSalNet + 求解器 | 脸+显著性，人体仍弱 | 对照「一次分析多比例」，不换栈 |
| [ImgCropCV](https://github.com/vlasvlasvlas/ImgCropCV) | YOLO-World + OpenCV 显著性 | **人框可用** | 检测层最值得借鉴 |
| [react-face-centered-portrait](https://github.com/Furkan-Demir/react-face-centered-portrait) | MediaPipe + 三分头上留白 | 近景竖屏 | **构图偏置**最小参考 |
| YuNet / [libfacedetection](https://github.com/ShiqiYu/libfacedetection) | 轻量人脸 | 只解决漏检 | 脸兜底检测替换 Haar |
| RetinaFace / InsightFace | 野外人脸 SOTA | 同上 | 旅行小脸质量优先时用 |
| MediaPipe Pose | 33 点 + 可选分割 | **关节 / 全身范围** | 构图与「不切关节」 |
| Ultralytics YOLO `person` | 人体框 | **保护框权威输入** | P0 检测首选 |

论文（A2-RL CVPR 2018、GAIC/GAICD、GAFIC 2026）评测几乎不把切脸/切人当硬失败，数字不能当相册验收。

## 5. 本项目目标算法（建议形态）

权威几何仍是 `crop_solver`（cover 窗 + `object-position` + bleed 名单禁止乱 contain）。增量分三层：**检测 → 景别 → 求解**。

### 5.1 检测（ingest 落盘，装配只读）

每个 asset 建议有：

| 字段 | 含义 |
|------|------|
| `faces[]` | 现网已有；检测器建议 Haar → YuNet（CPU） |
| `personBox` / `personBoxes[]` | 人体轴对齐框（YOLO `person` 或 Pose 外接框） |
| `protectBox` | **按景别生成**的求解输入（不再等于「脸×2.95」） |
| `shotType` | `closeup` / `half` / `full` / `environment` / `none` |
| `focalPoint` | 构图偏置后的 prefer，不是检测框中心 |

群像：人框并集；脸并集作兜底。误检小框需面积门（SSG 已见 Haar 噪点把人数抬过 4）。

### 5.2 景别（决定保护谁）

用脸面积、人面积、人高/图高的粗规则即可，不必先上分类网络：

| `shotType` | 经验条件（待狗粮标定） | `protectBox` |
|------------|------------------------|--------------|
| `closeup` | 主脸面积 ≳ 0.12，或无人框但脸大 | 现网脸外扩（头肩） |
| `half` | 人框在，人高/图高中等，脚不在框下沿 | 肩髋（Pose）或人框上 60% |
| `full` | 人高/图高 ≳ 0.45，且脚近画面下沿 | **整个人框** + 发顶/脚底少量 pad |
| `environment` | 有人，但人面积 ≲ 0.15（或脸 ≲ 0.04） | 人框必须在窗内；**不要**把人放大到填槽 |
| `none` | 无人无人脸 | 显著性 / smartcrop / 中心 |

阈值必须实拍标定，上表只作起步。SSG 已提示全身脸面积 0.02–0.04。

### 5.3 求解优先级（硬 → 软）

```
1. 人体完整 ⊆ cover 窗     # full / half / environment
2. 否则 人脸完整 ⊆ cover 窗  # 现网 face_hard_gate
3. 否则 contain（非 bleed 模板）或换槽（EDC / AEL 失败链）
4. 在 1 或 2 的可行松弛里，最小化「难看」代价（§6）
```

`environment` 的「好看」与 `full` 相反：人完整即可，**禁止**为了把人放中间而切掉大块场景。实现上：人框是硬包含，prefer 仍接近画面几何中心（或场景显著性），不是人中心。

`full` 在横槽里人框高度 > 窗高 → 步骤 1 不可行 → 步骤 2 保脸（会切脚）。这是产品接受的兜底，应打 telemetry（`bodyClipped` / `fellBackToFace`），并优先 **换更竖的槽** 而不是默默切脚。

## 6. 人体怎么裁才好看（软目标，硬约束满足之后）

cover **不放大**，松弛量 = `|1 - slotAR/assetAR|` 决定的可滑动距离。好看 = 在可行区间里选 `focal`，不是另开一套裁切。

### 6.1 特写 `closeup`

- 眼睛约在窗的上 1/3（headroom），不要脸垂直居中。
- 参考：react-face-centered-portrait 的 `ruleOfThirds`。
- 现网 `upper_body_crop_box`（侧 0.85 / 下 2.6 / 上 0.35）可继续服务 look / 头肩 ROI，与装配 protect 解耦。

### 6.2 全身 `full`

- 人在窗内垂直位置：头上留一点天，脚下留一点地；**不要**脚贴下边、头贴上边。
- 横构图有松弛（切左右）时：人不要死贴中缝；走/看的方向多留空（looking space）。无朝向则略偏三分线。
- 群像：并集居中偏上，不要只保最大脸把其他人切出画。

### 6.3 不得不切身体时（人脸兜底）

摄影常识：裁在关节**之间**，不要裁在关节上。

| 优先避开 | 相对可接受 |
|----------|------------|
| 踝、膝、髋、腰、肘、腕、脖 | 大腿中段、小腿中段、胸下（半身） |

有 Pose 时：若窗下沿落在踝/膝附近，将下沿移到小腿中或改 contain/换槽。无 Pose 时：兜底只保证脸完整，切点不做精细避让（P1 再加）。

### 6.4 环境 `environment`

- 硬：人框 ⊆ 窗（漏人比切一点天更糟）。
- 软：窗尽量接近「整图 cover 的默认位置」；显著性可微调，但**人权重低于场景**。
- 禁止：按脸中心滑动导致只剩人物特写。

### 6.5 明确不做

- 用 GAIC 当主求解器（会为「好看」切人）。
- 用去背/分割当 cover 构图（那是抠图）。
- 拆掉 bleed 模板的满幅合同（`screen-landscape-1` 等）去 contain 保半身框。
- 把「protect 装不下」重新升级成无条件 contain——那是现网已经踩过的满幅破坏。

## 7. 建议落地顺序（供后续 PRD 拆波）

本备忘录不冻结里程碑。若立项，建议：

| 波 | 做什么 | 可验收的变化 |
|----|--------|----------------|
| **P0** | 人体检测落 `personBox`；`full`/`half` 用其人框作 protect；`body_clipped` 遥测；脸检测 Haar→YuNet | 全身进横槽时不再「报成功却切脚」而不自知；特写不回退 |
| **P1** | 景别 `shotType`；`environment` 人框硬包含 + 焦点不跟人走；全身窗内 headroom | 环境人像不再被推成大头 |
| **P2** | 步骤 1 不可行 → 脸兜底（现网）+ **换槽优先于切脚**（挂 EDC/AEL 失败链） | 非标槽宁可留白/换模板，也不默默腰斩 |
| **P3** | Pose 避关节；无人页 smartcrop/显著性；可选：对人/脸安全窗做轻量美学排序 | 兜底切身也不切在膝盖上 |

**P0 不要换求解器。** 只换 `protectBox` 的生产函数，以及 `crop_safety` 增加 `bodyClipped`（与 `faceClipped` 并列）。`face_hard_gate` 保持不可关。

检测选型起步：CPU 上 YOLO-Nano / YOLO-World `person` + YuNet 脸。Pose 放到 P3，避免 P0 过重。

## 8. 与现网合同的边界

| 现网钉 | 本备忘录态度 |
|--------|----------------|
| `crop_solver` 是裁切权威（AEL D-AEL-11，禁止 export import `msa_fit`） | **保持**；人框只是新输入 |
| EDC：现网人像求解默认可达，W1 只控增量 | 人体保护若默认开，应视为**新增量**，需独立开关 + 盲评，不能偷偷替换脸路径 |
| `face_hard_gate` 不可关 | **保持**，作为第 2 优先 |
| bleed 名单禁止 contain flip | **保持**；人体不可行时换槽，不在名单模板上强 contain |
| MSA 默认 off | 不把本算法绑到打开 MSA |

## 9. 未决问题（立项 PRD 时要答）

1. `personBox` 多人体：并集硬保是否在拥挤街拍上导致窗永远不可行、过度 contain？
2. 坐姿 / 躺姿 / 只有半截人入画（构图故意切脚）：景别会误判 `full` 而「补脚」失败——是否要「框已贴边则视为故意出画、降级为半身」？
3. 人体检测与 NAS（无云端 AI）：模型是否本地捆绑、体积与 CPU 预算？
4. 盲评样本必须按景别分层（特写 / 全身 / 环境 / 无人），不能再用「有没有切脸」当唯一分。
5. 中文名文档 vs `RESEARCH-CROP-*.md`：本文件按讨论命名；若升格 PRD，建议英文代号（例如 **BSC** Body-Safe Crop）。
