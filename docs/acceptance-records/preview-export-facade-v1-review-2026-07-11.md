## 3. 分角色意见摘要

### 3.1 产品

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 不扩精修 IA；C1～C3 与 80% 零精修路径强对齐；D-EXP-02/03/07 应拍板为铁律 |
| ✅ 赞成 | 里程碑序 M1→M2→M3→M4 正确；No-Go 三条够尖 |
| ⚠️ 担心 | SF-02 + 全量埋点绑同一硬 Go，易拖死续跑可靠性价值 |
| ⚠️ 担心 | 「更新并导出 ≥80%」缺样本 N；刷新 busy 只在风险表、未进 AC |
| 📌 建议 | **拆两道门**：Reliability Go（可发布）vs Theme Complete（+ SF-02 + 周报可读） |

**北极星对齐**：约 8.5/10 — 分享者路径是加固非添负；成功引导闭环刚够用，缺「是否真懂拖进微信」的定性种子项。

### 3.2 UI / UX

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 金色长图 CTA + pending 红点在精修/Task Dock = 正确视觉语义 |
| ✅ 赞成 | Dock 可见「长图」+ aria「导出长图」分层正确；Modal 三钮层级正确 |
| ✅ 赞成 | 标题「导出前先更新一下」分享者向，惊吓感低于「版面尚未更新」 |
| 🔧 建议 | 成功态主句须为**第一可读行**；「在文件夹中显示」/多段说明不得同权并列 |
| 🔧 建议 | 脉冲停止条件③「已看过提示」若首屏即写，可能零点击灭脉冲 — 须收紧 |
| 🔧 建议 | 补 2～3 帧轻线框（busy / 仅更新后 / 成功主句）；不阻塞编码，48h 内补齐 |

### 3.3 用户体验

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 产品终点从落盘拉到「愿发出」正确；失败双否定文案（版面未成 + 长图未开始）优秀 |
| ⚠️ 关键 | 半生效教育几乎全压在 Modal；点导出前须能感到「版面有更新」（Task Dock/红点进 AC） |
| ⚠️ 关键 | 刷新空窗 = 分享者「卡死」主断点；「仅更新」≤2s 提示后易再次迷路 |
| ⚠️ 关键 | 「稍后/取消」后再拦 = 二次惊吓；F-EXP-08 偏弱 |
| 📌 种子验证 | 5 人任务式（3 分享者 + 2 编辑者）+ 出声想；≥2 人刷新或仅更新迷路 → No-Go 再测 |

### 3.4 用户动作流程 · 信息提示

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 主路径提示密度合适、不滥 Modal；漏斗骨架可用 |
| ⚠️ 关键 | **离开后 flag** 语义歧义（清 flag vs 靠 TTL）→ 可能幽灵续跑 |
| ⚠️ 关键 | 失败文案未按意图分叉（仅更新失败不该说「长图尚未开始」） |
| ⚠️ 关键 | storage 禁用降级未进 F/AC；consume 须立刻清 flag |
| ⚠️ 埋点缺口 | 缺 Modal 取消/Esc、leave 清旗、`layout_update_failed.intent`、仅更新回流 join 约定 |

## 7. 发布门禁（修订建议）

### Reliability Go（可合入 / 可发布）

| 标准 |
|------|
| MF-EXP-01～08、11 落地；AC-EXP 主路径（含刷新 busy、失败分叉、仅更新残留、发群主句）通过 |
| C1～C3 不回归；精修 V1 AC-REF-02 / UX-REF-80-01 绿 |
| 埋点最低四件套 + MF-EXP-10 最小集可观测 |
| **不要求** SF-02 已出报告 |

### Theme Complete（主题完结）

| 标准 |
|------|
| SF-02 ≥4/5 指认「精修」「长图」；未达标仅图标对比度 Follow-up |
| 种子 5 人任务式：刷新空窗 / 仅更新迷路 / 成功复述「拖进或发给微信」达标 |
| 周报漏斗公式可读（主钮完成率 · 仅更新回流） |

### No-Go（任一即停）

| 标准 |
|------|
| 仍可 pending 静默旧导出 |
| 「更新并导出」失败无提示、用户以为已导出 |
| 成功态无发群主句或主句被次要动作淹没 |
| 离开后再进同 trip 发生非预期自动导出 |

## 8. 会议结语

各方一致认为：精修 V1 已堵住「半生效导出旧图」；本主题补的是 **「点了之后人还在不在路上」** 与 **「落盘之后人知不知道怎么发」**。

最大获得感预期：

1. 刷新/续跑不再像卡死或幽灵导出  
2. 「仅更新」后不再失联  
3. 成功句把商业终点接到微信  

**下一步建议**：

1. 产品确认本纪要 → PRD 升 **v1.1**（回写 Must-Fix / D-EXP-08/09 / 两道门）  
2. 开写 `IMPLEMENTATION-PREVIEW-EXPORT-FACADE-V1.md`（按 M-EXP-1→4，M5 并行约人）  
3. 设计 48h 内补 SF-EXP-01 轻线框  
4. 可靠性手测通过后合入；Theme Complete 收 SF-02 + 种子复述
