## 1. 全场共识

1. **方向正确**：扩展现有 `cover_engine`、增值放在 **Closing + Pairing**、不做完整 Admin、MLLM/VL 默认关——与 V6 决议一致，值得立 Phase。  
2. **V1 不能只做引擎搬家**：若 B2 Pairing 因时序/级联错误落空，交付会被看成技术债 PR（PRD §1.3 自知风险）。  
3. **完整 Admin 不做**：通过（样式量级小；真正产品化的是 Studio 换首尾图）。  
4. **对用户禁用黑话**：界面主称「封面 / 封底」，禁止暴露 Bookends / Opening / Closing / Pairing。  
5. **进开发前须冻结契约**：Closing 解析相位、PAIR-H1 极小册策略、单一锁字段、盲评手册与 10 本清单、换封面→封底级联。

## 4. 重要改进项（建议 v0.2 合入）

1. **收窄 B1**：仅 facade + re-export + schema 预备；禁止 B1 大搬家 `joint.py`；G-BE-01 改为 B2 门禁。  
2. **PAIR-H2 信号源**：写清 burst / near-dup / 时间窗，避免死规则。  
3. **`confidence` 定义**：联合低置信 / closing degraded / 合成公式写死。  
4. **与 Peak Moment 互斥顺序**：谁先锁谁，避免三图位抢图。  
5. **Studio 合页预览**：封面+封底同时可见，禁止两块孤立卡片。  
6. **mobile/web**：V1 封底只服务 Web/auto；Mobile 封面折叠「可能不同」；文案写死。  
7. **V1 仅 1 款封底样式时不做样式切换 UI**。  
8. **§15 补决议行**：把 OQ-BE-01/03/04/06 与 H1 极小册策略升格为 R-BE-xx。  
9. **主路径 degraded 体感**：自动成书用户如何感知「弱收束/无封底」。  
10. **成对正反例（≥6 组）升为 B0 Go/No-Go 附件**。

## 7. 分席要点摘录

### 产品
- 防「引擎叙事」盖过可感知差异。  
- 盲评基线空洞会导致无限 waiver（重复封面选片 signoff 失败模式）。  

### 架构
- Bookends 挂在 `cover_engine` 正确。  
- **分层错误风险**：curate 持久 Closing vs layout 后才可得的占用信号。  
- 双锁字段 + render fail-open 现算 = 多真相源。  

### 算法
- 现网 closing 已有封面排除+unused；若无可靠 face/景别特征，软对比增量有限。  
- H* 过硬 → 小册大量 degraded → 盲评可能变差。  
- `_mllm_cover_logit_boost` 建议 B1 即标遗留并限制 shortlist≠cover。  

### UI/UX · 用户流程
- 换封面级联是硬缺口。  
- 合页预览是成对编辑的最小交互。  
- unlock 文案改为「恢复自动挑选」。  

### 用户体验 · 视觉
- 「明示 Web/Mobile 不同」不等于可完成任务；需折叠展示 mobile 缩略。  
- 压字可读截图应进封面盲评附属。  
- 空镜/暮色加分设上限，防「糊一片当收束」。
