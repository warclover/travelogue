## 3. 分角色意见摘要

### 3.1 产品

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 试用单一需求源；铁律锁死不加能力面；P0 切法先减惊吓；门禁可 bypass；附录 B 不进本主题门禁 |
| ❌ 阻塞 | **门禁主路径悬空**：COPY-05「改标题并导出」依赖落盘，EDIT-* 却标 P1——改完仍不落盘比不做门禁更伤信任 |
| ❌ 阻塞 | **与 Facade 双轨**：§7 大量 `= F-EXP-*` 又写「冲突取更严」无矩阵；须写死 Facade Reliability 前置 + 补丁表 |
| ⚠️ 高 | C4 vs 默认「点字可改」须改写边界；P-TRU-07（掉壳/顶栏差分）覆盖不足；正文复读被砍却附录写全覆盖 |
| 📌 拍板 | **D-TRU-11**：先 C2 再门禁，禁止合并新 UI；**D-TRU-12**：P0-B/C 并入 Facade；Trust = 壳+Share+门禁+杂志名写路径 |

### 3.2 开发

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 合同继承清楚；范围克制；验货/Share 有明确代码落点 |
| ⚠️ 现实 | Facade M-EXP-1～4 **已落地**——§12.3「未开工合并」过时，应按**增量补丁**重写 |
| ⚠️ 高风险 | P0-B：无 `exportSideEffect`；`refreshStaleHint` / `copy-saved→showStaleHint` 与「文案不置 pending」冲突 |
| ⚠️ 规格缺口 | 精修开/关权威状态、主警告边界、启发式规则表、跳首页复现路径、续跑 platform 合同（TEC-TRU-01～12） |
| 📌 建议 | 「跳首页」未定位前勿进 P0 硬 Go；主题 Go「敢发≥4.5」降 Soft；P0-D 勿膨胀进 P0 算法 |

### 3.3 UI / UX

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 验货壳藏控件 = 精修 V1 落地补丁；门禁软拦 vs 版面硬拦须可辨；成功主句第一可读行 |
| ✅ 文案 | 附录 C 大体通过；「杂志名」→「现在的标题」；破题字号 > 说明句 |
| 🔧 线框 | 建议补 **5 帧**；**帧 2（门禁展开）+ 帧 3（成功 vs stale）** 优先；P0-A **不阻塞**编码 |
| ❌ 反对 | 门禁做成第三种「系统错误」风；验货默认加常驻「发现精修」hint |

### 3.4 测试（QA）

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | C4～C7 与问题源清晰 |
| ❌ 验收 | §11 多为口号；缺 Given/When/Then、夹具、负例、故障注入；**P0 Go 不可审计** |
| 📌 要求 | 补 COPY-07/08、EXP-05、STALE-02/03、SHARE-03/05/06、TEL-*；样本 **N≥3**；挂 UX-P5-80-01 / C2 / Facade 加严对照 |
| ⚠️ 假绿 | CSS 隐藏仍可点；静态文案存在≠成功态可见；单 trip 单次；模拟分当主题 Go |

### 3.5 用户体验

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 四伤对症；愿发出去终点正确 |
| ⚠️ 新惊吓 | 门禁误杀；layout+门禁双 Modal overload；bypass 导致「敢发虚高、群里后悔」 |
| ⚠️ Share | DOM 零工程 ≠ 接收方敢翻；缺接收方剧本 AC |
| 📌 建议 | 门禁展示封面缩略+标题；bypass 后成功态回声标题；严重乱码首次偏强制改名；编辑者主题目标改为杂志名路径 ≥4（全角色 ≥4 降 stretch） |

## 7. 实施归属（拍板）

```text
Facade 增量 PR（或 Facade IMPLEMENTATION 续页）
  └─ P0-B 成功 vs stale / exportSideEffect
  └─ P0-C 续跑加严（禁跳首页探针、断服文案、platform 保持）

Trust IMPLEMENTATION（独立）
  └─ P0-A 验货壳 + Share 真只读
  └─ P0-D 文案门禁 + 杂志名写路径（P0）
  └─ P1 图说路径 + 平台话术
  └─ P2 首页降噪（可并行）
```

**建议开工顺序**：P0-A →（并行）P0-B 根因 → P0-C 增量 → P0-D 门禁。
