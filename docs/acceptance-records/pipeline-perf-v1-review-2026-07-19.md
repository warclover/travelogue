## 2. 总评（一句话）

> **证据链扎实（埋点 + 微基准 + 串并行对比三层互证）、瓶颈定位无争议、WS1–WS5 与 P0–P3 完整对应；阻塞不在方向，而在四条合同未钉死：① Q1 严格等价与 R1.3/R1.4 参数变更自相矛盾，须做等价性分级 ② srcset「pending 标记」污染产物合同，须改派生图清单 sidecar ③ materialize 不得新增公开 pipeline 状态 ④ NIMA 预热的 CPU/内存资源治理缺失。补完 Must-Fix 后可开 M1。**

**表决**：六席一致 **Conditional Go**。

| 角色 | 表决 | 备注 |
|------|------|------|
| 架构 | Conditional Go | D2/D3/D5 必须修订后再写 IMPLEMENTATION |
| 算法 | Conditional Go | D1 等价性分级是前置；R2.3 flag 默认关直至 SSIM 报告 |
| 测试 | Conditional Go | AC-PPF-07 必须拆分；绝对时长退出 CI 门禁 |
| 用户体验 | Conditional Go | D6 导出门控二选一；R5.1 两态进度语义 |
| UI / UX | Conditional Go | 换片补图 loading 预算与超量降级 |
| 典型用户 | Conditional Go | 强烈支持提速；红线是「选片和焦点一张都不能变得没道理」 |

**M1 是否阻塞**：不阻塞。§5 Must-Fix 已于 2026-07-19 回写 PRD **v0.2**；**可开 M1**。

## 3. 分角色意见摘要

### 3.1 架构

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 瓶颈证据三层互证；WS 切分与依赖顺序清晰；不引入新依赖、Playwright/GPU Park 正确 |
| ⚠️ **D2 反对原案** | R2.1 在 `srcset` 条目上加 `pending: true` 会污染**产物 schema**（渲染上下文、导出校验、schema 校验器都读 srcset）。应改为：`srcset` **只登记已落盘文件**（沿用现有 `_missing_derivative_paths` 不变量），计划档位放独立派生图清单（asset 级 `derivedPlan` 或 trip 级 sidecar），物化完成后增量回写 srcset |
| ⚠️ **D3 修订** | `materialize_derivatives` **不得**成为新的公开 pipeline 状态（`STAGE_MIN_STATUS` / `stages_order` 面向 Studio/CLI 的合同不动）。应作为 lock_structure 之后的**后台步骤**与 narrate 并行（CPU-bound × network-bound 天然互补），render 前 join + 校验 |
| ⚠️ **D5 升格** | 并行 worker 内存护栏「仅写文档」不够：36MP × 10 workers 峰值可 3–4 GB。V1 须实现简单降额公式（按相册 `nativeWidth` 中位数降 worker 数）+ fallback 遥测 |
| 🔧 R1.1 | 先写失败复现测试（断言 stats 含 `ingestWorkers`）再修；根因报告作为 M1 出口物 |
| ✅ D1/D4/D6 | 赞成算法席/UX 席修订案 |

### 3.2 算法 / 版式

| 态度 | 要点 |
|------|------|
| ⚠️ **D1 · 内在矛盾（最重要）** | Q1「选片决策逐字段一致」与 R1.3 自相矛盾：`face_detect_max_edge 0→1024` 改变 faceCount/focal/salientBox → 锐度 v2 ROI → 美学分 → cull 分 → **决策必然漂移**。须做**等价性分级**：重构类改动（E-A）要求严格等价；受控参数变更（E-B：R1.3/R1.4）走阈值门槛 + golden trip **差异报告** + 独立 flag 可单独回退，不承诺零差异 |
| ⚠️ **D4 修订** | R4.1 NIMA 预热 V1 **只做重叠、不做换源**：预热线程输入与现状完全一致（原图路径 + `_ML_INPUT_SIDE=512`），保证分数 bit 级一致（缓存键 contentSig 不变）。「输入源改派生图」连同 |Δ|≤0.01 校验整体 **Park** 到 V2 |
| ⚠️ R2.3 | 金字塔缩放 flag 默认**关**；出具 ≥3 相册 SSIM 报告（含高频纹理样张：树叶/织物/文字）后再默认开 |
| ✅ R2.1/R2.2 | 强赞成：落选照片的 2400/3200 是纯白工；「延迟物化 + fail-closed」保产物完整性 |
| 🚫 本包勿碰 | beam 宽度、评分权重、cull 阈值、`_ML_INPUT_SIDE`、`webp_quality` |

### 3.3 测试 / 质量

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | golden trip 双跑可沿用 `arch_equivalence_check` 模式；shadow-diff 可沿用 TPC W1 基建 |
| ⚠️ **AC-PPF-07 拆分** | 按 D1 分级拆为 07a（E-A：严格等价，CI 门禁）与 07b（E-B：受控差异报告 + 狗粮复核签字，人工门禁）。混在一条必然出现「假绿或永远红」 |
| ⚠️ **MF · 绝对时长退出 CI** | AC-PPF-12 的 ≤5 min 属基准机手动验收；CI 只跑等价性 + 功能断言 + **相对回归护栏**（遥测 per-photo ms 分位数，超阈值报警而非红灯） |
| 🔧 故障注入 | R2.2 fail-closed 须测：删档后导出、物化中途 kill、refine 换片并发导出三个负例 |
| 🔧 环境 | 基准脚本固定相册 + 固定机器写入验收记录；测试用临时 trips_dir，勿依赖本机 `config.yaml` |

### 3.4 用户体验

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 「感知时间 ≤2.5 min」比端到端更重要；两态进度语义（可查看 / 导出就绪）方向正确 |
| ⚠️ **D6 二选一** | R5.1 导出门控不可「置灰**或**同步物化」两案并存：拍板**同步物化 + 现有导出进度条**（与 R2.2 fail-closed 同一机制），不置灰不禁用——用户视角永远是「点了就出」 |
| ⚠️ R5.1 | 「版面已就绪，可先预览」阶段书架卡片与预览页水印/徽标须一致，不得出现「预览可见但书架仍显示处理中」的分叉 |
| 🔧 | 并行降级对用户静默正确；狗粮模式 hint 保留 |

### 3.5 UI / UX

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 本包 UI 触点克制（仅 R5.1 + 补图 loading）正确 |
| ⚠️ 换片补图 | 单张同步补图 ≤3 s 预算合理；**超过 3 张**排队时切后台队列 + 徽标（「正在准备 N 张高清图」），禁止按钮长 loading 假死 |
| 🔧 进度文案 | 「照片处理中… / 版面已就绪，可先预览 / 高清图与导出准备完成」三段与现有 stage hint 体系（`stage_hints.py`）合并，不新增文案面 |

### 3.6 典型用户

| 角色切片 | 态度 |
|----------|------|
| 纯小白 | **强支持**：27 分钟会直接放弃；「先看到再等高清」符合心智 |
| 普通旅行者 | 支持；红线：选出来的照片和裁切焦点不能变得没道理（→ D1 的 E-B 狗粮复核） |
| 分享达人 | 支持；红线：导出物一张不能缺、清晰度不能降（→ Q2/Q3 + AC-PPF-06） |
| 手机端用户 | 中立；关注体积增幅 ≤12% 的分享流量成本（→ R1.4 预算） |

## 6. Should-Fix / Park

### Should-Fix（不挡 M1，进 M2/M3）

- `scanMs` 从 ingestMs 拆出独立埋点（观测 R3.1 收益）
- 并行池 spawn 预热：选相册对话框期间预启动 ProcessPool（掩蔽 Windows 冷启动 5–10 s）
- CLI `--progressive` 可选参数（与 Studio 行为对齐）
- R5.1 阶段文案并入 `stage_hints.py` 体系
- 基准相册固化（`perf_probe_*` 指定样本 + 机器指纹入验收记录）

### Park（明确不进本包）

- NIMA 输入源换派生图（V2 · 需 |Δscore|≤0.01 证明）
- libvips / GPU 编码 / 图像库更换
- Playwright 长图导出并行（独立立项）
- CLIP/clustering 优化（当前默认关闭）
- `webp_quality`、srcset 档位定义、`_ML_INPUT_SIDE` 等产物/分数合同
