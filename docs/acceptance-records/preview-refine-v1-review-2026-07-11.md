## 4. 分角色意见摘要

### 4.1 用户代表 · 分享者

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 「精修」比「编辑与设置」轻；首访脉冲打在导出，符合「我来就是发长图」 |
| ✅ 赞成 | 不打开精修也能走完，对齐真实习惯 |
| ⚠️ 担心 | P0 仍是四 Tab 时，若标题已改「精修」但里面仍是「文字/结构/排版/高级」，会短暂困惑 |
| ⚠️ 担心 | 拦截 Modal 若文案太工程（layout/pending），会以为出错 |

**诉求**：P0 过渡脚注一句人话即可；Modal 主按钮用「更新并导出」。

### 4.2 用户代表 · 编辑者

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 「更新版面」+ 导出拦截直接解决「改了精选导出还是旧的」痛点——**本主题最大获得感** |
| ✅ 赞成 | 笔形比齿轮更像「改杂志」 |
| ⚠️ 担心 | 「这页」依赖当前屏：封面/封底时侧栏空洞，不知去哪 |
| ⚠️ 担心 | 意图立即保存后，「按新意图重写」若不够显眼，会以为锚点没生效 |

**诉求**：空态引导到「这本」；重写按钮保持二次确认但位置要在锚点区下方可见。

### 4.3 UI / 视觉

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 现网书册/胶片齿孔/齿轮在 18px **过密、难辨、语义错位**；线描四件套方向对 |
| ✅ 赞成 | 导出保持金色；精修/放映中性色，层级正确 |
| 🔧 建议 | 笔形注意：斜笔在小尺寸易看成「/」——笔尖+笔杆对比要够；命中区仍 36×36 |
| 🔧 建议 | 「长图」二字可与图标并存（线框已示意）；纯图标导出在首次认知上弱于「长图」标签 |
| ❌ 反对 | 不要为「更艺术」加齿孔、折页阴影、双色描边 |

**结论**：采纳线框 Tab ⑩ 套件为 P0 视觉规格；实装后做 5 人盲测「四个图标各是什么」。

### 4.4 交互体验

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 保存矩阵清晰；「半生效可导出」必须死 |
| ✅ 赞成 | Task Dock「稍后」不清除 pending + 再导出仍拦——正确 |
| 🔧 建议 | 拦截 Modal 三按钮层级：主 = 更新并导出；次 = 仅更新；幽灵 = 取消。避免三颗同权 |
| 🔧 建议 | P0 改名后，Sheet 内凡「应用排版」一律替换为「更新版面」，避免一词两名 |
| ⚠️ 风险 | 文案立即存与「按新意图重写」并存时，用户可能连续点重写——需 busy/禁用 |

**结论**：P0 交互门禁 = 导出拦截 + 文案统一；焦点陷阱维持 v3 即可。

### 4.5 用户流程设计

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 两拍发布降低一次性改壳风险；先堵错误导出是正确排序 |
| ⚠️ 关键 | **过渡态旅程未画全**：P0 用户打开「精修」仍见四 Tab——需一页「过渡线框」或 PRD 脚注规格 |
| ⚠️ 关键 | G1 横幅与 Task Dock、导出拦截的**优先级栈**要写死，避免三块同时抢 |
| 🔧 建议 | 80% 路径点击预算复核：返回不计入；导出 1 次；有 pending 时允许 +1（更新并导出） |
| 🔧 建议 | 阅读视图上 Dock 放到 P1 再定，避免第一拍 Dock 变挤（现已 4 控件） |

**结论**：补「P0 过渡态」说明为 Must-fix；优先级栈写入实施清单。

### 4.6 产品

| 态度 | 要点 |
|------|------|
| ✅ 对齐 | 与 Phase 5 断裂 O / P5-3.7 / 80% 零编辑一致 |
| ✅ 范围 | 不碰 Share、不扩章标题 inline——边界清楚 |
| 📌 决策 | 图标套件纳入 **P0 第一拍**（与改名同发），不单开视觉债 |

## 8. 会议结语

各方一致认为：**「编辑与设置」收纳完成了工程整合，但心智未完成**；本主题用「验货默认 + 更新版面 + 精修笔形」补的是心智，不是功能堆砌。

**下一步建议**：

1. 产品确认本纪要 → 开写 `IMPLEMENTATION-PREVIEW-REFINE-V1.md`（按两拍拆任务）  
2. 前端按 P0：拦截 → 文案替换 → 图标与改名  
3. 设计 48h 内补 SF-01/03/04 线框帧
