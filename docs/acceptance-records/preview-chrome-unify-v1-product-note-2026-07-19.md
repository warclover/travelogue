## 1. 原则

> **主路径应像成品交付，不像审稿流程；分章是工具栏里的选修课，不是入学考试。**

| 路径 | 目标占比 | 体验 |
|------|----------|------|
| A 主路径 | ~80%+ | 创建 → 预览 → 导出 → 结束；**零结构打扰** |
| B 轻不满 | ~15% | Dock「分章」→ 调整顺序 / 重生 |
| C 深编辑 | ~5% | 「精修」全能力 |

分章与精修均为 B/C，**不得在首次生成时主动弹出**。

## 2. 拍板项

| ID | 决定 |
|----|------|
| **D-PCU-01** | 首次生成**不**主动弹出分章确认（无黄横幅、无 G1 Task Strip、无底舱镜像） |
| **D-PCU-02** | 默认路径创建完成 = **结构已锁定、可预览可导出**（自动确认语义）；非静默 pending |
| **D-PCU-03** | Dock 增加 **「分章」** 入口（权重 ≤ 精修，远弱于长图）；点开后再出现调整/重生 UI |
| **D-PCU-04** | 精修保持更深一层；二者均不主动展开 |
| **D-PCU-05** | 覆盖 Refine「G1 默认醒目横幅」对**默认主路径**的要求；实验配置 `g1ConfirmStructure` 可保留给旧工作流，产品默认关且 UI 不按主路径门闸 |
| **D-PCU-07** | 精细制作也一律不弹分章 |
| **D-PCU-08** | 允许一次性轻提示「结构不对可点分章」 |
| **D-PCU-09** | kept_n 无关，默认一律自动锁定 |
| **D-PCU-10** | 实验 ON：自动开分章面板 + pending；无黄条 |
| **D-PCU-11** | 默认路径管线/服务端创建完成即 lock |
| **D-PCU-12** | F5 轻面板（跳章+说明+重生）；无拖拽 |

明细与覆盖矩阵见 [decisions](./preview-chrome-unify-v1-decisions-2026-07-19.md)。
