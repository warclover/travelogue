### 1.1 两个同时发生的失效模式

**失效模式 A · 一半的 trip 根本没有簇。** 16 本里 **9 本（56%）簇数为 0**——每一张 kept 都是噪声 `-1` 或压根没有 `sceneClusterId` 字段。在这 9 本上，「同 sceneCluster 内相邻单张组合并」是**完全的空操作**，填充组一张也凑不出来。这 9 本同时也都没有 `shotGroupId`，即每张自成一组——恰恰是最需要填充组的那批 trip。

**失效模式 B · 有簇的那一半，簇太粗。** 剩下 7 本每本只有 **2–3 个簇**，且规模极不均衡：`demo-1d4f92d534` 的最大簇有 **100 张**，`demo-2019` 有 **85 张**。一个 100 张的簇不是「同一个海边」，是半趟旅行。

### 1.2 这推翻了 D-MSP-13 的安全性论证

D-MSP-13 把 AC-PFM-09 从「不跨 shotGroup」放宽到「不跨 sceneCluster」，理由写的是「放宽范围收到 sceneCluster 内，就不会拼出『海边 + 餐厅』这种不相干的一页」。实测表明这条保护**在两种情况下都不成立**：

- 9 本没有簇 → 边界不存在，等于完全无约束（或完全无法填充，取决于实现取哪一边）；
- 7 本有簇但覆盖 199 张只用 2 个簇 → 边界宽到几乎不构成约束，「海边 + 餐厅」照样能进同一页。

**结论：`sceneCluster` 不是可用的填充组边界。** 不是「粒度需要调参」，是这个字段在真实数据上既缺失又过粗。

### 1.3 可用的替代边界（数据里现成有）

资产上现成可用的、比 `sceneCluster` 稳的信号：

| 字段 | 覆盖情况 | 适合做什么 |
|------|------|------|
| `takenAt` | 全覆盖 | **时间邻接**：同一章内间隔小于阈值的连续照片。最可能是正解 |
| `burstGroupId` / `dedupeGroupId` | 连拍 / 去重组 | 天然的「同一刻」，但规模通常 2–3，填不满 6 槽页 |
| `semanticTag` / `subjectClass` | 部分覆盖 | 可做二次约束（同题材），不宜单独作边界 |
| `curation.segments` / 章 | 全覆盖 | 天然的粗边界，配时间邻接使用 |

建议的替代方案：**填充组 = 同一章内、`takenAt` 间隔小于阈值的连续单张组**，`sceneCluster` 有效时作为可选的加强约束（而非必要条件）。这样 9 本无簇 trip 也能填充，且边界比 100 张的簇紧得多。**须产品重裁（OQ-MSP-12）。**

## 2. R-MSP-06 · 填充率窗口

规则按 PRD v0.3.1 §6.3：窗口 `[0.85, 1.05]` 取最小页数；未命中时溢出 ≤5% 优先选溢出档，否则选欠填档；超最大容量取顶档。容量阶梯 = 27 / 36 / 53 / 72 / 73 / 81 / 116 / 134。

### 2.2 窗口扫描 kept = 8…200

| 分支 | 命中数 | 占比 |
|------|------|------|
| `window` | 89 / 193 | **46%** |
| `ceiling` | 59 / 193 | 31% |
| `underfill` | 44 / 193 | 23% |
| `overflow-tol`（溢出 ≤5% 换兑现） | **1 / 193** | 1% |

未命中窗口的区间：

| kept 区间 | 值数 | 例 |
|------|------|------|
| **8–22** | 15 | kept=8 → 8 页，填充率 0.30 |
| 29–30 | 2 | kept=29 → 12 页，0.81 |
| 38–45 | 8 | kept=38 → 16 页，0.72 |
| 56–61 | 6 | kept=56 → 20 页，0.78 |
| **86–98** | 13 | kept=86 → 32 页，0.74 |
| **141–200** | 60 | 全部顶档 + 溢出 |

### 2.3 三条结论

**结论一 · 窗口不是问题，阶梯有洞。** 落空区间对应的都是容量阶梯上的空档：

- `86–98` 这个洞来自 **81 → 116 之间跨了 35 槽**（每新增一页带 8.75 张，是全阶梯最陡的一级）。这里缺一个容量约 95–100 的档。
- `8–22` 完全在最小容量 27 以下，任何档都填不满。**这恰好等于 AC-MSP-14 的置灰阈值 27**——阈值把不可填充区间准确地挡在门外，**BLK-MSP-05 选 (a)（阈值改由最小 `capacity` 派生）由此得到实测支持**。
- `141–200` 全部超顶档。

**结论二 · 疏/密矩阵不是"可选增强"，是补阶梯洞的手段。** D-MSP-11 把疏/密列为本波非目标（控幅，正确），但 §2.3 结论一说明：**填补 81→116 那个洞的正确做法是一个「32 页疏」或「28 页密」变体**，而不是再画一本新页序。应把疏/密的用途从「以后可能加的花样」改记为「补齐容量阶梯的既定手段」。

**结论三 · 顶档溢出不是边缘情况，是 1/5 的真实体验。** kept > 134 占扫描区间的 31%，且 16 本真实 trip 里有 3 本（19%）落这里。典型用户加席自述「一次旅行拍 180 张」正好在这个区间。这有两层含义：

- AC-MSP-11 的溢出明示是**承重构件**，不是兜底文案；
- **D-MSP-04 把上限抬到 48 是对的，但只抬上限不够——得真有一本 40 或 44 页的书**，否则 180 张永远只能出 36 页 + 溢出 44 张。建议把「工坊排一本 40–44 页」列入 AS 任务（**OQ-MSP-13**）。

**顺带一条**：`overflow-tol` 分支 193 个取值里只命中 1 次。这条规则（BLK-MSP-02 引入，允许 ≤5% 溢出换页序完整兑现）在当前阶梯下几乎不生效——不是规则错，是阶梯太稀疏。阶梯补密后它才会开始工作。**OQ-MSP-08「窗口上界 1.05 可接受吗」可以确认为「可接受，但当前阶梯下基本用不上」。**

## 3. 对 PRD 的处置建议

| 项 | 处置 |
|----|------|
| **R-MSP-05** | **从"待量风险"升为"已证实阻塞"**。`sceneCluster` 不能作填充组边界，D-MSP-13 的安全性论证失效。新增 **OQ-MSP-12**：填充组边界改用「同章 + `takenAt` 邻接」，`sceneCluster` 降为可选加强约束。W2 开工前必须关闭 |
| **R-MSP-06** | 关闭为"已量"。窗口保持 `[0.85, 1.05]`（OQ-MSP-08 确认可接受）；真正的动作是补阶梯洞 |
| **D-MSP-11** | 措辞改：疏/密仍是本波非目标，但用途从"花样"改记为"补齐容量阶梯（81→116 的洞）的既定手段" |
| **AC-MSP-14** | 置灰阈值 27 得到实测支持（`8–22` 不可填充区间与之吻合），**BLK-MSP-05 定为 (a)** |
| **AC-MSP-11** | 标注为承重 AC（31% 的 kept 取值 / 19% 的真实 trip 走此路径） |
| **新增 OQ-MSP-13** | 工坊是否排一本 40–44 页，用于承接 kept > 134（占真实 trip 19%） |
| **AS-MSP-04** | 优先级上调：阶梯上的"档"是稀缺资源，20/24 退化对浪费了一级，不只是"数据不整齐" |
