## 0. 会前宣读

1. **切口**：评估的是「实现后能力边界与收益分层」，不是重开 D-MSR/D-MGQ/D-GCS。  
2. **假设**：共享硬过滤守门已修；硬行为按 LQS-P0～P7 串行；LSE 仍冻结；BRIC **不**挂 `used_legacy`。  
3. **诚实预期**：混向页 bag 可为主力；本栈不抬选片 subset / 章级弧线（观感 P1/P3）。  
4. **对照基线**：现网 = LTE 固定 SKU + MCS soft + URO（可关）+ legacy 失败口 + Output Recipe 长图/九宫格。

---

## 1. 总评（一句话）

> **实现后，杂志主链从「按 N 枚举 + 手写 ordering + soft 微调 + legacy 兜底」升级为「库可扩 → 签名硬进类 → 用法/准入硬挡 → 几何可标定决胜」；另增与杂志分账的「单屏海报」交付。观感杠杆在进对页 + 同窗更稳 + 库天花板，不在解冻 LSE。九席一致：值得按纲领做；收益可分层证伪，须分主题盲评、忌超级开关一次全开。**

## 3. 分席：实现前 → 实现后

### 3.1 产品

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| 用户故事 | 「能排成册、能出长图」 | 「混向少乱裁、主图更稳、有字不瞎密铺；聚会可 ▾ 出一张能发的海报」 |
| 卖点可讲性 | 难讲清与竞品差异（solver 故事已证伪） | 可讲：**进对版式 + 图文一体选版 + 单屏海报**（勿吹 LLPP 精确率） |
| 风险 | Sparse 也被迫杂志长卷心智 | 主 CTA 不动；海报次入口，失败不静默顶替 |

**本席收益**：厚册「更像成品」；轻量分享路径补齐；产品叙事与 LSE 脱钩，预期更可控。

### 3.2 算法

| 能力 | 实现前 | 实现后 |
|------|--------|--------|
| 选版 | N 枚举 + soft；方向匹配靠事后 proxy | **L1/L2/L3 签名硬筛**；方向冲突禁入 L3 |
| 屏内几何 | 有 AR/窄条等罚；缺面积 prominence/coverage/CV | **三 soft + eligibility 硬带**；阈值可测、可标定 |
| 图文 | narrate 后置，选版不读 caption | **同 level caption prefer**；replan 默认 off |
| 扩拓扑 | 手写 YAML；缺工厂 | **轨道枚举 → admission**；按签名空洞补库 |
| 失败口 | legacy 规则屏 | 仍 legacy（**故意不**挂 BRIC） |

**本席收益**：搜索空间从「全库碰运气」变为「先对类再比分」；调参从直觉变为 pairwise + reject 看板。  
**诚实预期**：混向页 **bag 仍可能是主力**；L1 不会神话式处处精确。

### 3.3 架构

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| 权威链 | MCS 活跃；`layout.scoring` 休眠 | **不变**；增量只挂 `MosaicConfig` + 旁路 Writer |
| 可解释性 | 多见 `ordering_failed` 黑盒 | `signature:*` / `usage_rule:*` / `eligibility:*` **分账** |
| 确定性 | `deterministic_strict` | 保持；shadow/off 时与 baseline 逐屏一致 |
| 边界 | SKU / 导出 / 选版职责偶有串线 | 杂志 `screens[]` ≠ 海报 job sidecar；禁伪 patternId |

**本席收益**：主链合同不破（固定 SKU + solidify）；旁路可独立演进；硬层叠乘有序，避免「第二套 LSE」。

### 3.4 开发 / 工程

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| 扩模板成本 | 每加 SKU 易堆 `try_order_for_pattern` | 签名索引权威后，**新 ga 模板主要改 YAML** |
| Fallback 债 | self-heal / legacy **可绕过**硬过滤（已知） | 共享守门修好后，硬规则对全路径生效 |
| 发布纪律 | proxy / golden 易当门禁 | **分主题 flag + 独立盲评** 才默认开 |
| 依赖面 | — | GCS-B vendor MIT BRIC；热路径零新 pip |

**本席收益**：扩库可维护性上升；绕过修复是「还债型」收益，立刻提升 URO/MGQ/MSR 可信度。  
**成本**：W1 前须拆 ACCEPTANCE/IMPL；硬行为宜串行，忌三主题同周齐开。

### 3.5 测试 / QA

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| 回归 | 杂志 golden / LRG | 仍为 **W1 硬门**（尤其 GCS） |
| 归因 | 「这本不好看」难拆 | 路由 / 准入 / 几何 / 旁路 **四看板** |
| 发布 | 易被 proxy 带跑 | 三套 BLIND Gate（MSR/MGQ/GCS）独立计票 |
| 风险形态 | 软分微变难测 | 硬筛过严 → legacy 飙升（可监控、可回滚 flag） |

**本席收益**：可判定 AC 增多（签名序、面积口径、绕过负例）；盲评子集（混向+图文、海报可发）让「变好」可证伪。

### 3.6 设计（LTE SKU）

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| 库覆盖 | 有限 SKU；混向/有序签名空洞不可见 | MSR shadow **暴露空洞清单** → 工厂按靶补 |
| 页型质量 | 靠手感选模板 | eligibility（hero 带、photoCountScale）+ 几何罚约束「乱用 extreme」 |
| 图文版 | captionAreas 不驱动选版 | 有文案窗 **可观测优先** 带文案区 SKU |

**本席收益**：设计师劳动从「猜缺什么」变为「对着 exact/bag 报表补」；新 SKU 带 usage/eligibility 才算入轨，减少「入库了但降不了 legacy」。

### 3.7 交互 / 导出门面

| 维度 | 实现前 | 实现后 |
|------|--------|--------|
| Sparse 主路径 | 长图主 CTA | **不动**（GCS OQ-01 已关） |
| 新能力入口 | — | ▾「单屏海报」；与九宫格/拼贴分词 |
| 内部工具 | probe/golden 散 | MGQ `/layout-rating` 对内；文案钉「不改本书」 |

**本席收益**：不稀释 80% 长图心智；海报发现性足够做狗粮；内部标定不污染精修「这页」语汇。

### 3.8 用户体验 · 旅行厚册读者

| 感知 | 实现前（典型） | 实现后（预期） |
|------|----------------|----------------|
| 横竖混排 | 偶发全横/全竖页、裁切狠 | 更常进混向匹配页 |
| 主图页 | 「有大图但不跳 / 或太大」 | 更稳的「跳但不霸」 |
| 连拍 | 可能被拆碎（page_group 默认仍慎开） | V1 以签名/几何为主；邻近同窗为增强项 |
| 术语 | — | 用户不必懂签名；只感到「更顺眼」 |

**本席收益**：整本「杂志感」与「少糟心页」；章级节奏不靠本栈单独解决。

### 3.9 用户体验 · 图文叙事作者

| 感知 | 实现前 | 实现后 |
|------|--------|--------|
| 有 caption | 仍可能密铺，字挤在屏外感 | 更常进带文案区版式 |
| narrate 后 | 若全册重排会「改脸」 | **默认不 replan**；可选同窗薄封装 |

**本席收益**：「有字像排过版」；跳变风险可控。

### 3.10 用户 · Sparse / 聚会分享者

| 感知 | 实现前 | 实现后 |
|------|--------|--------|
| 3–6 张 | 仍偏多屏杂志卷 | ▾ 一张填满矩形的「单屏海报」 |
| 与九宫格 | 易混淆 | 文案/Writer 隔离后心智清晰 |

**本席收益**：补「能发群」的轻交付，而不绑架厚册主链。

## 4. 能力变化总表（前后对照）

| 能力域 | 前 | 后 | 收益类型 |
|--------|----|----|----------|
| 格式签名硬路由 | 无 | L1→L2→L3 + taxonomy | **精度 / 可解释** |
| 图文一体选版 | 弱/无 | caption prefer（同 level） | **产品差异** |
| 屏内几何质量 | 部分 soft | 三维 + 准入 DSL | **观感稳定** |
| 硬过滤守门 | 有绕过 | 全路径罩住 | **规则可信（还债）** |
| 调参闭环 | 直觉 + proxy | pairwise 评分台 | **可迭代** |
| SKU 供给 | 手写为主 | 轨道工厂 + 空洞驱动 | **天花板 / 可维护** |

## 5. 收益分层（全场共识）

### 5.1 高置信 · 偏工程与可维护（落地即得）

- 硬过滤绕过修复（self-heal / legacy 守门）  
- reject 可解释分账（`signature:*` / `usage_rule:*` / `eligibility:*`）  
- 扩模板不再堆 Python 选版特例（随 MSR W1 索引权威）  
- `enabled=false` / shadow 与 baseline 逐屏一致，可安全 merge  

### 5.2 中高置信 · 偏观感（过独立盲评后）

- 混向窗少进方向冲突页  
- hero 页「跳 / 盖 / 碎」三态更稳  
- 有字窗更多进带 `captionAreas` 的版式  
- legacy / pattern-miss 随「空洞 → GCS-A 补库」闭环下降  

### 5.3 中置信 · 偏场景增量

- ▾「单屏海报」服务聚会 / Sparse（须过 **AC-GCS-BLIND** 才默认露出）  

### 5.4 本栈抬不动（预期管理 · 必须对外诚实）

- 选片「讲故事的 subset」（观感路线图 P1）  
- 全册 opener → peak → breath 结构弧线（P3）  
- L1 精确率神话；Hungarian 作为观感主杠杆

## 6. 组合 ROI 与砍法（架构 + 产品）

| 若只做… | 主要得到 | 主要得不到 |
|---------|----------|------------|
| 仅 MGQ soft | 同窗微调 | 方向错页仍大量存在 |
| 仅 MSR | 进对类 | 类对了仍可能几何差；库空则 bag/L3 虚高 |
| 仅 GCS-A | 库变大 | 无硬路由则「多模板黑盒」加剧 |
| 仅 GCS-B | 新分享物 | 厚册杂志观感不动 |
| **LQS 全栈按序** | 漏斗完整：召回→精度→稳定→旁路 | 仍不替代选片/结构专项 |

**资源紧张时保留序**（与 LQS §6.1 一致）：

1. 共享守门 + MSR shadow + MGQ eligibility（W1a）  
2. MSR 硬筛 + GCS-B 海报  
3. MGQ soft + GCS-A 按空洞补库

## 7. 诊断叙事（实现后如何判断「赚到了」）

| 信号 | 解读 | 动作 |
|------|------|------|
| `bag ≫ exact` 且 miss 高 | 库缺有序 SKU | GCS-A 按空洞清单补库 |
| exact 高 · 混向仍狠裁 | L3 方向冲突未生效或 ordering 串账 | 查 `direction_conflict` / 分账 |
| exact 高 · 主图不稳 | 几何层主战场 | MGQ soft / eligibility |
| 有字仍密铺 | caption 层未覆盖 | caption prefer / `captionAreas` |
| Sparse 抱怨多屏 | 交付物问题，非杂志主链 | GCS-B 发现性（▾） |
| legacy 飙升 | 硬筛过严或绕过未修 | 先看板分账再回调 flag |

**禁止**：用单一「观感分」或 golden proxy 微涨充当默认开依据。

## 8. 风险（实现后仍可能出现）

| 风险 | 缓解（已写入 LQS/子 PRD） |
|------|---------------------------|
| 三主题同开硬行为 → 候选枯竭 | LQS-P* 串行；分开关 dogfood |
| BRIC 被当成 MCS 救场 | AC-GCS-01；产品话术禁「拼贴救场」 |
| 工厂产无 usage/签名的 YAML | SKU 入轨硬门（LQS §4.2） |
| L1 被误解为填槽契约 | L1 ≠ 填槽序；decision_log 三件套 |
| caption prefer 与几何罚互打 | 分账诊断；prefer 可观测 AC |
| 评分台与「这页」混用 | 独立路由 +「不改本书」 |

## 9. 结论与引用建议

### 9.1 结论

假设按 LQS 实现，**能力变化是「可解释硬路由 + 可标定几何 + 可驱动扩库 + 隔离海报」四层叠加**；相对现状的核心收益是：

1. **厚册少错页**（混向 / extreme / 用法）  
2. **同窗更稳**（prominence / coverage / balance）  
3. **库可对症扩张**（签名空洞 → 工厂）  
4. **轻分享多一条交付**（单屏海报）  
5. **工程可维护与可证伪**（守门、taxonomy、分主题盲评）  

前提：共享守门先修、硬行为按纲领串行、默认开启各自过盲评。
