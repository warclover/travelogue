## 3. 分角色意见摘要

### 3.1 产品

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 不推翻 V1 铁律；范围克制；狗粮证据链清楚（死胡同可演示） |
| ✅ 赞成 | 「模式 ≠ 面板」可写成产品铁律，利于后续 Trust/帮助系统引用 |
| 📌 **D1 拍板** | **采纳推荐**：关面板保模式；Dock 精修中 → **「完成」** 退出；**不做**半高面板（备选 B Park） |
| 📌 **D2 拍板** | **采纳**：章锚点/意图迁「这页」；这本禁止「当前章：—」 |
| 📌 **D3 拍板** | **采纳**：仅缩略图 + 选中态；`asset-id` 仅 `title` |
| 📌 **D4 拍板** | **采纳**：「导出与更多」→「导出」；更多工具折叠；**不**把导出 prefs 完全迁回 Dock-only |
| 📌 **D5 拍板** | UX 为主；**引号乱码可随 M3 顺带修**；标签式导语/内容质量 → Copy Gate 另项（不挡本主题 Go） |
| ⚠️ 边界 | 勿借本主题扩「手机双栏对照」或重做 bookends 算法 |
| 📌 切拍 | **M1 解耦可独立合入**；M2 可同 PR 或紧随，但 M1 不得被缩略图阻塞 |

### 3.2 UI / UX（交互）

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 线框①对照有力；③精修态 + Task Dock 是正确作业区 |
| ✅ 赞成 | 「收起面板，去画面上修改」作空态主 CTA — 比再写三遍说明书更对 |
| ⚠️ 缺口 | **精修中 · 面板开**时 Dock 仍写「精修」易误解为「再点退出」——须规格：**面板开时点 Dock「精修」= 关面板保模式**（toggle panel），**仅「完成」退出模式** |
| ⚠️ 缺口 | Esc：同意一次只关面板；**面板已关时 Esc 不应静默退出模式**（防误触）；退出只走「完成」 |
| ⚠️ 缺口 | layoutPending + 点「完成」：同意允许退出，但建议 **非阻断 toast**：「版面还没更新，可稍后在下方更新」一次 |
| 🔧 建议 | mode-chip 文案缩短为「精修中」；「可点 ★」放到首次收起后的一次性 tip，避免常驻噪音 |
| 🔧 建议 | 字段迁移后，首次打开「这本」若用户找锚点：空提示「章节锚点已移到「这页」」一次（localStorage） |

**结论**：交互门禁 = 状态机无歧义 + S1 手测通。

### 3.3 用户体验

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 直接命中「工具箱挡住工件」经典失败；与 80% 零精修不冲突 |
| ✅ 赞成 | 导出 Tab 收敛降低分享者误入「高级工具柜」的概率 |
| ⚠️ 担心 | 「完成」在中文里偏「任务做完了」，有 pending 时可能以为已经好了——须靠 Task Dock 持续可见 |
| ⚠️ 担心 | 轻度编辑路径变长：开精修 → 收起 → 点 ★ → 更新版面；可接受，但 **收起必须一键**（线框已有） |
| 📌 要求 | 主题 Go 测法：5 人新手脚本 S1，**禁止**旁白「先关面板」；失败即 No-Go |
| ❌ 反对 | 为教学在验货默认态常驻「点精修可改精选」——违反 Trust 验货壳 |

### 3.4 视觉审美

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 解耦后杂志画面重新成为主角；金色仍留给长图 CTA |
| ✅ 赞成 | 缩略图替代等宽 `asset-id` — 杂志审美底线问题，必须修 |
| 🔧 规范 | 缩略图：**3:4**、圆角 8、选中 2px accent 描边 +「当前」角标；栅格封面 3 列 / 封底可 4–5 |
| 🔧 规范 | mode-chip：深底半透明、字号 11、**不**用脉冲/强描边；距封面题签避让 |
| 🔧 规范 | Dock「完成」：用 folio 浅描边态（线框 `ctl--done` 方向），勿做成第二颗金色主按钮 |
| ❌ 反对 | 精修态给整页加暗角/磨砂遮罩（那会回到「挡内容」） |
| ⚠️ 线框债 | ⑥ 缩略图为纯色块，实装须用真实 cover candidates；线框可接受 |

### 3.5 典型用户代表 · 分享者（~80%）

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 「别让我学设置」——导出收敛对我有好处 |
| ✅ 赞成 | 我不懂也不想懂 ★；只要不改我的一键长图就行 |
| ⚠️ 原话 | 「精修中那个小条子别老闪，像系统报错。」 |
| 📌 诉求 | 验货默认零 chip；只有我点了精修才出现提示 |

### 3.6 典型用户代表 · 轻度编辑（~15%）

| 态度 | 要点 |
|------|------|
| ✅ **强支持** | 「原来不是我不会用，是真的点不到」——死胡同共鸣强 |
| ✅ 赞成 | 封面改成图而不是 asset-007，「我才知道点哪个好看」 |
| ⚠️ 原话 | 「完成」和「更新版面」是不是一回事？——须在 UI 上分词清晰 |
| 📌 诉求 | 收起面板后 ★ 够大、够亮；更新版面条子别藏 |

### 3.7 典型用户代表 · 重度编辑（~5%）

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 整本/本章分开后脑子更清楚 |
| ⚠️ 担心 | 习惯在「整本故事」填锚点的人会短暂迷路——要一次性迁移提示 |
| ⚠️ 担心 | 「按新意图重写」仍可怕；保持 V1 二次确认 + busy |
| 📌 诉求 | 进阶（模板/分章）别再被三连 hint 淹没 |

### 3.8 开发

| 态度 | 要点 |
|------|------|
| ✅ 赞成 | 改点集中：`onSheetClosed` / `onSheetOpened` / Dock 文案切换 / CSS 已按 `data-preview-refine` |
| ✅ 可行 | 封面缩略图：bookends 候选已有图 URL，主要是按钮 innerHTML/CSS |
| ⚠️ 规格须钉 | ① 面板开时再点 Dock「精修」行为；② Esc 在面板已关时；③ 返回首页是否强制 `refine=off`（建议 **是**） |
| ⚠️ 回归 | AC-REF 导出拦截、Share、G1 横幅优先级栈不得回归 |
| ⚠️ 导出 Tab | 「打开导出设置」与 Dock ▾ 必须同 prefs，避免双源 |
| 📌 工时 | M1 **1～2 人日**；M2 **2～3 人日**；M3 **≤1 人日**；同意 M1 可先合 |
| 📌 风险 | 低；最大风险是 Dock 双态文案与 `aria-expanded`/`aria-pressed` 搞混导致读屏混乱 |

## 7. 推荐发布门禁

### M1 Go（模式解耦）

| 门禁 | 标准 |
|------|------|
| **Go** | AC-REFUX-01～03；S1 新手可完成标精选；V1 导出拦截不回归；Share 无壳 |
